활용 가이드

자막·카피로 쓸 때

대사·내레이션에 맞춰 핵심 문구를 보여 줄 때 써요. 쇼츠 시청 유지에 가장 직접적인 효과가 있어요.

  • 대본을 단어별 시간과 함께 주면(받아쓰기 결과) 박자가 정확해져요.
  • 강조는 한 문장에 한 단어만. 다 강조하면 아무것도 강조되지 않아요.
  • 화면 아래 15%는 플랫폼 UI에 가려지니 비워 두세요.

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

샷 A는 눈 오는 밤 골목의 붕어빵 노점에서 사장님을 찍은 인터뷰 미디엄 숏이다. 줄무늬 차양과 전구가 있고, 뒤로는 초점이 나간 골목(창, 네온, 보케)이 보인다. 천천히 밀고 들어가며 미세한 핸드헬드가 있다. 샷 B는 식힘망 위 붕어빵 인서트다. 하나는 반으로 갈라 팥이 보이고, 집게가 갓 구운 하나를 내려놓는다. 강조색 라임(#c9f23a)은 그래픽만 쓴다. 장면의 따뜻한 주황·빨강과 겹치지 않게 차가운 형광으로 골랐다.

4.78–7.7 데이터 칩(왼쪽 위): "오늘 구운 붕어빵 1,180 → 1,284 마리"로 숫자가 올라간다. 고정폭 숫자라 폭이 떨리지 않는다. 인용 카드(이름 자막과 같은 슬롯): 브랜드 마크 두 개로 만든 따옴표가 튀어나오고, 두 줄이 줄 마스크 안에서 올라온다. 이어 출처가 나온다. 집게가 붕어빵을 들고 내려온다.
5.66–6.0 절정: 붕어빵이 망에 내려앉는다(찌그러짐, 김 퍼짐, 카메라 펀치 1.2%). 그 순간 칩의 일의 자리가 4 → 5로 굴러 1,285가 되고, 인용의 핵심어 "한 마리 더"에 라임 밑줄이 그어지며 글자색이 바뀐다. 6.0초에는 버그·칩·인용·주제 바·티커가 모두 화면에 있다. 김이 오른다. 집게가 빠진다.
7.68–8.7 칩 → 인용 → 티커 → 주제 바 순으로 빠진다. 글자가 먼저, 바는 뒤에 되감긴다.
8.5–10 슬롯 지도: 화면이 어두워지고 안전 영역이 다시 그려진다. 각 요소가 차지한 슬롯을 잰 크기 그대로 라임 윤곽으로 그리고, 라벨에 크기를 적는다: 버그 194×64, 데이터 칩 418×176, 이름 자막 / 인용 카드 482×328, 주제 바 + 티커 864×128. 가운데에 패키지 명세(제목, 글자 크기 단계 7개 견본, 글꼴·모서리·그리드)가 나온다. 9.42초에 버그가 빠진다.

프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 그래픽: 타임라인은 gsap.timeline({ paused: true }) 하나다.
  • 각 속성의 첫 트윈은 fromTo이고, setup 끝에서 tl.time(D); tl.time(0)으로 모든 트윈을 기록 순서대로 초기화한다(main.js:470).
  • frame(t)는 tl.time(t) 뒤에 닫힌 식 값만 쓴다(main.js:474-505): 크롤 translate, 시계·칩 글자, 버그 마크 회전, LIVE 점.
  • GSAP이 맡은 transform과 frame이 쓰는 translate는 서로 다른 속성이다.
  • 길이 0인 set은 쓰지 않는다.
  • 장면: 매 프레임 2D 컨텍스트 상태(변환, 알파, 합성, 필터, 선 끝, 점선)를 기본값으로 되돌린다(main.js:478-480). 그다음 t의 닫힌 식으로 그린다.
  • 흩어짐 표(눈, 보케, 김, 음절)는 rand(12301)로 setup에서 굽는다.
  • 블러는 setup에서 한 번만 쓴다(구운 골목). 헤드리스에서는 willReadFrequently 캔버스에 굽는다.
  • 그레인: setup에서 rand(9123)으로 한 번 만든다. 프레임마다 floor(t·12)로 정한 정수 오프셋만큼 옮긴다.
  • 렌더 검사 결과: 앞→뒤와 뒤→앞(새 페이지), 되돌아오기 모두 바이트 단위로 같다(maxPixelDiff 0).
한계와 조절할 점
  • 글자 폭은 setup에서 한 번 잰다. 문구를 런타임에 바꾸는 패키지라면 bar를 다시 만들어야 한다.
  • fitStep은 크기만 내린다. 직함이 두 줄이 되어야 하는 길이는 처리하지 않는다(balance를 이름 자막에도 쓰면 된다).
  • 인용 카드의 높이는 두 줄 기준이다. 세 줄 이상이면 슬롯 위쪽(칩 슬롯과의 간격)을 다시 확인해야 한다.
  • 집게는 두 팔이 화면 밖 경첩에서 나온다. 화면 안에서는 젓가락처럼 보일 수 있다.
  • 앱 UI 영역(위 160, 오른쪽 버튼 열 x > 936·y 880–1560, 아래 1560)은 특정 앱의 값이 아니라 흔한 세로 영상 앱 배치를 어림한 값이다.
  • 소리는 없다. 스팅어에는 보통 효과음이 붙는다.
