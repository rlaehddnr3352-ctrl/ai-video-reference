활용 가이드

자막·카피로 쓸 때

대사·내레이션에 맞춰 핵심 문구를 보여 줄 때 써요. 쇼츠 시청 유지에 가장 직접적인 효과가 있어요.

  • 대본을 단어별 시간과 함께 주면(받아쓰기 결과) 박자가 정확해져요.
  • 강조는 한 문장에 한 단어만. 다 강조하면 아무것도 강조되지 않아요.
  • 화면 아래 15%는 플랫폼 UI에 가려지니 비워 두세요.

제품·앱 소개로 쓸 때

제품·앱·서비스의 생김새나 기능을 보여 주는 장면에 써요.

  • 실제 제품 사진(배경 제거 PNG)이나 앱 화면 캡처를 함께 주면 그대로 넣어 움직여요.
  • 기능 하나당 2–3초, 한 화면에 한 가지만 보여 주세요.
  • 가격·혜택 같은 숫자는 코드로 넣어야 깨지지 않아요.

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

미감은 밤 방 안의 휴대폰이다. 남보라 방, 커튼 사이 창밖의 흐린 도시 불빛(보케)과 달, 이불과 베개가 있고, 화면 빛이 방을 비춘다. 휴대폰 UI(다크 모드 대화 앱, 두벌식 자판)는 전부 코드로 그렸다. 실제 앱이나 브랜드를 닮지 않게 했다: 강조색은 산호색(#ff7a5c) 하나이고, 노랑·파랑·초록 말풍선은 쓰지 않았다. 강조색이 칠해지는 곳은 내 말풍선, 조합 중 음절의 밑줄, 캐럿, 선택 영역, 보내기 버튼, 지운 말의 취소선이다.

시간 무엇이 보이나
0–0.75 어두운 데서 밝아지며 방이 보인다. 휴대폰은 −3° 기울어 있고, 빈 입력창에서 캐럿만 깜빡인다. 대화는 「잘 지내.」(8월 31일) → 「응. 너도.」에서 끝나 있다.
0.75–2.1 한 번에 몰아친 초안 「너 진짜 너무해」(16타). 카메라는 자판과 입력창 쪽으로 다가간다(배율 0.84 → 1.28). 음절이 자모 단위로 바뀐다: 너 → 넘 → 너무 → 뭏 → 무해. 받침이 다음 모음을 만나면 다음 음절로 건너뛴다. ⇧를 누르면 자판 윗줄이 ㅃㅉㄸㄲㅆ로 바뀌고, 그다음 ㅈ이 ㅉ이 된다.
2.1–3.0 손이 멈춘다. 0.5초 뒤부터 캐럿이 깜빡인다.
3.0–3.9 「너무해」를 길게 누른다. 손끝 자리가 부풀어 오른 뒤 선택 영역이 그 자리에서 양옆으로 펼쳐진다. 손잡이 둘과 「잘라내기 · 복사 · 붙여넣기」 메뉴가 뜨고, 0.55초 동안 아무것도 하지 않는다.
3.9–4.44 선택 위에 ㅂ을 친다. 「너무해」는 선택색을 입은 채 위로 떠올라 옅어지고, 한 글자씩 산호색 취소선이 그어진다. 입력창에는 ㅂ → 보 → 복 → 보고가 이어진다. 복의 ㄱ이 작은 호를 그리며 고의 첫소리 자리로 날아간다.
4.44–5.05 「보고 」에서 다시 망설인다. 가장 하기 어려운 말 앞이다.
5.05–5.68 「싶았어」를 친다. ㅓ 대신 바로 옆 키 ㅏ를 눌러 오타가 났다.
6.0–6.22 ⌫ 세 번. 어 → ㅇ(조합 중 음절에서 자모 하나), ㅇ → 없음, 그다음 「았」을 통째로 지운다. 지워진 자모와 음절은 산호색으로 떠올랐다가 사라진다.
6.37–7.35 「었어」를 다시 쳐서 「너 진짜 보고 싶었어」를 완성한다. 0.6초 동안 그대로 둔다.
7.35–7.95 보내기(절정). 버튼이 눌리고, 빛이 번지고, 링 두 개와 불꽃이 퍼진다. 입력창의 글자가 들려 올라가는 동안 둘레에 말풍선이 생긴다. 말풍선은 크기를 줄이며 대화 목록으로 날아가 살짝 넘쳤다가 자리 잡는다. 카메라는 빠르게 물러나 대화 전체를 보여 준다. 말풍선이 지나간 뒤 「너무해」가 한 번 붉게 타오르고 티끌로 흩어진다. 절정 = 7.6초.
7.95–10 여운. 말풍선이 착지하면 화면이 한 번 흔들리고, 「오전 1:12」 → 「읽음」이 뜬다. 헤더에 「입력 중…」이 나오고 상대 쪽에 점 세 개가 튄다. 9.15초에 점 말풍선이 늘어나 「나도.」가 된다. 방을 비추는 화면 빛은 보내는 순간부터 차가운 파랑에서 산호빛으로 따뜻해진다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 입력은 키 목록 하나뿐이다(main.js:32 KEYS).
  • [시각, 키] 쌍으로 적는다. 키는 두벌식 자판의 물리 키(자모는 시프트 없는 이름), ⇧(한 번 누르면 다음 자모까지 유지), ␣, ⌫다.
  • 글자 위의 손동작 두 가지(HOLD: 길게 누르기 시작, 조합이 끝남 / SEL a b: 그 구간을 선택)와 SEND도 같은 목록에 있다.
  • 사람의 리듬은 이 시각표로 쓴다. 화난 초안은 0.06–0.13초 간격으로 몰아치고, 「보고」는 0.13–0.14초 간격으로 느리다. 어려운 말 앞에서 0.6초 멈추고, 오타를 알아채기까지 0.3초가 걸린다.
  • 두벌식 오토마타(main.js:62-99):
  • 조합 중인 음절은 "그 음절에 들어간 자모를 입력 순서대로 담은 목록"이다. parse는 이 목록을 초성 / 중성 1–2개 / 종성 0–2개로 나누고, render는 0xAC00 + (초성·21 + 중성)·28 + 종성으로 완성형 음절을 만든다. 모음이나 초성이 없으면 낱자모 그대로 둔다.
  • feed(목록, 자모)가 상태 전이 전체를 맡는다(main.js:84).
    • 겹모음(ㅗ+ㅐ → ㅙ)과 겹받침(ㄴ+ㅎ → ㄶ)은 VV·CC 표로 처리한다. ㄸㅃㅉ는 받침이 될 수 없다.
    • 받침 뒤에 모음이 오면 마지막 받침이 다음 음절의 초성으로 옮겨 간다. 한 + ㅏ → 하 | 나, 않 + ㅏ → 안 | 하. 이때 moved에 옮겨 간 자모를 돌려준다.
  • 자모 목록으로 상태를 두기 때문에 ⌫는 목록에서 하나를 빼면 된다(main.js:204). 조합 중 음절이 비면 그다음 ⌫부터는 확정된 음절을 통째로 지운다(main.js:209). 실제 입력기도 이렇게 동작한다.
  • 매 프레임 처음부터 다시 친다(main.js:174 editorAt):
  • t까지의 키를 0초부터 다시 넣어 확정 글자, 조합 중 음절, 캐럿, 선택, 시프트, 키별 마지막 눌림 시각, 지운 글자 목록을 만든다. 키가 마흔 개 남짓이라 비용은 무시할 만하다.
  • 글자마다 born(태어난 시각)과 chg(마지막으로 모양이 바뀐 시각)를 달아 둔다(main.js:221-227). 그림은 이 두 값과 t만으로 팝을 정한다(main.js:487 glyphScale): 새 음절은 0.55 → 1(back.out(2.2)), 자모가 붙거나 떨어진 음절은 0.84 → 1이다.
  • 받침이 옮겨 가면 새 음절에 hop을 기록한다. 그림에서는 그 자모를 앞 음절의 받침 자리에서 새 음절의 초성 자리로 호를 그리며 날리고, 그동안 새 음절이 0.3에서 1로 진해진다(main.js:523).
  • 줄 배치는 앞부분 문자열 폭(measureText, 문자열별 캐시)으로 정한다(main.js:166). 조합 중 음절이 넓어지면 뒤 글자가 실제 입력기처럼 밀린다.
  • 입력기 표시(main.js:493 drawLine):
  • 조합 중 음절에는 옅은 산호색 상자와 밑줄을 그린다.
  • 캐럿은 키가 들어오는 동안 켜져 있고, 마지막 키에서 0.5초 지나면 1초 주기로 깜빡인다. 깜빡임 위상은 마지막 키 이후 시간으로 정한다(main.js:534).
  • 선택 영역은 길게 누른 자리에서 expo.out으로 펼쳐진다. 손잡이는 back.out으로 튀어나오고, 편집 메뉴(main.js:774)는 선택과 함께 떴다가 첫 키에 0.12초 만에 접힌다.
  • 지운 말의 두 가지 운명(main.js:559 drawGhosts):
  • ⌫로 지운 자모와 음절(jamo, syl)은 산호색으로 46px 떠오르며 0.45초 만에 사라진다.
  • 선택해서 덮어쓴 말(mem, main.js:180)은 지울 때의 줄 배치 x를 그대로 받아 0.9초 동안 118px 떠오른다(expo.out). 처음 0.3초는 선택색을 입고 있다가 옅은 라일락색으로 바래고, 0.4초부터 글자마다 0.09초씩 늦게 취소선이 그어진다(main.js:608). 그 뒤로는 그 자리에 머문다.
  • 보내기 0.1초 뒤 말풍선이 지나가면 mem 글자는 한 번 붉게 타오르고(종 모양 곡선) 글자마다 티끌 14개로 흩어진다(main.js:577). 글자는 말풍선 아래 층에, 티끌은 위 층에 그려서 지나가는 말풍선과 글자가 겹쳐 보이지 않게 했다.
  • 자판(main.js:616):
  • 두벌식 배열(ㅂㅈㄷㄱㅅㅛㅕㅑㅐㅔ / ㅁㄴㅇㄹㅎㅗㅓㅏㅣ / ⇧ㅋㅌㅊㅍㅠㅜㅡ⌫ / 123 ☺ 스페이스 . ⏎)이다.
  • 키마다 마지막으로 눌린 시각에서 0.16초 동안 밝아지고 2px 내려간다.
  • 시프트가 켜져 있으면 시프트 키가 흰색이 되고 윗줄 레이블이 쌍자음과 ㅒㅖ로 바뀐다.
  • 자모 키에는 실제 휴대폰처럼 0.15초 동안 미리보기 풍선이 뜬다(main.js:668). 풍선에는 눌린 키가 아니라 실제로 들어간 자모(시프트가 켜져 있으면 ㅉ·ㅆ)를 보여 준다.
  • 보내기(main.js:690-745):
  • flight(u)는 글자 원점, 기준선, 배율(54px → 40px), 말풍선 채움, 기울기, 찌그러짐을 u의 닫힌 식으로 정한다. x는 power3.out, y는 back.out(1.4)라서 위로 넘쳤다가 자리 잡는다.
  • 착지한 뒤에도 같은 함수에 u = 1을 넣어 그린다. 그래서 날아가던 말풍선과 놓인 말풍선이 한 픽셀도 어긋나지 않는다.
  • 꼬리 잔상 세 개는 글자 없이 말풍선 실루엣만 lighter로 그린다(main.js:899).
  • 링 두 개, 플래시(최대 0.32), 불꽃 16개(x = v(1−e^{−kτ})/k의 닫힌 식, main.js:730)는 보내기 한 박에만 쓴다. 착지 때는 카메라가 한 번 감쇠하며 흔들린다(main.js:385).
  • 카메라와 깊이:
  • CAM(main.js:119)은 [초점 x, y, 배율, 기울기] 키프레임이다. 방 → 자판과 입력창(1.28) → 입력 줄(1.42–1.45) → 대화 전체(0.97)로 옮겨 간다. 여기에 사인파 핸드헬드를 더한다.
  • 같은 카메라를 층마다 다른 계수로 쓴다(main.js:392 applyCam): 창과 커튼 0.16, 이불과 베개 0.42, 화면 빛에 뜬 먼지 0.6, 휴대폰 1, 앞쪽에서 초점이 나간 보케 1.35(main.js:926).
  • 창밖(별, 달, 아파트 불빛)은 선명하게 그린 다음 setup에서 blur(5px)로 한 번 흐린다(main.js:252). 이불의 주름도 setup에서 흐려 굽는다(main.js:338).
  • 휴대폰의 그림자와 화면 빛 번짐도 setup에서 흐린 스프라이트로 굽는다(main.js:375). 차가운 빛과 따뜻한 빛 두 장을 warmth(t)(main.js:401)로 교차한다.

  • 매 프레임 editorAt(t)가 0초부터 다시 계산한다. 프레임 사이에 남는 것은 문자열 폭 캐시(순수 함수 값)뿐이다.
  • 모든 효과는 사건 시각(born, chg, hop.t, 지운 시각, 보낸 시각)과 t의 차이로 정해진다. 그래서 어떤 효과도 다른 효과가 끝나기를 기다리지 않는다.
  • 난수: setup의 rand(10601–10605, 10699) 표만 쓴다(창밖 별과 불빛, 먼지, 불꽃, 티끌, 앞쪽 보케, 그레인). GSAP은 parseEase로 받은 이징 함수로만 쓰고 타임라인은 쓰지 않는다.
  • 2D 상태와 오프스크린:
  • 프레임마다 resetCtx(main.js:141)로 기본값으로 되돌린다.
  • 글자의 팝·회전 변환은 DOMMatrix로 만들어 setTransform에 넘긴다(누적 save/restore에 기대지 않음).
  • 흐림 필터는 setup에서 구울 때만 쓰고, 프레임에서는 filter·shadowBlur를 쓰지 않는다.
  • 오프스크린 캔버스는 헤드리스에서 willReadFrequently로 만들고, setup 끝에서 여덟 시각을 한 번씩 그려 둔다(main.js:995).
  • 그레인은 103번처럼 DOM 캔버스 한 장을 1/12초 계단으로 옮긴다(main.js:987).
  • 검사:
  • render.mjs: 앞→뒤와 새 페이지 뒤→앞에 되돌아가기까지 바이트 단위로 같음(maxPixelDiff 0).
  • 검사 시각(0, 3.7, 5, 7.1, 9.3, 9.97)이 받침 이동, ⌫, 비행을 지나지 않아서 따로 확인했다. 1.9, 3.45, 4.32, 6.05, 6.27, 7.6, 8.9, 9.3초를 서로 반대 순서로 두 번 찍은 PNG 해시가 모두 같았다.
한계와 조절할 점
  • 오토마타는 두벌식의 기본 규칙만 따른다.
  • 초성이 없는 모음 음절 뒤에는 받침을 붙이지 않는다.
  • 자음 둘을 겹자음 낱자(ㄳ 등)로 합치지 않는다.
  • 이미 확정된 음절로 돌아가 조합을 다시 열지 않는다(대부분의 입력기와 같다).
  • 입력기마다 다른 세부(겹모음을 ⌫로 한 번에 지우는지 등)는 한 가지로 정했다.
  • 캐럿은 늘 문장 끝이나 조합 중 음절 뒤에 있다. 문장 가운데로 캐럿을 옮기는 키(손가락으로 탭)는 넣지 않았다. 상태 구조(caret)는 이를 지원한다.
  • 받침 이동 효과는 낱자모 글리프(ㄱ)를 날린다. 음절 안 받침의 실제 모양(크기·위치)과는 조금 다르다. 0.24초 동안이라 눈에 띄지는 않는다.
  • 몰아치는 구간(초당 약 12타)에서는 팝과 받침 이동이 서로 겹쳐 하나하나 보이지 않는다. 의도한 것이다. 천천히 친 「보고」에서 또렷이 보인다.
  • 휴대폰 화면 밖의 큰 글자는 없다. 글자 크기는 카메라가 다가가서 키운다(입력 줄 54px × 1.42–1.45 ≈ 77px).
  • 손잡이:
  • 문장, 리듬, 오타, 선택: KEYS(main.js:32)
  • 보내기·읽음·답장 시각: T_SEND, T_READ, T_TYPING, T_REPLY
  • 카메라: CAM
  • 색: C
  • 입력 줄 크기와 위치: FS, FX, BASE
