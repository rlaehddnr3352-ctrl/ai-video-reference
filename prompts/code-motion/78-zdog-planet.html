작은 행성

광고 · 쇼츠에서는귀여운 작은 행성 일러스트, 낮밤 전환

활용 가이드

3D·공간로 쓸 때

제품이나 공간을 입체로 돌려 보거나 카메라가 공간을 지나가는 장면에 써요.

  • 제품 3D 모델(GLB)이 있으면 그대로 쓰고, 없으면 단순한 도형으로 만들어 달라고 해요.
  • 카메라 움직임은 한 방향으로 하나만. 사전의 카메라 무빙 카드 이름을 같이 쓰면 정확해요.
  • GPU를 많이 쓰니 렌더링은 시간이 걸려요. 해상도를 낮춰 미리 보고 마지막에 올리세요.

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

영상에 옮길 때 주의

  • Zdog: 영상 스킬에 없는 라이브러리라면 원리만 가져와 Canvas 2D·SVG·WebGL로 직접 쓴다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

부드러운 하늘 그라데이션(하늘색 → 크림) 위에 떠 있는 작은 초록 행성이다.

  • 시작 (0–0.9초): 행성이 스프링처럼 튀어나오며 커진다(줌 오버슈트).
  • 해가 왼쪽에서 톡 나타난다. 위에 "오후 3:00" 시계 알약이 뜬다.
  • 쌓기 (0.45–2.7초): 카메라 쪽 물건 24개가 원판 둘레를 따라 파도처럼 하나씩 튀어 오른다(스케일 오버슈트 + 늘었다 줄었다).
  • 집들(벽 4면 + 박공 + 지붕 2면 + 문·창, 굴뚝), 동그란 나무, 덤불, 꽃밭, 풍차.
  • 구름 다섯 덩이가 행성 둘레를 돈다. 적도에서 11.5° 기운 도로 위로 빨간 차와 노란 차가 서로 반대 방향으로 달린다.
  • 풍차 날개가 돈다.
  • 회전과 휙 돌기 (0–3.3초 천천히 → 3.3–6.4초 약 143° 스윙): 카메라가 천천히 돌다가 행성 뒤편으로 휙 넘어간다.
  • 스윙 동안 내려다보는 각도가 들렸다가 돌아온다. 살짝 뒤로 물러났다가(돌리) 다시 다가온다.
  • 뒤편의 등대, 호수, 침엽수 숲, 다른 집들은 지평선을 넘어오는 순간에 하나씩 튀어 오른다.
  • 해 지기 (4.6–5.5초): 해가 행성 왼쪽 위 가장자리 뒤로 들어간다. 지붕과 나무가 해를 배경으로 실루엣이 된다.
  • 동시에 달이 오른쪽 위 가장자리 뒤에서 떠오른다.
  • 하늘은 낮 → 노을(보라·분홍·주황) → 밤(남색)으로 바뀌고, 모든 물건의 색이 팔레트를 따라 바뀐다.
  • 밤 (5.5초–):
  • 창문이 하나씩 노랗게 켜지고 은은한 불빛 번짐이 생긴다(5.45–7초).
  • 차 전조등이 켜진다(5.5초). 등대 등이 켜지고 빛줄기 두 갈래가 돌기 시작한다(6초).
  • 별이 반짝이고, 8.25초에 별똥별이 지나간다.
  • 끝: 등대가 화면 가운데 위쪽에 서서 빛을 돌리는 밤의 마을. 시계는 "오후 9:30"이다.
  • 아래쪽에는 자막이 읽히도록 남색 안개 띠를 깔았다(y 1520–).

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • Zdog 장면 그래프
  • Illustration → scene(행성 중심을 60 px 올림) → world(카메라가 돌림) / sky(카메라 공간).
  • 지표의 물건: Anchor(rotate.y = φ) → Anchor(rotate.x = θ) → Group(translate.y = −R, rotate.y = spin). 행성 표면 (θ, φ)에 서고, 로컬 위(−y)가 반지름 방향이다(main.js:153, main.js:191–207).
  • 도로: 기울인 Anchor 안의 사각형 72개 + 점선 36개(main.js:173–189).
  • 차: 같은 Anchor 안에서 rotate.z로 도로를 돈다(main.js:224–235).
  • 그리는 순서 (z 정렬) — Zdog는 도형마다 평균 z로 정렬한다.
  • 행성은 큰 점 하나(정렬값 0)다.
  • 지면 것(도로·연못·풀밭): 카메라를 보면 1 + 층, 아니면 −10⁵ (groundSort, main.js:149).
  • 서 있는 물건은 Group 하나가 밑동 z로 통째 정렬된다(objSort, main.js:144).
    • 앞면이면 2 + z라 행성과 지면 위에 그려진다.
    • 뒷면이면 z < 0이라 행성보다 먼저 그려진다. 원판에 가려지고 지평선 밖으로 삐져나온 부분만 보인다(작은 행성다운 실루엣).
  • 물건 안의 순서는 고정이다(updateSort: false, 풍차만 true).
    • 벽과 박공은 front를 바깥으로 두고 backface: false로 뒤를 향하면 뺀다. 볼록한 상자의 보이는 면끼리는 겹치지 않으므로 순서가 상관없다.
    • 그 위에 문·창 → 창 불빛 → 지붕(역시 뒷면 제거) → 굴뚝 순으로 그린다(models.js:102–150).
  • Zdog의 Box는 옆면의 front가 안쪽을 향한다(node에서 확인). 그래서 벽은 Rect 네 장으로 직접 만들었다.
  • 조명 흉내 (Zdog에는 빛이 없다): updateGraph()(변환 + 정렬)와 renderGraph() 사이에서 모든 도형의 색을 정한다(main.js:356–377).
  • 'face': 방금 변환된 면 법선(renderFront − renderOrigin)과 빛 방향의 내적으로 그늘색 ↔ 밝은색을 섞는다. 면마다 단색이다(main.js:365–371).
  • 'ball'(구): Zdog 점의 render를 바꿨다. 그늘 원 위에 빛 쪽으로 밀린 밝은 원을 잘라 얹어 초승달 그늘을 만들고, 작은 하이라이트를 찍는다(models.js:23–41).
    • 행성·나무·덤불·구름이 이 방식이다.
  • 빛 방향은 해(낮)와 달(밤)의 화면 위치에서 온다. 각 원반이 행성에서 벗어난 정도를 가중치로 쓴다. 그래서 해가 지는 동안 그늘이 왼쪽에서 오른쪽으로 넘어간다(main.js:316–326).
  • 팔레트 낮/노을/밤 (palette.js)
  • 색 이름마다 세 단계가 있다. 노을과 밤은 낮 색에서 곱셈+덧셈으로 만들거나 직접 지정한다(palette.js:9–10).
  • 창·등불은 거꾸로 밤에 밝아진다. 창은 각자 정해진 시각에 0.16초 만에 켜진다.
  • 튀어나오기: 감쇠 스프링 계단 응답(오버슈트 약 25%)에 늘였다 줄이는 항을 얹었다(main.js:47–52).
  • Zdog의 stroke는 화면 공간이라 Group 스케일이 굵기에 먹히지 않는다. 그래서 등록된 도형의 stroke에 같은 배율을 곱한다(main.js:341–354).
  • 등장 순서(main.js:209–222): 카메라 수학을 Zdog과 똑같이(Z → Y → X 회전) 다시 짜서 setup에서 정한다.
    • 1초에 앞을 보는 물건은 원판 둘레 각도 순으로 파도처럼 튀어 오른다.
    • 나머지는 카메라 공간 법선 z가 −0.22를 넘는 순간, 즉 지평선을 넘어오기 직전에 튀어 오른다.
  • 해와 달: 카메라 공간의 기울어진 궤도(반지름 470, 납작도 0.45)에서 해와 달이 60° 간격으로 돈다(main.js:37–40).
  • 궤도의 위쪽 반은 행성 뒤다. 해는 왼쪽 위 가장자리로 들어가고, 달은 오른쪽 위 가장자리에서 나온다.
  • 정반대 막대(180°)로 묶으면 한쪽이 행성 뒤로 숨는 순간 다른 쪽이 반드시 행성 앞을 가로지른다. 그래서 같은 궤도 위 60° 간격으로 바꿨다.
  • 구름: 카메라 공간에서 화면과 거의 나란한 고리를 돈다. 행성 얼굴을 가로지르지 않고 실루엣 둘레를 감싼다. 고리 기울기 때문에 위쪽 구름은 지평선 물건 뒤로, 아래쪽 구름은 앞으로 지나간다(main.js:237–252).
  • 2D 레이어:
  • 하늘(main.js:379–424): 3단 그라데이션, 시드 별, 별똥별, 해·달 번짐, 대기 고리, 자막용 안개 띠.
  • 시계 알약(main.js:426–450): 해 아이콘이 초승달로 바뀐다.
  • 등대 빛줄기·전조등·창 불빛은 Zdog 순서 안에서 lighter 합성으로 그린다. 앞에 있는 물건이 정상적으로 가린다(models.js:44–90).
  • 해상도: Zdog은 devicePixelRatio만큼 캔버스를 키운다. 무대 자체가 창에 맞게 축소되므로 pixelRatio = 1로 되돌려 1080×1920 그대로 그린다(main.js:117).

프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • Zdog에는 시계가 없다. Dragger, animate 루프, requestAnimationFrame은 쓰지 않는다.
  • frame(t)가 t로 정하는 것:
  • 카메라 yaw/pitch/zoom.
  • 해·달 위치, 구름·차·풍차·등대 회전.
  • 물건마다 스케일과 stroke, 모든 도형의 색.
  • 그다음 illo.updateGraph() → 색칠 → illo.renderGraph().
  • 이전 프레임의 상태를 읽지 않는다. 직전에 무엇을 그렸든 같은 그림이 나온다.
  • 등장 시각, 창마다 켜지는 시각, 별 위치·반짝임 위상, 풀밭 얼룩은 setup에서 하네스 rand(seed)(78, 7, 1978)로 정한다.
  • 별똥별과 반짝임은 t의 함수다. Math.random·Date·performance.now는 쓰지 않는다.

한계: - 정렬은 물건 단위(밑동 z)다. 가까이 붙은 키 큰 물건과 낮은 물건이 지평선 근처에서 겹치면 순서가 한 프레임 뒤집힐 수 있다. - 배치 간격(최소 4 px 이상)으로 피했다. - 행성 그늘은 화면 공간 근사다. 진짜 명암 경계(대원)는 아니다. - 해가 행성 뒤를 지날 때 해 번짐(하늘 캔버스)은 행성에 가려지지만, 구름·물건과의 앞뒤는 따지지 않는다. - 원뿔(침엽수)은 Zdog 방식대로 단색이다. 축이 화면과 정확히 수직이 되는 순간에는 Zdog Cone이 옆면을 한 프레임 건너뛸 수 있다(부동소수 acos). - 성능: 도형 약 450개, 계층 깊이 6–9. 변환과 정렬이 JS 몇 ms, 그리기는 GPU 2D 캔버스. 30 ms 예산 안이 목표지만 실측은 사용자의 브라우저에서 해야 한다.
