오늘은 그냥, 한 번

키네틱 타이포그래피 · 글자 지도 위를 나는 카메라

자막·카피제목·로고가벼움 · 브라우저 기능만
광고 · 쇼츠에서는글자 위를 카메라가 날아다니는 키네틱 타이포

활용 가이드

자막·카피로 쓸 때

대사·내레이션에 맞춰 핵심 문구를 보여 줄 때 써요. 쇼츠 시청 유지에 가장 직접적인 효과가 있어요.

  • 대본을 단어별 시간과 함께 주면(받아쓰기 결과) 박자가 정확해져요.
  • 강조는 한 문장에 한 단어만. 다 강조하면 아무것도 강조되지 않아요.
  • 화면 아래 15%는 플랫폼 UI에 가려지니 비워 두세요.

제목·로고로 쓸 때

영상 첫 1–2초, 브랜드명이나 핵심 제목이 처음 나오는 순간에 써요.

  • 제목은 한 줄, 6–10자 안쪽이 가장 잘 보여요.
  • 기법이 끝난 뒤 0.5–1초는 글자를 멈춰 읽을 시간을 주세요.
  • 로고라면 브랜드 색 2–3개만 지정하면 나머지 톤은 AI가 맞춰요.

사전 카드와 함께 쓰기

G06 키네틱 타이포 카드와 같은 기법이에요. 카드의 예시 영상과 주문서 기능을 같이 써 보세요.

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

독백은 "매일 아침 / 생각만 했다 / 오늘은 / 그냥 / 한 번 / 해 보기로 / 했다."이다. 글꼴은 Pretendard Variable 하나에 굵기 두 단계(300, 900)만 쓴다. 강조색은 주홍(#ff5018) 하나이고, "한 번"과 마침표에만 남는다. 종이는 따뜻한 미색으로, 얼룩·섬유·티끌과 종이 결이 있다. 벽은 거푸집 이음매와 폼타이 구멍이 있는 노출 콘크리트다.

시간 무엇이 보이나
0–0.9 종이 위 머리글("월요일 오전 6:40", "일곱 마디", 굵은 줄) 아래로 비어 있는 칸들이 보인다. 칸은 파란 레이아웃 연필선으로 그려져 있고 번호(02–07)가 붙어 있다. 카메라는 살짝 기울어진 채 다가오며 자리를 잡는다. 0.14초부터 매일 아침(300)이 음절마다 꽂히고, 오른쪽 끝까지 가는 가는 줄이 그어진다.
0.92–1.3 첫 이동이다. 반대로 살짝 물러났다가(예비 동작) 확 빠지고, 넘쳤다가 자리 잡는다. 배율은 2.6에서 1.1로 줄어들며 방사형 모션 블러가 생긴다. 생각만 했다(900, 판면 너비)가 꽂힌다.
1.95–2.4 아래로 내려가 오/늘/은(900, 세 음절을 세로로 쌓음)에 닿는다.
2.92–3.3 카메라가 90° 돈다. 회전과 확대가 한 나선을 따라 함께 움직여서, 세로로 놓인 가는 그냥(300)이 가로로 읽힌다. 아래에 거대한 "오"가 돌아 누워 있다.
3.8–4.4 반대로 90° 돌며 빠진다. 주홍 한/번이 1.7배 크기에서 꽂히고, 펀치와 감쇠 흔들림이 따른다(첫 번째 큰 박).
4.98–5.4 다시 −90° 돌아 해 보기로(300)에 닿는다. 위에서 내려오던 가는 줄 끝에 점이 찍힌다.
5.95–6.4 +90° 돌아 나오며 했다(900)가 꽂힌다(작은 박). 화면에는 가운데 띠 전체가 보인다.
6.92–7.3 비어 있는 마침표 자리(파란 십자)로 배율 4.6까지 파고든다. 주홍 마침표가 2.6배 크기에서 내리꽂히며 잉크 방울 일곱 개를 튀긴다(가장 큰 박).
7.48–8.8 절정, 상승. 마침표에서 살짝 더 다가갔다가(예비 동작), 배율 4.6에서 0.73까지 약 여섯 배를 줌 블러와 함께 솟아오른다. 종이 가장자리, 그림자, 콘크리트 벽이 처음 드러난다. 그사이 바닥글(가는 줄, 작은 글 세 줄 "알람을 끄고 / 창문을 열고 / 운동화 끈을 묶었다.", 06:40)이 찍혀 나온다.
8.8–10 조금 넘쳐 물러났다가 자리 잡는다. 이후 아주 느리게 계속 멀어진다. 포스터 한 장이 완성된다(포스터 시각 9.4초).

포스터의 짜임은 세 단으로 되어 있다. - 위: 머리글, 매일 아침, 생각만 했다. - 가운데 띠: [오/늘/은 쌓음][그냥 ↓][해 보기로 ↑][한/번 쌓음]. "그냥" 아래로는 점으로 끝나는 세로 줄이, "해 보기로" 위로는 점으로 시작하는 세로 줄이 이어져 서로 대칭을 이룬다. - 아래: 했다. + 주홍 마침표, 바닥글.

크기 단계는 셋이다. 쌓인 큰 글자, 판면 너비의 줄, 작은 가로·세로 글자다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 글자 지도 조판(main.js:189 place, main.js:199-224)
  • 모든 문구는 100px에서 음절마다 펜 위치와 잉크 상자(measureText의 actualBoundingBox)를 잰다(main.js:158-185). 쌓는 문구는 줄마다 가운데를 맞추고, 다음 줄 잉크 위를 앞 줄 잉크 아래 + 0.07em에 둔다.
  • place(p, S, {left|right|cx, top|bottom})는 크기 S와 회전(0, ±90°)으로 돌린 잉크 상자를 앞 문구의 가장자리에 붙인다. 문구 → 세계 행렬은 [k·cos, k·sin, −k·sin, k·cos, ox, oy]이다.
  • 가운데 띠의 높이 Hm은 이분법으로 구한다(main.js:212-222). 두 더미(오/늘/은, 한/번)가 높이 Hm을 채우게 키웠을 때, 그 사이에 두께 TT인 세로 글 두 줄과 간격이 정확히 남도록 한다. 그래서 띠가 빈틈없이 맞물린다.
  • 회전한 문구는 가운데에 둔다(main.js:201-203, main.js:207-210 주석)
  • 90° 돈 카메라에서는 화면의 긴 변(1920)이 종이의 짧은 변(가로) 위에 놓인다. 벽을 보이지 않으려면 배율이 ZROT ≈ 1.99 이상이어야 하고, 그러면 보이는 가로 범위가 종이 너비와 거의 같다.
  • 그래서 회전한 문구가 종이 가장자리에 있으면 늘 화면 위나 아래 끝(자막 자리)으로 밀린다. 첫 판(가장자리 세로 단)에서 실제로 그랬다.
  • 회전한 두 문구는 판면 가운데 근처의 가는 단에 두었다.
  • 카메라 = 닮음 변환, 이동 = 닮음군의 측지선(main.js:86 camOf, main.js:92 blend)
  • 세계 → 화면은 복소수로 s = a·w + b, a = z·e^(−iθ)이다.
  • A → B 이동에서 B∘A⁻¹는 화면 위의 고정점 하나 c₀ = (b_B − λb_A)/(1 − λ), λ = a_B/a_A를 갖는다. 중간 카메라는 c₀ + λˢ(p − c₀)이다. 이것은 고정점을 중심으로 한 로그 나선 운동이라서 회전과 배율이 한 박자로 움직이고, 배율은 로그 공간에서 고르게 변한다.
  • clog의 편각을 (−π, π]로 잡아서 회전은 늘 짧은 쪽으로 돈다.
  • 두 글자가 만나는 모서리 근처를 축으로 화면이 "휘감기는" 키네틱 타이포 특유의 전환이 이 식 하나에서 나온다.
  • 이동 곡선 s(t)(main.js:112 moveS, 표 main.js:55-62)
  • 예비 동작: −a·(1 − cos)/2. a = 0.05이고 0.11초다.
  • 휘두르기: 거듭제곱 3.4의 in-out으로 1 + o까지 가며, 0.3초다.
  • 정착: 1 + o·e^(−ζτ)(cos ωτ + ζ/ω sin ωτ). 시작 속도가 0이라 휘두르기와 매끄럽게 이어지고, 한 번 덜 갔다가 선다.
  • s < 0이면 반대로 살짝 돌고 물러나고, s > 1이면 회전과 배율이 넘친다. 같은 측지선을 따라가기 때문이다.
  • 상승(마지막 이동)은 1.1초, 거듭제곱 2.4, 1 Hz로 정착한다.
  • 이어짐(main.js:283 baseCam, main.js:300-313)
  • 각 이동의 시작 카메라 START[i]는 setup에서 앞 이동이 남긴 그대로 계산한다. 아직 흔들리며 정착하는 중이어도 이음매에서 튀지 않는다.
  • 머무는 동안에는 배율이 초당 3%씩 천천히 밀려 들어간다(pushed, main.js:266). 마지막 포스터에서는 −1.4%로 계속 멀어진다.
  • 벽이 보이지 않게: 두 겹으로 막는다.
  • 뷰 자체: 화면 네 귀퉁이가 종이 안에 들도록 중심을 옮긴다(main.js:248 clampView).
  • 회전 도중 대각선 귀퉁이가 나가는 경우: setup에서 이동마다 표본 40개로 필요한 확대를 재서 1 + BULGE·sin(πs)로 부풀린다(main.js:300-313, 최대 0.8). 돌면서 파고드는 펀치처럼 보인다.
  • 그래도 남는 예비 동작·넘침·흔들림의 몇 프레임: keepInside(main.js:273)가 초점 기준으로 귀퉁이가 종이 안에 들어오는 최소 배율을 닫힌 식으로 곱한다. 상승 구간에서는 끈다. 0–7.6초를 1/60초 간격으로 훑어 귀퉁이가 하나도 나가지 않는 것을 확인했다.
  • 핸드헬드·펀치·흔들림(main.js:316 fullCam, 박 main.js:67)
  • 기본 카메라 위에 화면 공간의 사인 두 개 핸드헬드(±3px, ±0.13°)를 더한다.
  • 큰 박 세 번(한 번, 했다, 마침표)에는 감쇠 흔들림 A·e^(−kd)·sin(2πf·d)와 펀치(0.05초 올라가고 0.14초로 감쇠)를 더한다. 모두 t의 닫힌 식이다.
  • 속도 기반 모션 블러(main.js:587 samplesAt, main.js:604-618)
  • 셔터는 180°(1/60초)다. 화면 위 탐침 15점이 셔터 처음과 끝 사이에 움직인 최대 거리 md를 잰다.
  • 표본 수는 N = ceil(md/6) + 1이고 최대 16이다. 멈춰 있으면 1이다.
  • 표본마다 셔터 안의 시각 tₖ로 장면 전체(카메라와 글자 상태 모두)를 오프스크린에 그린다. 본 캔버스에는 globalAlpha = 1/(k+1)로 차례로 얹는다(누적 평균). 장면이 불투명하므로 정확한 평균이다.
  • 회전 이동은 나선형, 상승은 방사형 줌 블러가 저절로 나온다.
  • 글자가 꽂히는 동안에는 최소 4개, 마침표에는 12개를 쓴다. 0–10초 평균은 약 5개다.
  • 글자 꽂기(main.js:454 glyphState, 일정 main.js:227-236)
  • 음절마다 0.05초 간격으로 들어온다(쌓은 문구는 0.085초).
  • 크기: 1 + lift에서 가속하며 1로 떨어진다(0.13초). 이후 0.05의 찌그러짐이 감쇠한다. lift는 보통 0.42, "한 번"은 0.7, 마침표는 1.6이다.
  • 굵기 축: 300 문구는 80 → 300, 900 문구는 480 → 900으로, 지수 감쇠 0.075초다. 공중에서는 가늘고 크다가, 닿으면서 잉크를 머금는다.
  • 색: 주홍 → 먹(0.05–0.27초). 강조 문구는 주홍으로 남는다.
  • 음절은 측정한 자리에 하나씩, 잉크 중심을 축으로 그린다. 굵기가 변해도 조판이 밀리지 않는다.
  • 글자 지도의 빈칸(main.js:529): 아직 오지 않은 문구 자리에 파란 연필 상자와 읽는 순서 번호를 그린다. 그 문구가 꽂히면 0.22초에 걸쳐 지운다. 빈 종이가 비어 보이지 않고, 다음 목적지를 미리 보여 준다(기대감).
  • 인쇄된 느낌
  • 종이(main.js:336): 1/4 해상도 주기 값 노이즈 얼룩, 왼쪽 위 조명, 섬유 1,500가닥, 티끌로 이루어진다.
  • 종이 결(main.js:370): 384² 반복 무늬(세계 px당 2텍셀)이고, 글자 위에도 덮는다(main.js:578). 먹과 주홍에 종이가 비쳐 인쇄물처럼 보인다.
  • 벽(main.js:381): 얼룩, 물자국, 기공 5,200개, 거푸집 이음매, 폼타이 구멍, 종이 그림자로 이루어진다. 구멍은 마지막 구도에 맞춰 포스터 양옆을 테두리처럼 두르게 놓았고, 자막 뒤에는 두지 않았다(main.js:410).
  • 화면 공간 마감(main.js:435): 비네트와 자막 아래 어두운 띠를 미리 그려 두고, 프레임마다 한 번 얹는다.
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 그림은 t의 순수 함수다.
  • 카메라는 이동 표와 setup에서 구한 START/BULGE로 정해지는 닫힌 식이다.
  • 글자 상태, 흔들림, 핸드헬드, 잉크 방울의 비행(1 − e^(−u/0.045))도 모두 t만 읽는다.
  • 모션 블러 표본 수도 t의 함수다.
  • 텍스처(종이, 종이 결, 벽, 그림자, 비네트)는 setup에서 rand(seed)로 한 번 굽는다. ctx.filter(그림자 흐림)도 setup에서만 쓴다.
  • drawScene은 시작할 때마다 변환, globalAlpha, 합성 모드, 이미지 스무딩을 기본값으로 되돌린다(main.js:483). 끝에 본 캔버스도 되돌린다.
  • 오프스크린 표본 캔버스는 헤드리스에서 CPU 래스터(willReadFrequently)로 만들고, setup 끝에서 한 번 그려 둔다(main.js:600, README 90번 규칙).
  • 글자는 매 표본 fillText로 다시 그린다(벡터라 배율 13배에서도 선명하다). 그림자 흐림이나 점선은 쓰지 않는다.
  • 렌더러 검사: 정순, 역순(새 페이지), 되돌아가기 모두 pass, 최대 1/255.
한계와 조절할 점
  • 회전한 문구는 판면 가운데 근처에만 둘 수 있다(위 "회전한 문구는 가운데에 둔다"). 가장자리에 세로 단을 두는 짜임은 종이를 벽보다 크게 두거나 벽이 보여도 되는 연출이어야 가능하다.
  • 맨 아래 문구(했다)의 클로즈업은 종이 아래 여백 때문에 화면 아래쪽에 놓인다. 그래서 바닥글은 상승 중에 찍히게 했다. 종이 비율이 세로로 길다(가로의 약 두 배).
  • 모션 블러는 표본 최대 16개라, 아주 빠른 휘두르기에서 가는 줄(머리글 줄, 연필 상자)이 몇 겹으로 보인다. 큰 글자는 매끈하다. 표본을 늘리면 실시간 비용이 그만큼 는다.
  • 실시간 비용: 이동 중 프레임은 (종이 + 글자 약 25음절 + 종이 결 + 합성) × 최대 16회다. GPU 브라우저에서는 예산 안이라고 보지만, 여기서는 헤드리스 CPU만 쟀다. 굵기 축 애니메이션은 굵기마다 폰트 인스턴스를 만들므로, 첫 재생에서 조금 느릴 수 있다.
  • 더 해 볼 것
  • 카메라 경로를 종이 위의 가는 선으로 남겨, 마지막 포스터에서 읽는 길이 보이게 하기. 촘촘한 판에서는 선이 글자를 가로질러 취소선처럼 읽힐 수 있어 이번에는 넣지 않았다.
  • 상승 중의 약한 원근(기울기).
  • 낭독 음성의 음절 시각에 맞춘 꽂기.
