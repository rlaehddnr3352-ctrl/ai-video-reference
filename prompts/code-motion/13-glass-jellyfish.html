활용 가이드

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

3D·공간로 쓸 때

제품이나 공간을 입체로 돌려 보거나 카메라가 공간을 지나가는 장면에 써요.

  • 제품 3D 모델(GLB)이 있으면 그대로 쓰고, 없으면 단순한 도형으로 만들어 달라고 해요.
  • 카메라 움직임은 한 방향으로 하나만. 사전의 카메라 무빙 카드 이름을 같이 쓰면 정확해요.
  • GPU를 많이 쓰니 렌더링은 시간이 걸려요. 해상도를 낮춰 미리 보고 마지막에 올리세요.

영상에 옮길 때 주의

  • three.js — 영상 스킬이 three.js를 넣는 방법을 따른다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

  • 0–2.5 s 등장: 완전한 어둠에서 시작해 수면 쪽 빛줄기(god rays)와 함께 유리 같은 해파리가 화면 아래쪽에서 떠오른다.
  • 2.5–5 s 박동: 갓(bell)이 1.6초 주기로 오므라들었다 펴질 때마다 몸이 한 번씩 위로 밀려 올라가고, 긴 촉수 36가닥·짧은 테두리 촉수 64가닥·주름진 구완(oral arm) 4개가 시차를 두고 따라 흔들린다. 갓 안쪽으로 보라빛 생식소 고리와 방사관이 굴절되어 비친다.
  • 5–7 s 절정: 갓 꼭대기에서 생물발광이 켜져 빛의 앞머리가 방사관을 따라 가장자리까지 내려가고, 신경환이 번쩍인 뒤 빛의 펄스가 촉수를 타고 아래로 흘러간다. 주변 물은 살짝 어두워지고(빛이 화면을 장악), 가까운 플랑크톤이 청록빛으로 물든다. 블룸이 이때 가장 강하다.
  • 7–10 s 여운: 유리 가장자리와 신경환에 잔광이 남은 채 해파리는 계속 오르고, 마지막 1.7초 동안 빛이 다시 가라앉아 검정으로 끝난다(라이브 재생이 10 s → 0 s로 돌아갈 때 이음매가 보이지 않도록).

카메라는 해파리의 평균 상승 속도로 따라가며 아래에서 살짝 올려다보고, 10초 동안 약 33° 공전하면서 9.6 → 8.1로 다가간다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 유리 갓 = 닫힌 두께 껍질 + MeshPhysicalMaterial: 바깥면(정점→가장자리)과 안쪽면(가장자리→정점)을 이은 회전체 메시를 매 프레임 다시 만든다(main.js:294). 단면은 수축값 c에 따라 접시형 ↔ 종형으로 바뀌는 닫힌 식(main.js:68 outerAt, 이완 시 가장자리가 바깥으로 벌어지고 수축 시 안으로 말림)이고, 안쪽면은 바깥면을 법선 방향으로 두께 thick(s)만큼 민 것(main.js:76 profile). 가장자리 8엽 물결과 둘레 방향 흔들림을 얹은 뒤 computeVertexNormals()(main.js:440). 재질은 transmission 1 · thickness 0.5 · ior 1.36 · iridescence 0.6 · attenuationColor + PMREM으로 구운 수중 환경맵(main.js:276, main.js:322).
  • 투과(refraction) 버퍼 활용: three.js는 불투명 목록을 먼저 투과용 렌더 타깃에 그린 뒤 유리가 그것을 굴절시켜 샘플링한다. 그래서 빛나는 것(배경 셰이더·리본·플랑크톤·내부 코어)은 모두 transparent: false + AdditiveBlending으로 불투명 목록에 넣었다(main.js:372, main.js:352). 블렌딩은 가산이면서 투과 버퍼에는 들어가므로 생식소·방사관·구완이 유리를 통해 굴절되어 보인다. 투과 버퍼는 renderer.transmissionResolutionScale = 0.5(main.js:257).
  • 안에서 켜지는 빛: onBeforeCompile로 물리 재질의 emissivemap_fragment 뒤에 코드를 넣어(main.js:330) 방출광 = 앞머리 uFront 위쪽만 켜지는 띠 × 프레넬³(시선이 껍질을 비스듬히 지날수록 밝음, main.js:342) + 앞머리의 밝은 테두리 + 늘 켜진 약한 가장자리광 uRim. 갓 안쪽에는 가산 빌보드 코어(main.js:352).
  • 촉수·구완 = 시간 지연(follow-the-leader) 닫힌 식: 길이 u 지점은 "λu초 전의 가장자리 위치"(contraction(t-λu), bodyY(t-λu), 기울기)에서 아래로 늘어지고, 그 위에 u에 따라 커지는 사인파를 더한다(main.js:456). 그래서 갓의 수축이 촉수를 타고 내려가는 파동이 되고, 몸이 튀어 오를 때 촉수가 늘어났다 풀린다. 리본은 CPU에서 중심선→카메라를 향한 띠로 확장하는 Ribbons 클래스(main.js:191, build main.js:221), 셰이더는 가운데가 밝고 가장자리 림이 있는 가산 띠(main.js:134, main.js:145). 절정의 빛 펄스는 u를 따라 움직이는 가우시안(main.js:454). 구완은 반투명 막 + 양쪽 물결 주름 2줄(main.js:487), 생식소·방사관·신경환은 안쪽면 위의 곡선(main.js:514).
  • 배경: 화면을 덮는 삼각형 하나의 프래그먼트 셰이더 — 심해 그라디언트, 스넬의 창에서 퍼지는 빛줄기(각도 방향 1D 노이즈 3옥타브), 해파리 위치 주변의 산란광, 비네트(main.js:103, main.js:116). 주의: gl_FragCoord를 쓰면 반 해상도 투과 버퍼에서 화면의 1/4만 늘어나 찍혀 유리 속이 어둡게 나온다 — uv는 삼각형 정점에서 받는다.
  • 플랑크톤: 1600개 Points, 시드 속성만 두고 위치를 셰이더에서 t로 계산, 카메라 높이 기준 mod로 순환, 초점 거리에서 멀수록 커지고 흐려지는 원판(피사계 심도 흉내), 해파리 근처는 발광 시 물듦(main.js:154).
  • 후처리: EffectComposer(HalfFloat, MSAA 4) → UnrealBloomPass → OutputPass(ACES + sRGB)(main.js:394–401). 블룸 세기·노출·코어·주변 어둡게 하기(dim, main.js:551)는 모두 track().
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 모든 움직임이 t의 닫힌 식: 박동 contraction(t)(main.js:22), 상승 bodyY(t)(펄스마다 연속인 계단+표류, main.js:29), 빛 glow/front/coreK(main.js:45–50), 등장·퇴장 revealIn/revealOut/edge(main.js:41–44).
  • 촉수의 "관성"은 상태를 쌓지 않고 과거 시각 t-λu의 닫힌 식을 다시 계산하는 것으로 대신했다 — 어떤 순서로 seek해도 같은 그림.
  • 메시·리본 버퍼는 매 프레임 전부 덮어쓴다. 난수는 rand(seed)만 setup에서. PMREM은 setup에서 한 번.
  • THREE.Clock/performance.now 미사용. EffectComposer.render()는 인자가 없으면 내부 Timer로 delta를 재므로 composer.render(0)(main.js:559).
  • 라이브 루프: t=0과 t=D 모두 노출 0(edge)이라 끝→처음 점프가 검정→검정.
한계와 조절할 점
  • 투과는 화면 공간 근사라 유리 뒤의 유리 자신은 굴절되지 않는다(이중 굴절 없음). 갓 앞을 지나는 플랑크톤·촉수도 유리 픽셀에 덮여 굴절된 모습으로 보인다.
  • 리본은 카메라를 향한 평면 띠라 굵은 구완을 가까이서 보면 얇은 막처럼 보인다. 튜브 메시 + 버텍스 셰이더 변형으로 옮기면 CPU 작업도 줄어든다.
  • 촉수 간 충돌·자기 교차가 없다. 지연 기반 근사라 급격한 상승 때 촉수 길이가 약 10% 늘어난다.
  • 다음: 갓 표면의 미세 주름 노멀맵, 빛줄기를 3D 볼륨 판으로(시차), 생물발광 입자를 촉수에서 흩뿌리기, 실제 GPU 브라우저에서 프레임 시간 측정.
