활용 가이드

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

영상에 옮길 때 주의

  • 손으로 쓴 WebGL2 셰이더 — 영상 스킬의 WebGL 층(three.js 등) 위에서 다시 쓴다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

북쪽을 바라보는 호숫가의 밤(9초). 검은 화면에서 별과 산, 가문비나무 실루엣이 떠오르고, 왼쪽 지평선 너머에서 시작한 초록 커튼이 오른쪽 위 하늘 꼭대기까지 대각선으로 걸쳐 있다. 커튼은 아래 테두리가 가장 밝고, 위로 갈수록 수직 광선(ray)으로 갈라지며, 200 km 위쪽은 붉은 빛으로 바뀐다. 접힌 자리(fold)는 시선이 커튼 면을 스치므로 기둥처럼 밝다. 4.8초부터 서브스톰 폭발(breakup) — 밝은 전선이 지평선 쪽 끝에서 머리 위쪽 끝으로 커튼을 따라 달려가며 불을 붙이고, 아래 테두리가 분홍·보라로 물들며 광선이 빠르게 흐른다(절정 5.2–6.6초). 이후 밝기가 천천히 가라앉고(여운) 마지막 0.4초에 어두워진다. 커튼 전체가 아래 호수에 거꾸로 비치며, 가까운 물결이 반사를 세로로 늘이고 흔든다. 멀리 설산·능선·숲·가까운 곶의 네 겹 실루엣이 카메라의 좌우 이동에 따라 서로 다른 속도로 움직인다(시차).

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리

세 개의 WebGL2 패스, 모두 전체 화면 삼각형 하나에 프래그먼트 셰이더.

  1. 커튼 = 수평면 위의 리본 + 수직 면. 커튼의 지상 투영선을 JS가 매 프레임 폴리라인(곡선당 160점)으로 만든다 (main.js:418 CURVES, main.js:424 buildCurves). 기울어진 기준선 위에 진행하는 두 파동을 얹는데, 법선 방향 진폭 A와 접선 방향 진폭 B를 함께 주면 트로코이드가 되어 B·k > 1인 곳에서 곡선이 스스로 되감긴다 (main.js:434) — 실제 오로라의 말림(curl)과 접힘. 높이 함수 z = Z(x)로는 이런 되감김을 만들 수 없어서 이 방식을 택했다.
  2. 패스 0 — 거리장 굽기 (main.js:39). 800×560 RGBA32F 텍스처의 각 텍셀(1600×1040 km 영역)에서 두 리본까지의 부호 있는 수평 거리와 가장 가까운 점의 호 길이(arc length)를 저장한다. 텍셀을 기준선에 투영해(main.js:51) 주변 28개 선분만 검사하므로 싸다.
  3. 패스 1 — 볼륨 레이마칭 (main.js:72, 0.62배 해상도 RGBA16F). 시선마다 지구 곡률을 넣은 85–380 km 껍질 구간을 구하고(main.js:88, h = r·tanE + r²/2R), 각 커튼이 있을 수 있는 창(window)만 34구간으로 나눠 걷는다(main.js:118). - 구간별 해석 적분: 커튼 단면을 가우시안 exp(−(g/σ)²)로 두고, 구간 안에서 g(거리)가 선형이라 보고 erf로 정확히 적분한다(main.js:140). 그래서 σ≈3 km의 얇은 면이 34걸음에도 계단·띠 없이 날카롭고, 시선이 면을 스칠수록 (|Δg|/Δr가 작을수록) 경로가 길어져 접힌 곳이 자연히 밝아진다. - 립시츠 검사 (main.js:137): 거리장은 1-립시츠이므로 한 구간에서 |Δg|가 구간 길이보다 크게 바뀌면 중간축이나 곡선 끝 연장선에서 부호가 뒤집힌 것 → 가짜 교차로 버린다. - 교차점에서 거리장을 한 번 더 읽어 정확한 호 길이를 얻고(main.js:150), 픽셀 하나가 커튼을 따라 덮는 길이 fs = r·δ/sinα로 광선 노이즈를 대역 제한한다(main.js:152, main.js:100). 이 두 가지가 없으면 커튼을 옆에서 볼 때 광선 무늬가 사선 무아레로 깨졌다. - 고도별 발광 (main.js:93): 아래 테두리 hb≈103 km(절정 때 −8 km), 초록 557.7 nm는 테두리에서 가장 밝고 광선마다 다른 높이로 감쇠(main.js:105), 붉은 630 nm는 170–245 km에서 켜져 위로 천천히 감쇠(main.js:106), 질소의 분홍·보라는 테두리 바로 아래 얇은 띠(main.js:107). 호 길이를 따라 달리는 폭발 전선(main.js:109). - 낮은 확산 오로라(95–150 km 층의 경로 길이, van Rhijn 효과, main.js:172)와 공기질량에 따른 소광(main.js:176).
  4. 패스 2 — 풍경과 호수 (main.js:248). 실루엣 네 겹을 실제 거리의 평면(120 m, 560 m, 7.5 km, 26 km)에 세우고 시선이 그 평면을 지나는 높이로 판정한다(가문비나무 main.js:230, 설산 main.js:221). 수평 방향 픽셀 크기로 안티에일리어싱. 물에 닿는 시선은 물결 법선(main.js:297, main.js:312)으로 반사한 뒤 수면 아래의 가상 카메라 (높이 −camH) 에서 같은 장면 함수를 다시 부른다(main.js:350) — 하늘은 패스 1 텍스처를 반사 방향의 화면 좌표로 다시 읽고, 나무 반사는 기슭을 기준으로 올바르게 뒤집힌다. 프레넬, 거리에 따른 mip 흐림, 세로 번짐, 물안개 (main.js:367), 패스 1 텍스처의 mip 체인으로 만든 블룸(main.js:323, 생성은 main.js:564), 지수 톤매핑(main.js:372).
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 모든 움직임은 track() 키프레임과 그 시간 적분으로만 정한다. 접힘·광선의 위상은 속도 track을 0부터 t까지 고정 간격(0.01 s)으로 합산한 값(main.js:406 integrate)이라, 직전 프레임과 무관하게 t만으로 결정된다.
  • 리본 폴리라인은 JS의 정수 해시 노이즈로 매 프레임 새로 계산해 texSubImage2D로 올린다(main.js:527) — 상태 없음.
  • 셰이더 난수는 화면 좌표·프레임 번호(round(t·30)) 해시뿐이며 Math.random/시계는 쓰지 않는다.
  • 렌더러 검사: 앞→뒤 / 새 페이지에서 뒤→앞 / 되돌아가기 모두 픽셀 동일(deterministic: true).
한계와 조절할 점
  • 커튼 아래 어두운 하늘이 밝은 테두리와 맞닿아, 정지 화면에서는 가끔 "능선"처럼 읽힌다. 테두리 아래로 번지는 확산 오로라나 얇은 2차 커튼을 더하면 나아질 것.
  • 자기장선은 완전한 수직으로 가정했다. 실제 오로라 광선은 자기 천정(magnetic zenith)을 향해 기울어 수렴한다.
  • 볼륨 패스는 0.62배 해상도라 가장 가는 광선은 약간 부드럽다. 시간 누적(TAA) 없이 결정성을 유지하려면 해상도를 올리는 것 외에 방법이 없다 — 예산 여유가 있으면 0.75배로.
  • 호수 반사는 하늘 텍스처를 반사 방향으로 다시 읽는 방식이라 화면 밖(위쪽) 하늘은 비칠 수 없다. 지금 구도에서는 반사 방향이 항상 화면 안에 들어오지만, 카메라를 더 내리면 깨진다.
  • 다음: 자기 천정 수렴, 커튼 위쪽의 얇은 구름 띠로 깊이 한 겹 더, 오로라 빛이 호숫가 눈밭을 비추는 조명.
