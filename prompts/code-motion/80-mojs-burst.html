활용 가이드

자막·카피로 쓸 때

대사·내레이션에 맞춰 핵심 문구를 보여 줄 때 써요. 쇼츠 시청 유지에 가장 직접적인 효과가 있어요.

  • 대본을 단어별 시간과 함께 주면(받아쓰기 결과) 박자가 정확해져요.
  • 강조는 한 문장에 한 단어만. 다 강조하면 아무것도 강조되지 않아요.
  • 화면 아래 15%는 플랫폼 UI에 가려지니 비워 두세요.

제목·로고로 쓸 때

영상 첫 1–2초, 브랜드명이나 핵심 제목이 처음 나오는 순간에 써요.

  • 제목은 한 줄, 6–10자 안쪽이 가장 잘 보여요.
  • 기법이 끝난 뒤 0.5–1초는 글자를 멈춰 읽을 시간을 주세요.
  • 로고라면 브랜드 색 2–3개만 지정하면 나머지 톤은 AI가 맞춰요.

영상에 옮길 때 주의

  • mo.js: 영상 스킬에 없는 라이브러리라면 원리만 가져와 Canvas 2D·SVG·WebGL로 직접 쓴다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

따뜻한 흰 바탕(#FFF6EA)의 앱 화면에서 시작한다. 위에 「오늘은 특별한 날 / 하트를 눌러 확인해 보세요」, 아래에 자두색 탭 바가 있다.

  • 0–0.5 s: 흰 원형 버튼(평면 그림자 포함)이 탄성 있게 튀어나오고, 그 안에 하트 윤곽이 들어선다.
  • 0.3–0.6 s, 탭: 손끝 그림자와 잔물결이 생기고 버튼이 0.88로 눌린다.
  • 0.62 s, 놓기:
  • 윤곽은 사라지고 분홍 하트가 탄성으로 튄다(elastic).
  • 분홍 링이 퍼진다.
  • 원 10개와 삼각형 10개의 버스트 두 겹이 터진다.
  • 버튼도 출렁이며 돌아온다.
  • 0.75–2.1 s: 작은 하트 18개가 소용돌이치며 떠오른다(ShapeSwirl). 「함께한 날」 카운터가 0 → 100으로 올라가며 끝에서 느려진다.
  • 2.1–3.1 s, 100:
  • 숫자가 한 번 튀고 하트가 부풀었다가 쪼그라든다.
  • 혼합 도형 버스트가 터지는 사이, 분홍 원과 짙은 청록 원이 차례로 화면을 덮는다(색면 전환).
  • 카운터 숫자는 날아올라 2.7배로 커지며 먹색에서 분홍 그림자를 단 금색으로 바뀐다. 그대로 제목의 「100」이 된다.
  • 3.0–6.3 s, 파티:
  • 「일」이 튀어 들어오고 청록 원판 두 장이 탄성으로 펼쳐진다.
  • 폭죽 일곱 발이 터진다. 꼬리 달린 로켓이 흔들리며 오르고, 섬광·링·원·다각형·지그재그·곡선·사각형이 섞인 버스트가 터진 뒤 잔불이 튄다.
  • 리본 같은 소용돌이 입자가 바닥에서 계속 오른다.
  • 「축하해」가 한 글자씩 튀어 착지하고, 글자마다 작은 버스트가 따른다.
  • 5.95 s에 클라이맥스: 링 세 겹(하나는 점선이 돌며 퍼짐), 광선 36개, 하트를 섞은 26개 버스트가 터지고 제목 전체가 한 번 박동한다.
  • 6.3–9 s, 여운: 점선 링 두 개가 천천히 돌고, 제목 둘레에서 반짝이 16개가 깜빡이고, 색종이 34장이 뒤집히며 흔들려 내려온다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 단 하나의 mojs.Timeline(main.js:139): 모든 모듈(Shape·ShapeSwirl·Burst·Html·Tween)을 tl.add로 넣는다. 각자의 delay(Burst는 timeline: { delay })로 배치하고, 길이 D = 9 s의 빈 Tween으로 시계를 잡는다(main.js:323).
  • Shape + then 체인(main.js:154–164): 버튼은 등장(elastic) → 눌림(0.88) → 놓기(elastic), 하트는 팝 → 부풂 → back.in 붕괴다. isShowEnd: false인 체인의 마지막이 끝나면 감춰진다.
  • 커스텀 도형(main.js:37–48): mojs.CustomShape를 상속해 하트와 4각 반짝이를 addShape로 등록했다. 버스트 자식 도형에도 섞어 쓴다.
  • Burst: 자식 옵션에 배열을 주면 mo.js가 자식 순서대로(나머지 연산) 나눠 준다(_getPropByMod). kids()(main.js:51)가 시드 난수로 자식마다 다음 값을 구체적인 숫자 배열로 만든다. mo.js의 'rand(…)' 문자열은 쓰지 않는다.
  • 도형(원·다각형·지그재그·곡선·사각형·하트)
  • 채움/선 색, 크기, 꼭짓점 수
  • 회전량, 길이, 지연
  • 도달 거리(pathScale), 각도 흔들림(degreeShift), 소용돌이 여부·크기·주파수·방향
  • ShapeSwirl: 떠오르는 하트, 폭죽 로켓(점 세 개를 45 ms씩 늦춘 꼬리), 바닥에서 오르는 리본, 떨어지는 색종이. 색종이의 scaleX는 curve: p => cos(2πkp) 속성 곡선이라 종이가 뒤집히듯 깜빡인다(main.js:310–319).
  • 속성별 이징·곡선: scale: { 0.2: 1, easing: 'back.out' }, opacity: { 1: 0, easing: 'quad.in' }. bump = sin(πp)는 0 → 1 → 0인 순수 이징 함수로, 탭 그림자·카운터 팝·제목 박동·반짝이에 쓴다.
  • Html 모듈: 머리글·탭 바·라벨의 등장, 「일」「축」「하」「해」의 탄성 착지, 제목 박동. 카운터는 요소 네 겹(move ⊃ pop ⊃ in ⊃ 먹색/금색 면)에 Html 모듈을 하나씩 걸어 서로 transform을 덮어쓰지 않게 했다. 먹색 → 금색은 두 면의 교차 페이드라 중간의 탁한 색이 없다.
  • 카운터(main.js:191–199): mojs.Tween의 onUpdate(ep)가 round(ep·100)을 쓴다. 이징은 끝에서 느려지는 1−(1−p)^2.2이다.
  • 제목 조판: setup에서 Black Han Sans가 실린 뒤 캔버스로 「100」「일」「축하해」의 폭을 재서 한 단어처럼 중앙 정렬한다(main.js:116–125). 카운터의 출발 위치·배율은 그 결과에서 역산한다.
  • 레이어: 화면(z1) < 색면(z2) < 폭죽·링(z3) < 글자(z4) < 앞쪽 입자(z5). 탄성 이징이 SVG 상자를 넘어도 잘리지 않게 svg { overflow: visible }를 준다(style.css).
프레임마다 같은 그림이 나오게 하는 법 (결정성)

mo.js 1.3.0 배포본(dist/mo.umd.js)을 읽고 확인한 것:

  • setProgress는 동기적으로 그린다: Tween._setProgress → onUpdate → Module._draw가 곧바로 style/attribute를 쓴다.
  • tweener의 requestAnimationFrame 루프는 play()할 때만 시작한다. 여기서는 부르지 않는다.
  • mo.js 안의 setTimeout은 MotionPath·Spriter의 자동 재생뿐이고, 둘 다 쓰지 않는다.
  • 패키지 이름은 1.7을 예상했지만 설치본은 1.3.0이다.

문제는 각 트윈이 자기 _prevTime을 기억하고 본 경계에만 반응한다는 점이다. - 새 타임라인의 첫 _update는 시각만 기록한다. - 이전 시각과 새 시각 사이에 통째로 들어 있는 자식 구간은 건너뛴다. 진행률 1(또는 0)로도 가지 않고, Shape를 보이고 숨기는 onStart/onComplete도 불리지 않는다. - 그래서 0 → 9 s로 바로 가면 초반 버스트가 시작 상태로 남는다.

해결 — seek.js의 createSeeker(tl): 1. 첫 두 번의 setProgress(0)으로 타임라인을 깨운다. 2. 모든 잎 트윈의 실제 구간 [startTime, endTime]을 모아 각 구간의 중점을 표본으로 둔다(중복 제거, 수백 개). 3. cur → ms로 갈 때 그 사이의 표본을 진행 방향 순서대로 한 번씩 밟은 뒤 ms에 내린다.

각 잎은 연속 재생 때와 똑같이 자기 구간에 들어갔다 나오므로, ms에서의 진행률과 보임/숨김은 ms만으로 정해진다. - 정방향 재생에서는 프레임당 표본이 0–3개다. - 반복 되감기(9 → 0)만 표본 전체를 한 번 거꾸로 밟는다.

추가로: - 모든 지연에 0.37 ms를 더했다(at, main.js:33). mo.js는 구간 경계에 정확히 닿을 때 접근 방향에 따라 보임/숨김이 갈리는데, 이렇게 하면 프레임 시각이 경계와 정확히 겹치지 않는다. - 난수는 전부 rand(시드) 숫자이고, 이징은 문자열 프리셋, 베지어 배열, 순수 함수 중 하나다. - 카운터의 shown 변수는 같은 글자를 다시 쓰지 않게만 하는 캐시라 결과에 영향이 없다.

한계와 조절할 점
  • 길이: D = 9(main.js:21). 팔레트: C(main.js:22). 버튼 위치: BX, BY(main.js:26). 제목 위치·크기: main.js:27–29.
  • 카운터 속도·곡선: main.js:193(duration: 1380, 지수 2.2).
  • 색면 전환: main.js:211–212. 두 원의 시차 0.12 s, 반지름 1260 = 화면 구석까지의 거리 + 여유.
  • 폭죽: 시각·위치·색 표 FW(main.js:228). 버스트 반지름 R, 자식 수 n은 그 아래 루프에 있다.
  • 리본 수: main.js:256. 반짝이 수: main.js:302. 색종이 수·시작 범위: main.js:310 이하.
  • 클라이맥스 시각 TM = 5.95(main.js:280).
  • 자식 무작위 범위(크기·길이·소용돌이 비율·회전량): kids()의 옵션(main.js:51).
  • 한계:
  • 도형마다 div + svg라 동시에 300개 남짓의 DOM 노드가 있다. 숨은 것은 scale(0)이라 그리지 않지만, 클라이맥스(5.9–6.6 s)가 가장 무겁다.
  • 반복 되감기 한 프레임은 표본 전체(수백 번의 setProgress)를 밟아 다른 프레임보다 길다.
  • 처음 열 때 ?t=로 늦은 시각부터 시작해도 같은 비용이 한 번 든다.
  • 색종이 일부는 9 s 이후까지 이어지는 트윈이다(마지막 프레임에서 공중에 있음). 마스터는 절대 ms로 매핑하므로 길이는 D 그대로다.
