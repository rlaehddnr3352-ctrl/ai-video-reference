  • 실제 숫자와 출처를 표로 주세요. AI가 숫자를 지어내지 않게 '주어진 값만 쓰라'고 적어요.
  • 한 화면에 수치 하나, 결론 숫자는 크게.
  • 그래프는 마지막 값에서 1초 멈춰야 기억에 남아요.

제품·앱 소개로 쓸 때

제품·앱·서비스의 생김새나 기능을 보여 주는 장면에 써요.

  • 실제 제품 사진(배경 제거 PNG)이나 앱 화면 캡처를 함께 주면 그대로 넣어 움직여요.
  • 기능 하나당 2–3초, 한 화면에 한 가지만 보여 주세요.
  • 가격·혜택 같은 숫자는 코드로 넣어야 깨지지 않아요.

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

비 오는 저녁의 작은 책방이다. 짙은 초록 칸을 단 나무 서가가 벽을 채우고, 맨 윗칸 책 사이에 주황 고양이 "귤이"가 눈만 내놓고 엎드려 있으며, 앞쪽 계산대에는 김이 오르는 찻잔과 녹색 갓 탁상등, 안경을 얹은 책 더미가 놓여 있다.

색은 따뜻한 나무색, 짙은 초록, 크림의 세 갈래다. 강조색은 고양이의 주황(#ee8a37) 하나이고, 자막에서도 "고양이"와 "귤이"에만 쓴다. 등불 빛은 색 토큰이 아니라 가산 합성되는 빛으로만 쓴다. 깊이 카드는 넷이다. 안쪽 방(7 m: 비 내리는 창, 안락의자, 스탠드), 서가(3.2 m: 책, 지구본, 지도 바구니, 도자기 고양이 장식, 시계, 사다리, 고양이), 매달린 등과 전구 줄(1.9 m), 계산대(0.85 m)다. 가게와 고양이는 모두 지어낸 것이다.

시간 무엇이 보이나
0–0.8 어둠에서 밝아진다. 위쪽에 "오늘의 숨은그림찾기 / 책방 고양이를 / 찾아보세요"가 줄마다 0.11초 간격으로 떠오른다(expo.out).
0–1.5 책방 전체가 보인다. 조리개가 f/8이라 거의 다 선명하고, 맨 앞 계산대만 조금 무르다(σ 3.1 px). 찻잔의 김이 오르고 전구가 깜박이며 등이 미세하게 흔들린다.
1.42–1.95 화면 전체가 어두워지며 색을 잃는다. 빛이 반지름 5배에서 1배로 모이며(outCubic) 안쪽 방 안락의자 위에 스포트라이트가 생긴다. 첫 자막은 이때 빠르게 나간다.
2.2–5.0 탐색이다. 지도 바구니 → 지구본 → 도자기 고양이 장식으로 도약하고, 자리마다 0.5–0.7초 머문다. 도약하는 동안 빛은 진행 방향으로 늘어나고 살짝 어두워진다. 마지막 도약(4.62초)은 고양이에 조금 못 미쳐 멈추고, 0.12초 뒤 짧은 보정 도약으로 5.0초에 고양이에 닿는다.
5.0–5.45 스포트라이트가 고양이 크기로 조여든다(back.out이라 조금 더 조였다 돌아온다). 가장자리에서 크림색 고리 두 개가 퍼지고 바깥은 더 어두워진다. 고양이는 귀를 두 번 씰룩이고(5.12, 5.34초) 빛에 동공이 가늘어진다. 자막 "맨 윗칸, 책 사이에 / 찾았다!"가 들어온다.
5.42–5.92 느린 눈 깜박임이다(닫기 0.16초, 멈춤 0.1초, 뜨기 0.24초).
6.0 절정(포스터). 어둡고 색이 빠진 책방 속에서 고양이만 따뜻한 빛 웅덩이 안에 있다.
6.5–7.12 스포트라이트가 열린다(반지름 ×20, inCubic). 색과 밝기가 돌아온다. 함께 조리개가 f/8 → f/1.2로 열리고(6.55–7.3초) 초점이 찻잔으로 간다(6.72–7.32초). 서가가 녹아내리고 전구는 보케 원판이 되며, 그림이 4.6% 커진다(초점 브리딩).
7.32–7.62 찻잔에 초점이 맞아 있다. 김이 또렷이 오른다.
7.62–8.66 랙 포커스다. 초점이 찻잔에서 고양이로 당겨진다. 찻잔과 계산대가 흐려지고 서가가 선명해지며, 그림은 원래 크기로 돌아간다.
8.66–10 여운이다. "책방 지킴이 / 시선 끝엔 / 언제나 귤이". 넓고 옅은 스포트라이트가 고양이 둘레로 돌아오고(8.75–9.8초, 바깥 노출 −50%, 탈색 48%), 고양이는 꼬리를 한 번 튕기고(9.05초) 한 번 더 천천히 깜박인다(9.25초).

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 스포트라이트 = 늘어나는 타원의 부호 거리(main.js:904-932)
  • 타원 중심 기준 픽셀 q에서 f(q) = |A·q| − 1, A = diag(1/a, 1/b)·S⁻¹이다. S는 시선이 움직이는 방향 u로 s배 늘리는 행렬이고 S⁻¹ = I + (1/s − 1)·u·uᵀ다(main.js:906-908).
  • 거리는 1차 근사 d ≈ f/|∇f|로 구한다. ∇f = Aᵀ·A·q / |A·q|이므로 d = k0·(k0 − 1)/k1, k0 = |A·q|, k1 = |Aᵀ·(A·q)|다(main.js:914-918). 경계 근처에서 거의 정확한 유클리드 거리라서, 타원이 늘어난 방향에서도 감쇠 폭이 고르게 유지된다.
  • 바깥 정도는 o = smoothstep(−0.35F, F, d)다(F는 감쇠 폭: 탐색 중 92 px, 조인 뒤 50 px, 크기에 따라 √size배). 안쪽 폭을 짧게 잡아서 빛 웅덩이 속은 평평하고, 바깥으로는 길게 사라진다.
  • 이 계산은 1/4 크기(270×480, 약 13만 텍셀)에서만 한다. 감쇠 폭이 텍셀(4 px)보다 훨씬 넓으니 쌍선형 확대로 충분하다. 값은 ImageData의 알파에 쓰고 putImageData 한 번으로 올린다.
  • 바깥 = 휘도 보존 탈색 + 노출 감소, 마스크 한 장을 두 번 합성(main.js:929-931)
  • 마스크의 색은 검정이고 알파가 o다. 완성된 그림 위에 먼저 'saturation'으로 그린다. W3C 비분리 혼합 B = SetLum(SetSat(Cb, Sat(Cs)), Lum(Cb))에서 검정은 채도가 0이므로, 결과는 Lum = 0.3R + 0.59G + 0.11B를 그대로 지킨 회색이다. 알파 o·desat만큼 원래 색과 선형 보간된다.
  • 같은 마스크를 source-over로 한 번 더 그린다. 검정을 알파 k로 덮으면 C·(1 − k), 곧 노출을 곱으로 낮춘 것과 같다(탐색 중 k = 0.7, 찾은 뒤 0.82, 약 −1.7 ~ −2.5스톱).
  • 어두운 사본을 따로 굽거나 매 프레임 필터를 돌리지 않는다. 전체 화면 합성 두 번과 작은 업로드 두 번이 전부다. 경계에는 같은 d로 만든 따뜻한 테두리 exp(−(d/0.42F)²)를 'screen'으로 얹는다(main.js:922, main.js:931).
  • 눈처럼 찾기: 고정과 도약(saccade)(main.js:66-103, main.js:106-130)
  • 도약 시간은 주 계열(main sequence)을 따라 진폭에 비례해 길어진다. 여기서는 T = 0.07 + 0.00032·진폭(px)초다(main.js:69). 372 px는 0.19초, 711 px는 0.30초 걸린다.
  • 위치는 최소 저크 곡선 p(u) = 10u³ − 15u⁴ + 6u⁵로 옮긴다(main.js:68). 시작과 끝에서 속도와 가속도가 0이고, 최고 속도는 가운데에서 1.875·진폭/T다.
  • 머무는 동안에도 사인 둘의 합으로 몇 px씩 떠돈다(고정 중 미동, main.js:98-100).
  • 마지막 긴 도약은 86% 지점에서 멈춘다(hypometric). 0.12초 잠복 뒤 짧은 보정 도약이 정확히 5.0초에 닿는다. buildGaze가 두 번 돌면서 마지막 고정 시간을 늘려 도착 시각을 맞춘다(main.js:70-88).
  • 속도 v는 gaze(t ± 1/240)의 중앙 차분이다(닫힌 식이라 결정적이다). fast = smoothstep(v/2600)으로 타원을 진행 방향으로 최대 1.36배 늘린다. 도약 중 시각 억제(saccadic suppression)를 흉내 내어 빛 안쪽도 최대 26% 어둡게 한다(main.js:112-127).
  • 찾음의 박자와 돌아오는 장치
  • 도착한 뒤 크기는 back.out(오버슈트 2.4)으로 조인다. 잠깐 더 작아졌다가 돌아온다. 크림색 고리 두 개가 0.13초 차이로 outCubic을 따라 퍼진다(main.js:991-1001). 임팩트는 이 박자 한 번뿐이다.
  • 열 때는 반지름에 20^inCubic(p)를 곱한다. 처음에는 천천히, 끝에는 화면 밖으로 빠르게 열린다(main.js:118).
  • 같은 장치가 여운에서 넓고 옅은 빛 웅덩이로 돌아온다(main.js:108-111). 이야기 내내 돌아오는 시각 장치가 이것이다.
  • 깊이 카드와 블러 피라미드(main.js:804-829)
  • 카드 넷을 setup에서 한 번 그린다. 서가 깊이에는 서가, 고양이, 고양이 앞의 책 두 권이 각각 카드로 서 있다.
  • 블러 단계는 σ = 0, 1, 2(같은 크기, blur(1px)·blur(2px))다. 그다음은 반 크기로 줄이며 blur(√3 px)를 걸어 σ가 4, 8, 16, 32 텍셀로 두 배씩 된다. 줄이면 σ가 반이 되고 거기에 √3을 제곱합으로 더하면 √(1 + 3) = 2이기 때문이다. 저장량은 원본의 약 3.3배다.
  • 카드는 화면보다 90 px 넓게 그린다. 가장자리가 흐려질 때 투명한 테두리가 화면에 들어오지 않고, 초점 브리딩으로 확대돼도 화면을 덮는다. 계산대는 확대될 때도 또렷하도록 1.15 텍셀/px로 굽는다.
  • 얇은 렌즈의 착란원(main.js:47-60)
  • f = 50 mm이고 화면 폭 1080 px를 24 mm(45 px/mm)로 본다. 상거리는 v_f = f·z_f/(z_f − f), 조리개 지름은 A = f/N이다.
  • 착란원 지름은 c = A·v_f·|1/z − 1/z_f|(mm에 45를 곱해 px)다(main.js:52). 깊이의 역수 차이에 비례한다.
  • 가우시안 σ는 원판과 2차 모멘트를 맞춘 σ = c/4다. 반지름 R인 균일 원판은 축마다 분산이 R²/4다(main.js:944).
  • 예를 들어 초점 3.2 m, f/1.2이면 계산대 c = 82 px(σ 20.6), 안쪽 방 16 px(σ 4.0)다. 초점 0.85 m이면 서가 86 px(σ 21.5), 안쪽 방 103 px(σ 25.7)다. 탐색 동안(f/8)은 계산대만 12 px(σ 3.1)다.
  • 이웃한 두 단계의 교차 페이드(premultiplied)(main.js:861-891)
  • σ를 0단계 텍셀로 바꾼다(×m ÷ 브리딩 배율). σ ≤ 1이면 0단계와 1단계를 선형으로, 그 위는 1 + log2(σ)로 이웃한 두 단계와 비율 w를 고른다(main.js:865).
  • 스크래치에 A를 알파 1 − w로 그리고, B를 'lighter'로 알파 w만큼 더한다. 미리 곱한(premultiplied) 색에서 정확히 (1 − w)·A + w·B가 된다. source-over로 겹치면 투명한 가장자리(아치 구멍, 계산대 위 물건의 윤곽)에 선명한 쪽 윤곽이 남거나 뒤가 비친다.
  • 불투명한 안쪽 방 카드는 A 위에 B를 알파 w로 덮어도 같은 식이 되므로 스크래치를 거치지 않는다. w가 0이나 1에 가까우면 한 장만 그린다.
  • 조리개와 랙 포커스(main.js:53-60)
  • 초점은 1/z_f(디옵터) 공간에서 inOutCubic으로 보간한다. c가 |1/z − 1/z_f|에 비례하므로 흐림이 고르게 바뀐다.
  • 탐색 동안은 f/8로 거의 다 선명하게 둔다(그동안은 스포트라이트가 시선을 이끈다). 스포트라이트가 열리는 동안 조리개를 스톱 단위 N = 8·(1.2/8)^p로 열어 얕은 심도로 넘어간다. 시선을 이끄는 일이 마스크에서 초점으로 넘어가는 순간이다.
  • 초점 브리딩(main.js:60, main.js:939)
  • 렌즈 전체를 앞뒤로 밀어 초점을 맞추면 상거리 v_f가 바뀌고, 모든 깊이의 상 크기가 v_f에 비례해 변한다. 배율 sb = v_f(z_f) / v_f(3.2 m)를 광축(화면 중심) 기준으로 모든 카드, 점광원, 김에 곱한다. 0.85 m에 맞추면 1.046배다.
  • 점광원 보케(main.js:894-901)
  • 전구, 매달린 등, 안쪽 방 스탠드는 카드에 굽지 않고 매 프레임 그 깊이의 c로 그린다. 반지름은 R = √(r² + (c/2)²)인 원판이고, 밝기는 에너지 보존 (r/R)²에 바닥값을 둔다.
  • R/r이 작으면 부드러운 점 스프라이트를, 크면 테두리가 조금 밝은 원판 스프라이트를 쓴다.
  • 김(main.js:973-984)
  • 퍼프 36개짜리 가닥 두 개가 u = (0.26t + j/36) mod 1로 오른다. 가로 흔들림 sin(4.6u − 1.2t)가 진행파라서 가닥 전체가 휘며 올라간다.
  • 계산대 깊이의 c로 반지름을 √(r² + (c/2)²)로 키우고, 알파를 (r/R)²로 낮춘다. 그래서 초점이 떠나면 김도 함께 번진다.
  • 고양이는 선명할 때만 움직인다(main.js:133-147, main.js:672-728, main.js:945-950)
  • 고양이 카드의 0단계는 매 프레임 그 시각의 자세로 다시 그린다. 1단계 이상은 setup에서 쉬는 자세로 구워 둔 것이다.
  • 그래서 자세 변화(귀, 동공, 눈꺼풀, 꼬리)에 게이트 g = clamp(1 − σ/0.12)를 곱한다(σ는 고양이 카드의 텍셀 단위). 흐린 동안에는 쉬는 자세라서 두 단계를 섞어도 어긋나지 않는다.
  • 귀 씰룩임은 가우스 펄스 두 개다. 동공 폭은 빛을 받으면 6.5 → 2.2 px로 줄어든다. 느린 깜박임은 위 눈꺼풀 곡선의 제어점이 아래 눈꺼풀까지 내려오는 것이다(main.js:714-727).
  • 몸통은 선반 판 위쪽만 남기고 잘라(clip) 그린다. 꼬리는 판 끝을 축으로 흔든다. 앞쪽 책 두 권과 앞발은 별도 카드라서 고양이가 그 뒤에 숨는다.
  • 자막(main.js:772-784, main.js:1010-1019): 글자는 setup에서 그림자까지 스프라이트로 굽는다. 줄마다 0.11초 간격으로 expo.out을 따라 떠오르고, 0.32초 inCubic으로 더 빠르게 나간다.
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 모든 값이 t의 닫힌 식이다. 시선 경로(구간표는 모듈을 불러올 때 한 번 만든다), 속도(중앙 차분), 스포트라이트 크기, 초점, 조리개, 고양이 자세, 김, 전구 깜박임이 다 그렇다.
  • 무거운 것은 setup에서 한다. 카드 그림, 블러 피라미드(ctx.filter는 setup에서만 쓴다), 스프라이트, 자막, 비네트, 그레인이 여기에 든다. 난수는 모두 rand(seed)다. 그레인 위치는 rand(5000 + round(t·30))에서 정한다.
  • 매 프레임 첫머리에서 주 캔버스, 스크래치, 고양이 캔버스의 2D 상태(변환, 알파, 합성, filter, 선 모양, 대시, 그림자, 이미지 보간 품질)를 기본값으로 되돌린다(main.js:161, main.js:937-938).
  • 스포트라이트 마스크는 매 프레임 모든 텍셀을 다시 쓴다. 고양이 0단계도 매 프레임 지우고 다시 그린다. 이전 프레임의 흔적이 남을 곳이 없다.
  • 헤드리스(api.headless)에서만 모든 캔버스를 CPU 래스터(willReadFrequently)로 만든다. 마스크와 테두리 캔버스는 매 프레임 putImageData하므로 언제나 CPU다.
  • 렌더러 검사 결과는 byte-identical이다(6개 시각, 앞→뒤 순서와 새 페이지의 뒤→앞 순서, 되돌아가기).
한계와 조절할 점
  • 카드 하나의 내용은 모두 같은 깊이다. 서가 안에서 사다리와 책 사이에는 흐림 차이가 없다. 카드를 더 쪼개면 깊이감이 풍부해진다.
  • 카드 블러는 가우시안이라서 렌즈다운 원판 모양은 점광원에서만 나온다. 원판 커널로 피라미드를 구우면 넓은 면의 번짐도 렌즈를 닮는다. 이웃한 두 단계의 교차 페이드는 진짜 중간 σ가 아니라서 전환 중에 살짝 빛이 번지는 느낌이 있다.
  • 카드 단위로 흐리므로, 흐린 앞 물체의 가장자리 너머로 뒤가 비치는 부분 가림(partial occlusion)은 근사다.
  • 조리개를 5.5스톱 여는 동안 노출은 그대로 둔다(셔터나 ND로 보정했다고 가정한다).
  • 스포트라이트는 화면 공간의 효과라서 그림자를 만들지 않는다. 진짜 조명처럼 보이게 하려면 깊이마다 빛 받는 양을 다르게 하거나 가림 마스크를 더할 수 있다.
  • 실시간 비용은 전체 화면급 합성 열 번 안팎(카드, 스크래치, 마스크 두 번, 비네트, 그레인)과 13만 텍셀 JS 반복문이다. GPU 브라우저에서는 예산 안이라고 보지만, 여기서는 헤드리스 CPU 수치만 쟀다.
