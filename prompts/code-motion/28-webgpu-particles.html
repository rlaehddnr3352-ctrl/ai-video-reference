활용 가이드

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

영상에 옮길 때 주의

  • WebGPU — 영상 내보내기(헤드리스)에는 쓰지 않는다. 원리만 참고

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

9.5초. 별이 깔린 어둠 속에서 원반은하 두 개가 화면 위아래에 떠오른다(0–0.9 s). 위쪽 은하는 궤도면에 거의 누워 있고 아래쪽 은하는 58° 기울어져 있다. 둘 다 금빛 팽대부와 크림색 원반 위로 푸른 나선팔이 감겨 있고, 팔에는 분홍 HII 매듭이 박혀 있다. 둘은 서로 끌려 다가오며 돈다(0–2.8 s). 2.8 s에 근점(거리 13, 원반 반지름과 비슷한 깊은 순행 통과)을 지난다. 이때 마주 보는 쪽이 늘어나 두 은하를 잇는 다리(bridge)가 생기고, 반대쪽으로는 조석 꼬리(tidal tail)가 길게 뿜어진다(절정 3–5.5 s). 조석력을 받은 가스 추적 입자는 별 탄생처럼 분홍·청백색으로 달아오른다. 카메라는 근점을 지나는 동안 위로 올라가며 돌고(방위 39° → −74°), 화면 안에서 두 은하는 서로를 돌아 위아래 자리를 바꾼다. 여운(5.5–9.5 s): 은하들은 다시 멀어지고, 활처럼 휜 꼬리 두 줄과 흩어진 별무리가 천천히 펼쳐진다. 카메라는 뒤로 물러나 전체를 담는다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 입자 1,048,576개(model.js:9). 위치 vec4(xyz, 은하 번호), 속도 vec4(xyz, 조석 들뜸), 정적 속성 u32 (은하·종족·밝기·색 흔들림·크기 비트 묶음, model.js:107)를 GPU 버퍼 세 개에 둔다. 종족: 팽대부(Plummer 구), 늙은 원반, 젊은 원반(가스 추적), HII 매듭(나선팔 위 군집 260개), 청색 거성. 젊은 별과 매듭은 로그 나선팔(피치 약 21°) 주위에 몰려 있다.
  • 은하 핵의 궤도는 JS에서 적분(model.js:56). 핵 둘(질량 MC+MD, 소프트닝 2.2)의 2체 궤도를 근점에서 시작해 T_PERI만큼 거꾸로 적분한 뒤 앞으로 다시 적분한다. 반 스텝마다 핵의 위치를 표로 만든다(leapfrog, 반 스텝당 40회). 이 계산은 싸고, 다시 돌려도 결과가 정확히 같다.
  • 스텝마다 쓰는 값은 setup에서 미리 한 번에 쓴다(main.js:426). 서브스텝마다 256바이트 칸을 하나 두고(핵 위치, 조석 보정, 격자, h, 소프트닝) 동적 오프셋 uniform으로 고른다(main.js:467). 그래서 여러 스텝을 커맨드 인코더 하나에 담을 수 있다.
  • 입자 스텝 = 비디오 1프레임당 3회의 drift–kick–drift(심플렉틱 leapfrog, main.js:130). 힘은 두 가지를 더한다. 1. 두 핵의 Plummer 인력(소프트닝 1.15). 핵은 팽대부와 암흑 헤일로를 합친 질량이다. 2. 입자–메시(PM) 자기중력. 원반과 팽대부 질량(은하당 0.3)은 입자가 직접 나른다.
    • 질량 할당(main.js:79): 입자 4개 중 1개가 4배 질량으로 32×12×32 격자(칸 6)에 CIC 가중치를 atomicAdd한다(main.js:95). 가중치는 2048배 고정소수점 정수다. 정수 덧셈은 스레드 순서와 상관없이 결과가 같아서 프레임마다 비트 단위로 똑같다(float atomic이었다면 순서에 따라 달라진다).
    • 장(field) 계산(main.js:100): 소프트닝된 그린 함수와의 합성곱을 FFT 대신 직접 합으로 구한다. 12,288칸 × 12,288칸(약 1.5억 쌍)을 워크그룹 메모리 타일(64칸씩)로 나눠 계산한다(main.js:116, 124). 격자가 작아서 직접 합이 FFT보다 단순하고, 고립 경계 조건(패딩 불필요)이 저절로 맞는다.
    • 보간(main.js:61): 입자는 같은 CIC 가중치로 주변 8개 노드의 가속도를 읽는다. 메시는 비디오 프레임마다 한 번 새로 계산한다.
  • 평형 상태로 시작하기(main.js:152). 입자를 자기 핵 주위에 놓고(place), 메시를 한 번 계산한 다음(spin, main.js:161), 시뮬레이션이 실제로 가하는 힘(자기 핵 + PM 장)의 반지름 방향 성분에서 원궤도 속도를 구한다. 해석적 근사가 아니라서 원반이 처음부터 흔들리지 않는다. 팽대부는 무작위 궤도면과 원반 회전을 일부 섞는다.
  • 조석 들뜸(main.js:144–145): 상대 은하 핵이 이 입자를 당기는 힘에서 내 핵을 당기는 힘을 뺀 것이 조석 가속도다. 그 크기에서 들뜸을 만들고 τ=80(약 1.8 s)으로 감쇠시킨다. 렌더에서 젊은 별과 HII 매듭의 밝기·색을 키우는 데 쓴다(상호작용이 일으키는 별 탄생 연출).
  • 렌더(main.js:194). 입자 버퍼를 그대로 인스턴스 정점 버퍼로 쓴다. draw(4, N) 한 번으로 triangle-strip 쿼드 100만 개를 그린다.
  • 정점 셰이더가 카메라 투영(camera.js, 렌즈 시프트로 자막 위에 구도)을 직접 계산한다.
  • 플럭스를 보존하는 정규화 가우시안을 쓴다(main.js:241). 빛의 총량은 크기와 무관하고 거리²로 줄어든다(main.js:233). 그래서 카메라가 물러나도 표면 밝기가 유지된다.
  • 반지름은 1.5 px 아래로 내려가지 않아서 깜빡이지 않는다.
  • rgba16float에 가산 합성한다 → 1/2·1/4·1/8 해상도 다운샘플(4탭 = 4×4 박스) + 9탭 가우시안 블룸 → ACES 톤매핑(main.js:329), 비네트, 디더.
  • 배경 별은 해시 격자의 3×3 이웃을 합산하고(main.js:309), 카메라 요(yaw)만큼 함께 돈다(main.js:582).
  • 노출(main.js:365): 0–0.9 s에 페이드인한다. 꼬리가 얇아지는 여운 구간에서는 노출을 1.0에서 1.3으로 살짝 올린다. FLUX(main.js:371)는 Node 시험 적분(입자 6만 개를 100만 개 밀도로 환산)으로 픽셀 밝기 분위수를 재서 정했다. 원반 몸통의 중앙값이 톤 곡선 중간쯤에 오게 했다.
  • 궤도·구도는 Node에서 같은 model.js / camera.js로 미리 맞췄다. 핵이 처음과 끝에 화면 세로축에 놓이고, 중요한 그림이 y < 1650 안에 들어오게 했다.
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • replay({ dt: 1/30, every: 60 })(main.js:528). 스텝 n은 서브스텝 3n…3n+2이고, 각 서브스텝은 미리 써 둔 uniform 칸(동적 오프셋)을 쓴다. 핵의 궤도는 JS 표라서 시각만으로 정해진다.
  • 상태 = 위치 버퍼 + 속도 버퍼(16 MB씩). 속도의 w 성분인 조석 들뜸도 여기에 들어 있다. 메시(질량·장)는 매 프레임 위치에서 다시 만드는 임시값이다. save()는 새 버퍼 두 개에 copyBufferToBuffer로 복사하고(main.js:555), load()는 거꾸로 복사한다(main.js:566). 체크포인트는 0, 60, 120, 180, 240스텝이다(약 160 MB).
  • 질량 할당은 정수 atomic이고 장 계산은 스레드마다 고정된 순서의 합이라서, 같은 GPU에서는 비트 단위로 같은 결과가 나온다.
  • frame()은 헤드리스 캡처와 긴 seek(6스텝 넘게 건너뛴 경우)에서만 device.queue.onSubmittedWorkDone()을 기다린다(main.js:619). 실시간 재생에서 매 프레임 기다리면 그 대기가 다음 화면 갱신을 넘길 때 플레이어가 그 틱을 건너뛰어 프레임이 반으로 준다(85번과 같은 문제). 끝에서 0초로 돌아가면 체크포인트 0을 복원한다.
한계와 조절할 점
  • 실제 GPU에서 직접 돌려 보지 못했다. 헤드리스 점검에는 WebGPU가 없어서 확인한 것은 대체 경로뿐이다. WGSL과 바인딩은 손으로 검토했다. 첫 실행에서 오류가 나면 화면이나 콘솔에 셰이더 줄 번호와 함께 나온다.
  • PM 격자가 거칠다(칸 6, 원반 반지름 13.5). 원반 자체의 나선 불안정이나 꼬리 속 덩어리 형성은 해상하지 못하고, 큰 규모의 자기중력만 들어간다. 격자를 키우려면 직접 합(O(M²))을 FFT 합성곱(64³, 패딩 128³)이나 멀티그리드로 바꿔야 한다.
  • 핵은 강체 Plummer 포텐셜이라서 동역학 마찰이 없다. 그래서 9.5초 안에 병합하지 않는다. 마찰을 넣으면 두 번째 접근과 병합까지 담을 수 있지만, 그 감속을 핵 주변 입자에도 같게 주어야 원반이 핵에서 떨어지지 않는다.
  • 노출(FLUX)은 Node 밀도 추정으로 정했다. 실제 화면에서 너무 밝거나 어두우면 FLUX와 exposure 트랙(main.js:365–371) 한 줄씩만 바꾸면 된다.
  • 다음 단계: 먼지(빛을 깎는 두 번째 패스), 꼬리에서 태어난 성단의 수명 모델, 피사계심도.
