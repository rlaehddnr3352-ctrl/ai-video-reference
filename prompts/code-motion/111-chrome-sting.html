오늘의 발견

방송 타이틀 스팅 · 금속 입체 글자 + 반사 + 빛 쓸기

광고 · 쇼츠에서는방송 타이틀처럼 번쩍이는 금속 로고

활용 가이드

제목·로고로 쓸 때

영상 첫 1–2초, 브랜드명이나 핵심 제목이 처음 나오는 순간에 써요.

  • 제목은 한 줄, 6–10자 안쪽이 가장 잘 보여요.
  • 기법이 끝난 뒤 0.5–1초는 글자를 멈춰 읽을 시간을 주세요.
  • 로고라면 브랜드 색 2–3개만 지정하면 나머지 톤은 AI가 맞춰요.

영상에 옮길 때 주의

  • opentype.js: 영상 스킬에 없는 라이브러리라면 원리만 가져와 Canvas 2D·SVG·WebGL로 직접 쓴다
  • three.js — 영상 스킬이 three.js를 넣는 방법을 따른다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

미감은 '방송 그래픽'이다. 남색이 도는 검은 스튜디오에 위에서 희미한 빛기둥이 내려오고, 바닥은 검게 윤이 난다. 「오늘의」는 차가운 크롬, 「발견」은 금이다. 강조색은 금 하나로, 「발견」과 자막의 괘선, '1분'에만 쓴다. 금속 면에는 스튜디오의 수평 경계(위는 밝은 소프트박스, 아래는 어두운 바닥)가 비쳐, 한 줄의 크롬 선이 글자를 가로지른다. 글꼴은 Pretendard 하나다. 입체 글자는 Black(OTF 윤곽), 자막은 Pretendard Variable 600/800이다.

시간 보이는 것
0–0.45 검은 화면에 불이 들어온다(환경 세기 0 → 0.88). 「오」의 ㅇ 고리를 아래에서 1.7단위 거리, 화각 44°로 본다. 크롬 고리에 소프트박스의 흰 창과 수평 경계가 비친다.
0–1.55 ① 매크로 활주. 렌즈가 고리 윗변을 따라 1.4 rad 미끄러진다. 화면은 −0.16 → −0.08 rad 기울어 있고, 앞쪽에 보케 알갱이 18개가 떠 있다. 첫 빛 띠가 반사 속을 왼쪽에서 오른쪽으로 지나가고, 0.62초에 고리 가장자리에서 별빛이 반짝인다.
1.55–3.8 ② 빼기와 회전. 거리 1.2 → 26.5를 로그 공간 inOutCubic으로, 화각 44° → 30°로 바꾼다. 바라보는 점은 고리에서 문장 가운데로 옮겨 가고, 기울기는 풀린다. 동시에 두 줄이 세로축으로 돌아 들어온다(「오늘의」 −0.62 rad, 「발견」 −1.05 rad). 각 줄은 2° 넘쳤다가 자리 잡는다. 2.6초쯤에는 거대한 「늘」 옆으로 옆모습의 금 덩어리가 지나간다.
3.45 / 3.82 ③ 잠금. 크롬 줄이 먼저, 금 줄이 마지막으로 선다. 금 줄이 설 때 카메라가 1.8% 밀렸다 돌아오고(펀치), 조명이 0.9 → 1.0으로 올라간다. 발밑에 반사가 생긴다.
4.0–4.78 금색 괘선 두 줄이 가운데에서 양옆으로 그어진다(expo.out). 이어 자막 「작은 질문에서 시작하는 1분 과학」이 왼쪽에서 오른쪽으로 닦여 들어온다.
4.55–6.25 ④ 빛 쓸기. 환경 속 밝은 띠(HDR 20)가 왼쪽에서 오른쪽으로 지나간다. 글자 면에는 세로 빛 띠가 구르고, 날카로운 모서리는 띠가 지날 때마다 하나씩 반짝인다. 같은 띠가 자막 위로도 지나간다.
5.4 절정. 띠가 「견」의 오른쪽 위 모서리를 지나는 순간 플레어가 터진다. 별, 파란 아나모픽 줄, 금빛 후광, 화면 가운데를 지나는 고스트 다섯 개다. 플레어는 0.45초 동안 남았다가 사라진다.
6.25–9 잠금 화면. 카메라가 아주 천천히 다가가고(4.5%), 0.022 rad 돈다. 6.6–9.2초에는 흐린 띠(세기 1.6)가 거꾸로 지나가며 반사를 살려 두고, 7.55초에 「늘」 모서리가 한 번 반짝인다.

포스터(절정): 5.4초다. render.mjs의 기본 시각(0.6 × 9 = 5.4초)과 같으므로 out/poster.jpg가 바로 절정이다. poster.mjs의 AT 표에 넣을 것은 없다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 윤곽 → Shape → ExtrudeGeometry(main.js:102, main.js:123)
  • loadOutlineFont('Pretendard-Black')에서 글자를 가져와, outlineContours로 크기 100, 허용 오차 0.12로 평탄화한다. 그다음 줄 크기(2.2 / 3.8단위)로 줄인다.
  • 구멍 가리기(main.js:113): 면적 절댓값이 가장 큰 윤곽의 부호를 바깥으로 본다. 반대 부호는 구멍이다. 구멍은 첫 점을 품은 바깥 윤곽 가운데 가장 작은 것에 붙인다(inPoly). 「오」「의」의 ㅇ, 「발」의 ㅂ·ㄹ 같은 속공간이 이렇게 뚫린다.
  • 베벨: 깊이 0.56, 두께 0.1, 크기 0.07, 오프셋 −0.025(옆벽이 윤곽보다 0.045만 나온다), 세 마디다. curveSegments: 1로 둔다(윤곽이 이미 평탄화돼 있다).
  • 음절마다 메시 하나다. 줄 묶음이 세로축으로 돌기 때문에 바닥 접점이 흔들리지 않는다.
  • 법선 고치기
  • smoothSides(main.js:162): ExtrudeGeometry는 면마다 평평한 법선을 준다. 옆면·베벨(그룹 1)만 같은 위치의 이웃 면과 평균한다. 단, 두 면의 각도가 40° 안일 때만이다. 둥근 베벨과 곡선은 매끈해지고 모서리는 날카롭게 남는다. 크롬은 법선 오류를 그대로 비추기 때문에 앞면(그룹 0)은 건드리지 않는다.
  • domeCaps(main.js:203): 앞면 법선만 줄의 아래에서 위로 ±0.13 rad 기울인다. 모양은 그대로 두고, 가로축을 둘레로 한 원통처럼 비추게 한다.
    • 26.5단위 떨어진 평평한 면은 스튜디오의 아주 좁은 조각(세로 약 0.07 rad)만 비춘다. 그래서 회색 판처럼 보인다.
    • 기울이면 줄마다 약 0.5 rad를 훑는다. 그래서 하나의 수평 경계(HORIZON = −0.1)가 두 줄을 모두 가로지르는 크롬 선이 된다.
  • 조명 = 그린 스튜디오(main.js:69)
  • 램프는 하나도 없다. 금속(metalness 1)은 환경만 비춘다.
  • 스튜디오는 512×256 half-float 등장방형 텍스처다. 방향 (az, el)마다 값을 계산한다.
    • 카메라 뒤 앞채움: 밝은 '하늘', 수평 경계, 얇은 어두운 틈, 밝은 입술선, 어두운 '바닥'
    • 머리 위 소프트박스(윗베벨)
    • 왼쪽 앞 키 스트립, 오른쪽 뒤 림 스트립
    • 수평선 위 가는 선
    • 앞쪽 바닥의 따뜻한 반사광(금이 아래에서 죽지 않게)
  • 고정 부분은 setup에서 한 번 굽는다(main.js:296). 매 프레임 updateEnv(main.js:473)가 고정 half 배열을 복사하고, 빛 띠가 닿는 텍셀만 다시 계산한다. 그다음 PMREM을 같은 렌더 타깃에 다시 굽는다(main.js:497).
  • 그래서 빛 쓸기는 반사 지도를 돌리는 것이 아니라, 스튜디오 안에서 소프트박스 하나가 실제로 움직이는 것이다. 베벨의 곡면, 앞면, 바닥 반사가 모두 같은 빛을 받는다.
  • PMREM 텍스처는 scene.environment가 아니라 재질마다 envMap으로 건다(main.js:336). r186에서 scene.environment를 쓰면 재질의 envMapIntensity 대신 scene.environmentIntensity를 쓴다. 그러면 처음의 점등과 반사 복사본만 어둡게 하는 일이 되지 않는다.
  • 빛 띠(bands, main.js:460)
  • 띠 좌표는 s = az + 0.16·el(조금 기운 줄무늬)이고, 가우스 폭 w를 준다. 띠는 셋이다.
    • 첫 빛(w 0.07, 세기 7)
    • 쓸기(w 0.024, 세기 20)
    • 잠금 화면의 흐린 띠(세기 1.6)
  • 띠가 앞면 어디에 비치는지는 닫힌 식으로 푼다. sOf(main.js:447)는 눈에서 점으로 간 빛이 +z 면에서 튕긴 방향(Px − Cx, Py − Cy, Cz − Pz)의 s다.
  • 플레어 모서리의 s를 5.4초의 카메라로 계산한다. 쓸기 곡선은 s₀(t) = s_F + 0.32·(2·smooth(p) − 1)로 정해, 5.4초에 정확히 그 모서리를 지나게 했다(main.js:454-458).
  • 같은 식이 모서리 반짝임의 세기(main.js:720)를 정한다. 자막 위 광택 위치(바닥 높이에서 이분법, main.js:762)도 같은 식으로 구한다.
  • 반사 바닥
  • 「발견」의 복사본을 scale(1, −1, 1) 묶음에 넣었다(main.js:341). 줄의 회전을 매 프레임 그대로 베낀다. 음의 행렬식이라 three.js가 감기 방향을 알아서 뒤집는다.
  • 복사본의 꼭짓점 색 = 0.5·(1 − h/2.3)³이다(h = 바닥 위 높이). 금속은 F0 = 바탕색이라, 꼭짓점 색이 반사를 어둡게 한다.
  • 앞면 삼각형은 글자 높이만큼 길어서 색이 선형으로 번진다. 그래서 splitLong(main.js:221, main.js:371)으로 0.2단위보다 긴 변을 가운데에서 쪼갠다. 같은 변은 양쪽에서 같은 점에서 쪼개지므로 틈이 생기지 않는다.
  • 감쇠는 h = 2.3에서 정확히 0이고, 그 위 삼각형은 버린다. HDR 띠(×20)는 1% 색조로도 비쳐 보였기 때문이다.

프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 모든 값은 t의 닫힌 식이다(track, smooth, 감쇠 bump). 직전 프레임의 상태는 쓰지 않는다.
  • 환경 텍스처는 매 프레임 '고정 배열 복사 + 그 시각의 띠'로 처음부터 다시 만든다. 쌓이는 것이 없다.
  • PMREM은 같은 입력에서 같은 출력을 내고, 같은 렌더 타깃을 재사용한다.
  • 난수는 먼지·보케 배치 rand(1111)과 반짝임 모서리 고르기 rand(4242)뿐이다.
  • 캔버스(배경, 바닥 알파, 스프라이트)는 setup에서 한 번만 그린다. 헤드리스에서는 willReadFrequently(CPU 래스터)로 만든다. 블러 필터도 setup에서만 쓴다.
  • 자막 DOM의 스타일(top, transform, clip-path, 그라디언트)은 매 프레임 모두 다시 쓴다. CSS 전환·애니메이션은 없다.
  • 카메라 행렬은 lookAt → rotateZ → updateProjectionMatrix → updateMatrixWorld(true) 순서로 그 자리에서 확정한다. 그래서 투영(플레어 위치)이 직전 시각의 행렬을 읽지 않는다.
  • 결과: 정순 / 새 페이지 역순 / 되돌아가기 6개 시각 모두 byte-identical(maxPixelDiff 0).
한계와 조절할 점
  • 반사는 진짜 거울이 아니다. 뒤집은 복사본이 원래 환경을 그대로 비춘다(거울 속 환경은 위아래가 뒤집혀야 한다). 감쇠가 강해서 눈에 띄지 않지만, 쓸기 띠가 반사 속에서 원본과 같은 쪽으로 움직인다.
  • 돔 법선은 음영 속임수다. 실루엣은 평평한 판 그대로다. 매크로처럼 아주 가까이에서는 앞면의 반사가 살짝 굽어 보인다.
  • 환경 해상도: 512×256 → PMREM 큐브 128이라, 거칠기 0.06–0.09의 가는 반사선은 조금 무르다. 1024×512로 올리면 PMREM 비용이 네 배다(지금 실시간 GPU에서는 여유가 있다).
  • 플레어·반짝임은 화면 공간 스프라이트다. 가려지지 않고 늘 위에 그려진다. 띠 위치 식은 줄이 정면(yaw 0)일 때의 앞면 기준이라, 잠금 이후에만 정확하다(쓸기는 잠금 뒤에만 있다).
  • 바닥 끝의 밝은 띠: 「발견」의 발치 뒤에 보이는 흐린 수평 띠는 멀리서 열리는 바닥 너머로 보이는 배경이다. 스튜디오 사이클로라마처럼 읽히지만 실제 벽은 없다.
