제품·앱 소개로 쓸 때

제품·앱·서비스의 생김새나 기능을 보여 주는 장면에 써요.

  • 실제 제품 사진(배경 제거 PNG)이나 앱 화면 캡처를 함께 주면 그대로 넣어 움직여요.
  • 기능 하나당 2–3초, 한 화면에 한 가지만 보여 주세요.
  • 가격·혜택 같은 숫자는 코드로 넣어야 깨지지 않아요.

자막·카피로 쓸 때

대사·내레이션에 맞춰 핵심 문구를 보여 줄 때 써요. 쇼츠 시청 유지에 가장 직접적인 효과가 있어요.

  • 대본을 단어별 시간과 함께 주면(받아쓰기 결과) 박자가 정확해져요.
  • 강조는 한 문장에 한 단어만. 다 강조하면 아무것도 강조되지 않아요.
  • 화면 아래 15%는 플랫폼 UI에 가려지니 비워 두세요.

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

10초. 부드러운 파스텔 그라디언트 위에 CSS로 그린 일반 휴대폰이 있다(흑연색 테두리, 펀치홀 카메라, 측면 버튼, 상표 없음). 화면 속 앱은 가상의 '쉼표'다. 차분한 하루 관리 앱으로 Pretendard를 쓰고, 둥근 카드와 옅은 그림자, 남색 강조색을 쓴다. 휴대폰 위에는 흰 카드 형태의 스프링 관찰창(SPRING INSPECTOR)이 떠 있다. 아래의 어두운 띠에는 여섯 장(章)의 표시 알약이 있고, 자막이 그 위에 얹힌다.

  1. 알림 낙하 (0.4–1.7 s, k 380 · c 24 · m 1, ζ 0.62) - 알림 세 장이 화면 위에서 차례로 떨어진다. 수면 기록, 3분 호흡, 물 한 잔 순서다. - 새 카드가 앞에 내려앉을 때마다 뒤 카드들이 아래 모서리를 기준으로 작아지며 밀려나, 쌓인 끝이 살짝 보인다.
  2. 토글 (1.9 s, k 700 · c 34 · m 0.6, ζ 0.83) - 손가락 표시가 '방해 금지' 스위치를 누른다. - 가볍고 단단한 스프링으로 손잡이가 건너가며 잠깐 납작해지고, 트랙이 남색으로 물든다.
  3. 완료와 재정렬 (2.9–4.0 s, k 260 · c 26 · m 1.1, ζ 0.77) - '물 2L 마시기'를 체크하면 원이 차오르고 체크 표시가 그려진다. 취소선이 그어지고 '1/4 완료'가 '2/4 완료'로 굴러 바뀐다. - 그 행이 들려 올라(그림자) 아래로 내려가고, 남은 두 행이 한 칸씩 올라온다. 끝낸 일은 아래로 모인다.
  4. 좋아요 (4.2 s, k 600 · c 11 · m 1, ζ 0.22) - 오늘의 문장 카드의 하트가 아주 덜 감쇠된 스프링으로 튀어 오른다. 1.44배까지 갔다가 진동하며 멈춘다. - 고리가 퍼지고 불꽃 여덟 개가 흩어지며, 128이 129로 굴러간다.
  5. 던지기 (5.15–6.2 s, k 140 · c 20 · m 1 · 초기 속도 2380 px/s, ζ 0.85) - 손가락이 맨 앞 알림을 조금 끌다가 놓는다. 놓는 순간의 속도를 가진 스프링이 카드를 회전시키며 화면 밖으로 보낸다. - 뒤 카드들은 한 칸씩 앞으로 나온다.
  6. 바텀 시트 (6.4 s, k 220 · c 17 · m 1.4, ζ 0.48) - 새 맨 앞 카드('3분 호흡')를 누르면 화면 전체가 살짝 물러나 어두워진다. - 무거운 스프링의 시트가 위로 넘쳤다가(약 −32 px) 내려앉는다. 제목, 칩, 숨 구슬, 시작 버튼이 차례로 올라온다. - 여운 (8.2–10 s) - 시트 안의 구슬이 한 번 천천히 숨을 들이쉰다. - 관찰창은 '여섯 가지 스프링, 한 화면'으로 바뀌어 여섯 곡선을 색별로 하나씩 겹쳐 그린다. 띠의 알약 여섯 개가 모두 켜진다.

관찰창이 보여 주는 것: - 지금 동작의 제목, stiffness·damping·mass(던지기는 velocity까지), 감쇠비 ζ = c / (2√(k·m)). - 계단 응답 x(t) 곡선: 0–1.6 s, 점선은 전체 곡선, 굵은 선은 지금까지 지나온 부분. 재생 헤드와 점, t 0.42 s x 1.12 판독값이 함께 나온다. - 왼쪽에는 천장에 매달린 코일과 추가 있다. 추는 같은 x(t)로 출렁여서 물리를 눈으로 보여 준다. - 동작이 바뀌면 곡선이 0.4 s 동안 이전 스프링에서 새 스프링으로 모프되고, 색도 함께 바뀐다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • Motion의 animate와 스프링: 모든 UI 움직임은 Motion.animate(el, keyframes, { type: 'spring', stiffness, damping, mass, velocity }) 또는 { duration, ease, times } 트윈이다.
  • 만들자마자 pause()하고 시작 시각과 함께 목록에 넣는다(main.js:189, go).
  • 여섯 스프링의 매개변수는 SEG 한 곳에 있다(main.js:30). UI 애니메이션과 관찰창 곡선이 같은 값을 쓴다.
  • 수동 시계(main.js:24, :406–407): Motion은 보통 opacity·transform을 WAAPI에 넘기고 나머지는 rAF 프레임 루프에서 그린다.
  • 숫자 탐침으로 확인한 결과(이미지 없음)는 이렇다.
    • WAAPI로 가는 값(opacity, transform 문자열)은 멈춘 컨트롤에 time을 넣자마자 정확히 그 자리에 간다.
    • 독립 변환(x, y, scale → WAAPI 묶음 변환), SVG, 객체 값은 다음 rAF에야 바뀐다.
  • 그래서 MotionGlobalConfig.useManualTiming = true를 애니메이션을 만들기 전에 켠다. 그러면 모든 애니메이션이 JS로 돈다.
  • frame(t)는 모든 컨트롤에 time = t − 시작을 넣고 Motion.processFrame(ts)를 부른다. 이 함수가 Motion의 update·render 단계를 그 자리에서 돌린다(motion-dom/.../frameloop/process-frame.mjs).
  • 멈춘 JSAnimation은 holdTime만 보고 값을 낸다(JSAnimation.tick). 그래서 같은 t는 늘 같은 값이고, 0.82726 = 스프링 생성기의 0.8273 × 100으로 정확히 일치한다.
  • 값 하나에 animate 하나, 움직임마다 래퍼 하나
  • Motion에서 같은 요소의 같은 값에 animate를 두 번 걸면 두 번째가 첫 번째를 멈춘다(MotionValue.start).
  • 그래서 여러 번 움직이는 카드는 래퍼를 겹친다: drop > push1 > push2 > prom > drag > throw(main.js:68).
  • 밀려나기와 앞으로 나오기는 같은 원점(아래 가운데)의 축소·이동이다. 앞으로 나오기는 밀려나기를 정확히 되돌리게 계산한다(main.js:210, :269). 안쪽 래퍼의 이동은 바깥 배율로 나눈다.
  • 같은 요소라도 속성이 다르면 animate를 따로 건다. 예를 들어 던지는 카드의 x(속도 2380 px/s)와 회전(속도 60 °/s), 불꽃의 위치와 불투명도가 그렇다.
  • 스프링을 가진 동작들
  • 낙하 main.js:211, 토글 :222, 재정렬 :238, 하트 :247, 던지기 :265, 시트 :279.
  • 화면 물러남은 :278. 체크 표시는 SVG pathLength이고(:231), 숨쉬기는 트윈이다(:282).
  • 3개 키프레임과 times로 '0 → 최고 → 0' 모양을 만든다(고리, 불꽃, 들어 올림 그림자).
  • 관찰창 곡선(main.js:297–302): Motion.spring({ keyframes: [0, 1], stiffness, damping, mass, velocity }) 생성기를 10 ms마다 161번 표본화한다(restDelta를 아주 작게 해서 곡선 끝이 잘리지 않게 한다).
  • UI 애니메이션과 같은 해석해다. 감쇠 진동 x(t) = 1 − e^(−ζω₀t)(A sin ω_d t + cos ω_d t).
  • 던지기의 초기 속도는 0→1 단위로 정규화한 2380/700 = 3.4 /s다.
  • inspect(main.js:354)가 t에서 곡선, 재생 헤드, 점, 판독값, 코일·추, 장 표시를 다시 그린다. 곡선 사이 모프는 표본별 보간이고(main.js:358), 색은 Motion.mix로 섞는다.

  • motion.dev 문서: animate, spring options(stiffness/damping/mass/velocity), MotionGlobalConfig.useManualTiming + processFrame
  • 감쇠 조화 진동자 m·x″ + c·x′ + k·x = k(목표), ζ = c / (2√(km)), ω₀ = √(k/m)

한계와 조절할 점
  • 여섯 스프링의 값과 장 전환 시각은 SEG(main.js:30)에 있다. at은 관찰창이 바뀌는 시각, t0은 재생 헤드 0이다. 바꾸면 UI 애니메이션과 곡선이 함께 바뀐다.
  • 요약 시작 SUMMARY_AT(main.js:38). 던지기 거리와 속도는 FLICK, FLICK_V(main.js:39).
  • 쌓임의 깊이(배율·간격)는 S1, S2, T1, T2(main.js:210), 앞으로 나오는 스프링은 P(main.js:268).
  • 시트 뒤 화면이 물러나는 정도는 main.js:278, 숨 한 번은 main.js:282.
  • 관찰창
  • 곡선 영역과 값 범위는 PX0…VMAX(main.js:46). 덜 감쇠된 스프링이 1.55를 넘으면 위로 잘리므로 VMAX를 올린다.
  • 곡선 모프 시간 0.4(main.js:358), 요약 곡선 간격 0.08(main.js:380).
  • 코일 길이와 추 이동 46 + 60·x(main.js:386).
  • 한계
  • 수동 시계를 켜면 Motion의 WAAPI 가속(합성 스레드에서 도는 opacity/transform)은 쓰지 않는다. 결정적 seek를 위해 바꾼 것이다. 실시간 재생에서는 애니메이션 75개를 JS로 매 프레임 계산한다(작은 비용).
  • 탐침상 WAAPI 경로만으로도 opacity와 transform 문자열은 정확히 seek되지만, x/y/scale 같은 독립 변환은 rAF 한 번이 늦다. 이 장면은 독립 변환을 많이 쓰므로 섞어 쓰지 않았다.
  • 손가락 표시는 장식이다. 실제 포인터 입력이나 드래그 물리(inertia)는 쓰지 않는다. 던지기의 끌기 구간은 트윈이고, 놓은 뒤만 스프링이다.
  • 앱, 문구, 휴대폰 모양은 모두 가상이고 일반적인 것이다. 상표는 없다.
