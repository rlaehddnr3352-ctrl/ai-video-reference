#087 · 영상 표현력

밤 숲의 한 사람

센서 시점 · 스칼라장 + 거짓 색 + 스캔 전환

장면 전환배경·분위기가벼움 · 브라우저 기능만
광고 · 쇼츠에서는열화상 · 센서 시점으로 바뀌는 연출 (보안 · 테크)

활용 가이드

장면 전환로 쓸 때

장면 A에서 B로 넘어가는 0.3–1초 구간에 써요. 컷 사이 이탈을 줄여요.

  • 전환 하나를 영상 전체에 반복해 쓰면 통일감이 생겨요. 매번 다른 전환은 산만해요.
  • 앞 장면의 마지막 프레임과 다음 장면의 첫 프레임을 같이 알려 주세요.
  • 실사 영상 사이에 넣을 땐 투명 배경(알파) 영상이나 두 영상을 직접 합치는 방식으로 요청해요.

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

밤 #070b18 바탕이다. 강조색은 지금 켜진 채널의 색 하나만 쓴다: 달빛 #bcd0ff, 열 #ff9a4a, 소리 #7fe7ff, 고정 #ffcf5a. 글꼴은 Pretendard(제목·한글 라벨·숫자)와 JetBrains Mono(라틴 HUD 문자·숫자 판독값) 둘이다. HUD는 화면 내내 같다. 네 귀퉁이의 뷰파인더 괄호, 위쪽 막대(REC SAR-07, 실종자 수색, 고도·시각), 채널 칩 1 가시광 · 2 열 · 3 소리, 방위 눈금, 오른쪽의 컬러맵 범례, 왼쪽 아래의 후보 개수와 상태 줄이다.

시간 채널 보이는 것
0–0.6 — 가운데 밝은 가로선에서 화면이 위아래로 열리고(센서 부팅), 뷰파인더 괄호와 HUD가 스프링으로 들어온다.
0.4–1.75 CH1 가시광 달빛만 있는 숲이다. 둥근 수관(활엽·침엽), 텐트 네 동, 모닥불과 연기, 냇물의 달빛 반짝임이 보이고, 구름 그림자가 지나간다. 조준 괄호는 "탐색 중"으로 빈 곳을 헤맨다. 제목은 안 보인다, 부제는 "달빛뿐인 밤 숲".
1.75–2.55 스캔 → 열 주황 스캔 띠가 위에서 아래로 훑는다. 띠가 지나간 위쪽부터 열 지도가 드러나고, 가장자리 바로 뒤 줄들은 RGB가 갈라지며 흔들린다. 띠가 텐트·사슴·사람을 지나는 순간 그 위에 작은 괄호가 차례로 붙고 A 34.8° 같은 판독값이 뜬다.
2.55–4.3 CH2 열 텐트 셋 안의 사람들, 사슴 둘, 냇가의 한 사람이 모두 주황으로 빛난다(빈 텐트 하나는 차갑다). 모닥불은 흰색이고, 그 연기는 보라색 열기둥이 되어 텐트 사이로 피어오른다. 후보 수가 0→6으로 오르고, 조준 괄호는 A → D → F → B를 오가며 "판별 중"이다. 제목은 다 따뜻하다.
4.3–5.1 스캔 → 소리 청록 띠가 훑고 지나간다. 소리 지도는 거의 검다. 수관 위의 바람 소리, 냇물의 쉬 소리 띠, 모닥불이 탁탁 튀는 작은 파문만 있다.
4.85–5.6 CH3 소리 냇가의 F 한 점에서만 호루라기 파동이 동심원 묶음으로 퍼진다. 나머지 후보는 무음으로 바뀌며 차례로 떨어지고, 후보 수가 6→1로 줄어든다. 제목은 들린다.
5.62–6.3 절정 넓게 듣던 조준 괄호가 회전하며 F에 스프링으로 고정된다("신호 고정", 금색). 플래시, 펀치 줌, 감쇠 흔들림이 있고, 금색 링 두 개와 불티가 퍼진다. F의 열이 소리 지도 위에 겹쳐 주황 핵으로 떠오른다(두 채널이 일치하는 단 한 곳). 제목은 찾았다(팝 + 빛 스침), 거리·방위 숫자는 해독되듯 찍힌다.
6.2–9 여운 카메라가 F 쪽으로 밀어 들어간다. 호루라기 파동은 계속 몇 묶음 더 나온다.
7.5–8.3 스캔 → 가시광 흰 달빛 띠가 지나가며 다시 첫 장면의 어두운 숲이 드러난다.
8.05–10 CH1 + 조명 드론 탐조등이 깜빡이며 켜진다. 빛 웅덩이 안만 실제 색(풀밭, 주황 재킷, 배낭, 흙길)으로 보이고, 실종자가 팔을 흔든다. 부제는 "구조대에 위치를 보낸다", 오른쪽 아래 위치 전송 진행 막대가 채워진 뒤 "완료"와 체크 표시가 뜬다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 같은 장소, 세 가지 표현. setup에서 지도 기하(공터, 냇물·오솔길 Catmull-Rom 스플라인, 나무 수백 그루 배치)를 한 번 만든다(main.js:710-745). 그것을 세 장으로 굽는다(main.js:747-751).
  • 밤 팔레트 NIGHT, 탐조등 아래 실제 색 LIT(main.js:167-187), 센서용 외곽선(paintOutline, main.js:342).
  • 같은 paintWorld(main.js:263)가 팔레트만 바꿔 그리므로 세 장의 형태가 픽셀 단위로 맞는다.
  • 사슴과 사람은 움직이므로 매 프레임 그린다(main.js:365, main.js:391).
  • 스칼라장 = t의 순수 함수. 월드 1340×2140을 3px 칸(447×714)으로 나눈 격자에 매 프레임 값을 처음부터 계산한다.
  • 정적인 부분은 setup에서 마스크로 굽는다. 수관·냇물·공터·바위·텐트를 격자 해상도 캔버스에 그리고 알파를 읽는다(main.js:753-770). 그 값으로 바탕 온도·바탕 소리를 만든다(main.js:776).
  • 열(computeHeat, main.js:468): 바탕 + 텐트 속 사람(천을 통과해 퍼진 넓은 가우시안) + 사람 + 사슴(가우시안 paint: 목표 온도까지만 칠해서 겹쳐도 넘치지 않음, main.js:424) + 모닥불 핵(가산 가우시안)과 불꽃(노이즈로 흔들리는 고리) + 연기 기둥.
  • 연기 기둥 = 이류(advection)된 노이즈(computePlume, main.js:448). 바람 축을 따른 거리 s와 수직 거리 c로 가우시안 기둥을 만든다. 폭은 s에 비례해 넓어지고, 축은 사인으로 굽이친다. 밀도는 p − v·t에서 샘플한 도메인 왜곡 값 노이즈로 곱한다. 무늬가 바람을 타고 흘러가지만 상태는 쌓이지 않는다. 같은 버퍼를 가시광의 연기(회색 알파)로도 쓴다(main.js:539).
  • 소리(computeSound, main.js:489): 수관 위 바람(느린 노이즈), 냇물 쉬 소리(빠른 노이즈 × 냇물 근처 마스크), 모닥불 탁탁 소리(짧은 펄스 링). 호루라기는 지연 시간(retarded time) 파동이다(main.js:511). field(r,t) = W(t − r/c) · (½ + ½cos(k(r − ct)))² · 감쇠(r). W는 호루라기 세기 곡선(BLASTS, main.js:66)을 1ms 간격 표로 구운 것이다. 그래서 짧게 두 번, 길게 한 번 분 소리가 각각 고리 묶음이 되어 바깥으로 나간다.
  • 거짓 색(컬러맵 LUT). makeLUT(main.js:146)이 색 정지점을 256칸 표(ABGR로 묶은 Uint32)로 만든다.
  • 열은 아이언보(검정 → 남보라 → 자홍 → 주황 → 노랑 → 흰색, main.js:160), 소리는 청록 단색 램프(main.js:162)다.
  • mapLUT(main.js:531)는 칸마다 표를 한 번 찾아 Uint32Array에 쓴다. 2×2 순서 디더를 넣어, 3배로 늘려도 램프에 띠가 지지 않는다.
  • 결과를 putImageData로 격자 캔버스에 올리고, 카메라 행렬로 늘려 그린 뒤 외곽선을 screen으로 얹는다(renderChannel, main.js:878). 범례 막대도 같은 정지점을 쓴다.
  • 스캔 띠 전환(frame, main.js:829-840).
  • 띠 가장자리 y는 inOutQuad로 0.8초 동안 화면 위에서 아래로 간다(main.js:569).
  • 옛 채널을 전부 그리고, 가장자리 위쪽만 클립해 새 채널을 같은 캔버스에 덧그린다.
  • 가장자리 바로 뒤 150px은 chroma(main.js:975)가 처리한다. 픽셀을 읽어 R은 한쪽, G·B는 반대쪽으로 정수 칸만큼 밀고, 10px 줄 묶음마다 해시로 흔든다. 둘 다 가장자리에 가까울수록 커진다.
  • 그 위에 band(main.js:990)를 그린다. 채널 색 그라디언트 띠, 스캔라인 패턴, 글로우가 있는 흰 가장자리, 눈금, 띠를 타고 가는 CH2 열 라벨이다.
  • 채널에 따라 바뀌는 HUD(칩, 범례, 괄호·판독값 색)도 splitDraw/chY(main.js:576-588)로 띠 가장자리에서 함께 바뀐다.
  • 괄호와 스프링.
  • spring(τ)(main.js:89)은 감쇠 진동의 닫힌 해다(1 − e^(−ζωτ)(cos ω_dτ + ζω/ω_d sin ω_dτ)).
  • 후보 괄호는 띠가 자기 화면 행을 지나는 시각(passTime을 setup에서 역산, main.js:821)에 1.7배 크기에서 스프링으로 붙는다(main.js:1102).
  • 조준 괄호는 hop 목록 RET(main.js:597)을 inOutCubic으로 오간다. 고정 순간에는 위치(ζ 0.6)와 크기(ζ 0.48)에 서로 다른 스프링을 쓰고, 크기가 목표보다 작아지는 쪽 반동은 35%로 줄인다. 그래서 괄호가 목표 위로 쪼그라들지 않고, 회전하며 딱 맞물린다(main.js:622).
  • 임팩트는 세 박자에만 둔다. 스캔 세 번(띠 자체), 고정(플래시 0.26, 펀치 4.5%, 감쇠 흔들림, 금색 링 둘, 불티 26개, main.js:1137), 탐조등 점등(따뜻한 플래시 + 링)이다. 모든 위치는 t − t0의 닫힌 식이다.
  • 가시광의 깊이. 레이어는 구운 지도 → 구름 그림자(곱하기 대신 어두운 방사 그라디언트) → 사슴·사람 → 연기 → 모닥불 빛·불티(가산) → 냇물 반짝임 순이다. 화면 위에는 스캔라인, 위아래 스크림, 비네트, 필름 그레인(초당 12번 자리 바뀜)을 얹는다.
  • 탐조등(main.js:945): 실제 색 지도를 같은 카메라로 작은 캔버스에 그리고, 방사 그라디언트로 destination-in 마스크해 얹는다.
  • 글자. 제목은 음절마다 줄 마스크 안에서 expo.out으로 올라오고 더 빨리 위로 빠진다. "찾았다"만 음절별 스프링 팝을 쓰고, 오프스크린에 그린 글자 위로 source-in 빛 띠를 지나가게 한다(heroText, main.js:1173). 거리·방위 숫자는 decode(main.js:656)로 t에 따라 해독된다.
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 무거운 일은 전부 setup에서 rand(seed)로 한다. 지도 기하, 나무 배치(rand(1201)), 세 장의 굽기, 필드 마스크, 노이즈 순열표, 호루라기 세기표, 그레인 타일이다.
  • frame(t)는 필드 버퍼를 바탕값으로 덮어쓴 뒤(heat.set(heatBase)) 다시 더한다. 연기 버퍼는 사각 범위 전체를 매번 다시 쓴다. 이전 프레임의 값이 남지 않는다.
  • 움직임은 모두 t의 닫힌 식이다. 노이즈는 p − v·t에서 샘플하고, 파동은 지연 시간을 쓰고, 스프링은 해석해다. 깜빡임·판독값 흔들림·해독 숫자는 hash(floor(t·f))다.
  • 2D 컨텍스트 상태(lineCap, 그림자, 대시, 정렬 등)는 프레임 사이에 남는다. 그래서 그리기 단계마다 resetCtx(main.js:873)로 같은 상태에서 시작한다. 처음 렌더에서는 이것이 빠져 선 끝 모양이 앞 프레임에 따라 달라졌다.
  • 오프스크린 캔버스 주의(이번에 찾은 것).
  • 처음에는 새 채널을 화면 크기 오프스크린에 그려 복사했다. 그런데 그 캔버스에 외곽선 이미지를 screen으로 처음 그릴 때와 두 번째 그릴 때 결과가 ±2/255 달랐다(헤드리스 CPU 래스터). 그 탓에 jump-back 검사에서 실패했다.
  • 필드 값 자체는 같았다(버퍼를 직접 비교해 확인함). 차이는 합성 단계에서 생겼다.
  • 그래서 오프스크린을 없앴다. 새 채널은 같은 캔버스에 클립으로 그리고, RGB 분리는 getImageData → 정수 이동 → putImageData로 바꿨다. 픽셀 연산이라 정확하다.
  • 렌더러 검사(정순·역순 새 페이지·되돌아가기): pass, 최대 차이 2/255(허용 4 이내).
한계와 조절할 점
  • 필드 해상도: 1/3 격자를 쌍선형으로 늘린다. 마지막 밀기(1.36배)에서 소리 고리가 조금 무르다. 고리만 1/2 격자로 따로 계산하거나 WebGL2 셰이더로 옮기면 선명해진다(67번 이후 규칙상 직접 셰이더는 쓰지 않았다).
  • 실시간 비용: 스캔 중 프레임은 두 필드를 다 계산하고, getImageData로 150줄을 읽는다. GPU 캔버스에서는 이것이 동기 읽기(readback)라 약한 기기에서는 30 ms 예산이 빠듯할 수 있다. 수관 바람 노이즈를 setup에서 타일로 구워 두면 소리 계산이 절반쯤 줄어든다.
  • 물리성: 소리는 장애물(나무)에 막히거나 반사되지 않는 자유 공간 파동이다. 열은 그림자·방사율 없이 가우시안을 합한 것이다. 시각적 설득력만 노렸다.
  • 그림: 텐트는 같은 돔 모양에 색만 바뀐다. 사슴은 위에서 본 단순 타원이다. 가시광에서 실종자가 아주 희미하게 보이는데, 의도한 "안 보인다"보다 조금 밝을 수 있다(NIGHT.jacket 등으로 조절).
  • 오프스크린 함정: 위 결정성 전략에 적은 "오프스크린 캔버스에 처음 그린 합성과 두 번째 합성이 다르다" 현상은 README 규칙 후보다. 원인은 Chrome 내부(Skia 이미지 캐시로 추정)라 정확히 짚지 못했다.
