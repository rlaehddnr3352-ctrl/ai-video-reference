활용 가이드

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

자막·카피로 쓸 때

대사·내레이션에 맞춰 핵심 문구를 보여 줄 때 써요. 쇼츠 시청 유지에 가장 직접적인 효과가 있어요.

  • 대본을 단어별 시간과 함께 주면(받아쓰기 결과) 박자가 정확해져요.
  • 강조는 한 문장에 한 단어만. 다 강조하면 아무것도 강조되지 않아요.
  • 화면 아래 15%는 플랫폼 UI에 가려지니 비워 두세요.

영상에 옮길 때 주의

  • 손으로 쓴 WebGL2 셰이더 — 영상 스킬의 WebGL 층(three.js 등) 위에서 다시 쓴다
  • 소리 — 소리를 쓸지는 영상 스킬의 규칙을 따른다. 소리에 그림을 맞추는 방식을 참고한다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

9.6초짜리 짧은 곡(D장조 5음 음계)에 맞춰 밤하늘 같은 어둠 한가운데에서 빛의 꽃이 핀다.

  • 도입(0–2.3 s): 종소리 세 번(A5, F♯5, D6)이 울린다. 소리마다 꽃잎 하나가 그 음의 방향으로 쑥 자라고, 끝에서 물결 고리가 퍼지며 불꽃이 튄다. 가운데의 '소리의 근원'에서는 동심원 파면이 계속 흘러나온다.
  • 전개(2.3–5.3 s): 낮은 심장 박동(펄스)이 0.6초마다 분홍빛 충격 고리를 내보내고, 파면의 아래쪽(저음)이 박동에 맞춰 부푼다. 뜯는 소리(pluck) 멜로디가 꽃잎을 하나씩 보탠다. 같은 음이 다시 나오면 꽃잎이 부채꼴로 겹친다.
  • 절정(5.3–6.9 s): 노이즈 시머가 차오르며 파면 위쪽(고음)이 밝아지고, 5.3 s에 종 화음이 한꺼번에 여러 꽃잎을 피운다. 이어지는 상행 아르페지오(0.15초 간격)가 다섯 방향을 차례로 돌며 꽃잎을 나선처럼 붙인다.
  • 여운(7.45 s–): 낮은 D4 종이 위쪽(으뜸음 D 방향)으로 짧고 굵은 꽃잎을 남긴다. 펄스가 멎고 잔향이 줄면서 파면이 잦아든다. 꽃잎들은 희미한 윤곽으로 남는다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 합성(synth.js, OfflineAudioContext 48 kHz 스테레오)
  • 뜯는 소리(synth.js:70): 삼각파와 3/1000 높은 톱니파를 섞는다. 차단 주파수가 내려가는 로우패스를 거치고, setTargetAtTime으로 지수 감쇠한다.
  • 종(synth.js:89): 비조화 부분음 5개(1, 2, 2.76, 5.4, 8.93배)를 가산 합성한다. 부분음마다 감쇠 시간이 다르다.
  • 펄스(synth.js:106): 120 → 52 Hz로 떨어지는 사인 + D2 몸통. 패드(D3+A3 삼각파)와 대역 통과 노이즈 시머(synth.js:128, 145)도 있다.
  • 컨볼루션 리버브(synth.js:12, 52): 임펄스 응답을 직접 만든다. 지수 감쇠 노이즈에 시간이 갈수록 어두워지는 1극 로우패스를 걸고, 채널별 초기 반사 6개를 더한 뒤 에너지를 1로 정규화한다. normalize=false, 습 0.34. 마스터는 tanh WaveShaper로 부드럽게 포화시킨다.
  • 악보는 score.js에 있다. 화면 쪽은 악보를 보지 않는다.
  • 분석(analysis.js, 순수 JS, 우리가 짠 FFT)
  • 반복형 radix-2 FFT(analysis.js:16). 분석 프레임은 초당 120개, 2048점 Hann 창이다.
  • 밴드 레벨(analysis.js:70): 50 Hz–12 kHz를 로그 간격 64밴드로 나눠 평균 파워의 dB를 구한다. 빈보다 좁은 저역 밴드는 중심 주파수에서 보간한다. 전체 최대값 기준 60 dB 범위를 0..1로 정규화하고(analysis.js:96), 스펙트럼 분석기처럼 즉시 오르고 0.5초에 걸쳐 내려가는 탄도를 준다. RMS와 저역(30–180 Hz) 레벨도 같은 방식이다.
  • 온셋(analysis.js:86, 108): 로그 압축 크기의 양의 변화(spectral flux)를 고역(280 Hz–9 kHz)과 저역에서 따로 구한다. 국소 평균 × 1.4 + 바닥값을 적응 임계값으로 쓰고, ±3프레임 국소 최대만 온셋으로 친다. 최소 간격은 고역 70 ms, 저역 200 ms다. 저역 온셋은 펄스로, 고역 온셋은 음으로 쓴다.
  • 온셋마다 새로 생긴 음높이(analysis.js:129): 온셋 20 ms 뒤 4096점 창의 크기에서 바로 앞 창의 크기를 빼서 '새로 생긴' 에너지를 본다. 그래서 아직 울리고 있는 앞 음은 빠진다. 다음 순서로 거른다.
    1. 사후 스펙트럼의 피크를 포물선 보간한다.
    2. 이미 있는 낮은 피크의 2–4배면 배음으로 보고 버린다(analysis.js:151).
    3. 평균율에서 ±35 cent 안이면서 음계 안의 음만 남긴다. 화음은 최대 4음까지 받되, 두 번째 음부터는 그 빈의 에너지가 1.8배 이상 커져야 한다. - 같은 음을 다시 칠 때 울리던 소리와 위상이 상쇄되는 경우에 대비해, 종은 7 cent 높게 조율했다(실제 종처럼).
  • Node에서 악보를 대략 다시 합성해 이 분석을 돌려 보았다. 온셋 시각 오차는 한 홉(8 ms) 이내였고, 음높이는 거의 모두 맞았다.
  • 그림(main.js, WebGL2): 화면은 분석표만 t로 읽는다.
  • 밴드표를 64 × 1153 R16F 텍스처로 올린다(main.js:342). 셰이더는 아무 밴드, 아무 시각이나 선형 보간해 읽는다.
  • 극좌표 스펙트로그램(main.js:89): 파면이 0.1초마다 반지름 118 px에서 태어나 160 px/s로 퍼진다. 파면 하나의 모양(반지름 변위)과 밝기는 태어난 시각의 스펙트럼이다. 각도는 아래가 저음, 위가 고음이고 좌우 대칭이다. 그래서 반지름이 곧 시간축이고, 방금 지난 2.6초의 소리가 동심원 판화처럼 남는다. 픽셀마다 근처 파면 5개만 계산한다.
  • 근원(main.js:111): 지금 스펙트럼의 닫힌 윤곽과, 저역 레벨로 숨 쉬는 뜨거운 중심.
  • 펄스 고리(main.js:120): 저역 온셋마다 하나씩.
  • 꽃잎(main.js:132): 감지된 음 하나에 하나다.
    • 방향 = 음계 도수(D 위, E·F♯·A·B가 72° 간격), 길이 = 음높이, 모양 = iq의 정확한 vesica SDF(main.js:53).
    • 밝기 = 그 음의 밴드의 현재 레벨³(main.js:156). 음이 잦아들면 꽃잎도 함께 잦아든다. 여기에 오래 남는 잔광과 온셋 섬광을 더한다.
    • 꽃잎 끝에서 물결 고리가 퍼진다.
  • 불꽃(main.js:394): 음마다 30개를 점 스프라이트로 그린다. 위치는 항력 비행 + 떠오름을 닫힌 식으로 계산한다.
  • HDR(RGBA16F) → 1/4·1/8 블룸 → 지수 톤매핑, 비네트, 그레인.
  • 실시간 소리(main.js:227)
  • 플레이어가 onTransport({ playing, t })를 부르면(재생, 정지, 재생 중 이동, 반복) 기존 AudioBufferSourceNode를 멈춘다. 재생 중이면 새 소스를 start(0, t + 경과 + 출력 지연)으로 시작한다. 시작 위치에 출력 지연(baseLatency + outputLatency)을 더해서 소리가 화면과 같은 순간에 들리게 했다.
  • AudioContext는 첫 사용자 입력(클릭이나 키) 때 만들고 resume한다.
  • 화면을 처음 클릭하면 소리만 켜고 플레이어는 멈추지 않는다(main.js:257, 캡처 단계에서 그 클릭 하나만 전파를 막는다). 아래 막대의 버튼은 평소대로 동작한다.
  • 소리가 날 때까지 위쪽에 "클릭하면 소리가 나요" 알약을 띄운다. 헤드리스 렌더(?render)에서는 만들지 않는다.
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 소리는 setup에서 한 번만 합성한다. 무작위는 시드 난수(rand(2929))뿐이고(노이즈, 임펄스 응답), OfflineAudioContext 렌더는 같은 브라우저에서 늘 같다. 분석도 순수 함수라서 표가 매번 같다.
  • frame(t)는 표를 t에서 읽는 순수 함수다. 꽃잎과 고리는 '온셋 시각 대비 나이'로, 불꽃은 음마다 고정된 난수와 나이의 닫힌 식으로 정해진다. 상태가 없어서 replay가 필요 없다.
  • 실시간 소리는 화면과 따로 돈다. 플레이어의 전송 이벤트로만 맞추고, 그림에는 영향을 주지 않는다.
한계와 조절할 점
  • 실제 Web Audio 렌더 결과로 분석표를 눈으로 확인하지는 못했다. Node에서 근사 합성으로 확인한 결과, 같은 음을 다시 치는 경우의 일부 오검출(옆 도수로 감지)이 남을 수 있다. 그래도 꽃잎이 다른 방향에 하나 더 생기는 정도라서 그림이 깨지지는 않는다.
  • 첫 클릭으로 소리를 켤 때 플레이어 정지를 막는 것은 이 데모만의 처리다. 공통 플레이어에 '소리 켜기' 버튼이 생기면 그쪽으로 옮기는 편이 낫다.
  • 다음 단계: 크로마그램이나 HPS로 화음 검출 개선, 스테레오 위치(좌우 레벨 차)로 꽃잎 기울이기, 박자 추적으로 파면 속도 동기화.
