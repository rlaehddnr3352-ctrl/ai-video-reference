#127 · 영상 표현력

정리 전, 정리 후

비교 장면 · 한 장면의 두 상태 + 와이프 슬라이더 + 분할 화면

제품·앱 소개장면 전환가벼움 · 브라우저 기능만
광고 · 쇼츠에서는사용 전후 비교 슬라이더 · 분할 화면

활용 가이드

제품·앱 소개로 쓸 때

제품·앱·서비스의 생김새나 기능을 보여 주는 장면에 써요.

  • 실제 제품 사진(배경 제거 PNG)이나 앱 화면 캡처를 함께 주면 그대로 넣어 움직여요.
  • 기능 하나당 2–3초, 한 화면에 한 가지만 보여 주세요.
  • 가격·혜택 같은 숫자는 코드로 넣어야 깨지지 않아요.

장면 전환로 쓸 때

장면 A에서 B로 넘어가는 0.3–1초 구간에 써요. 컷 사이 이탈을 줄여요.

  • 전환 하나를 영상 전체에 반복해 쓰면 통일감이 생겨요. 매번 다른 전환은 산만해요.
  • 앞 장면의 마지막 프레임과 다음 장면의 첫 프레임을 같이 알려 주세요.
  • 실사 영상 사이에 넣을 땐 투명 배경(알파) 영상이나 두 영상을 직접 합치는 방식으로 요청해요.

사전 카드와 함께 쓰기

T17 비포 · 애프터 카드와 같은 기법이에요. 카드의 예시 영상과 주문서 기능을 같이 써 보세요.

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

어둡고 어질러진 원룸이 정리된 방으로 바뀌고, 와이프 슬라이더와 위아래 분할 화면이 달라진 곳 여덟 군데를 같은 번호의 손그림 고리로 짚는다.

미감은 따뜻한 베이지·회색 평면 일러스트다. 색 토큰은 벽·바닥·나무·크라프트 같은 따뜻한 중간색과 먹색(#2C2A31)이고, 강조색은 민트(#34C49C) 하나다. 민트는 "정리됨"의 표시로만 쓴다. 슬라이더 손잡이, 표시 고리, 도장이 민트이고, 방 안에서는 B 상태의 커튼 끈, 선 정리 밴드, 시계 초침만 민트다. A 상태는 커튼이 닫혀 차갑고 어둡다(곱하기 합성의 회색 막과 비네트). B 상태는 커튼이 열려 창 모양 그대로 햇빛이 바닥에 떨어진다. 깊이는 세 겹이다. 원경은 벽·창밖 지붕·액자·시계, 중경은 침대·책상·의자·선반, 전경은 바닥의 상자·책 더미·종이 뭉치다.

시간 무엇이 보이나
0–1.5 어질러진 방이 쌓인다. 카메라가 1.075배에서 1배로 물러나는 동안 바닥과 의자의 물건이 뒤쪽부터 차례로 떨어져 튀며 자리 잡는다(0.1–1.05초, 간격은 그리는 순서). 왼쪽 위에 「토요일 오전 10시 · 원룸」과 큰 제목 「정리 전」이 줄 마스크에서 올라오고, 1.42초부터 위로 빠지며 흐려진다.
1.46–4.0 와이프 슬라이더. 둥근 손잡이가 오른쪽 가장자리에서 튀어 들어오고, 세로선이 손잡이에서 위아래로 자란다. 1.72초에 손잡이가 눌리고 손이 끌기 시작한다. 왼쪽 166 px까지 쓸며 정리 후를 드러내고, 튕겨 넘쳤다가 돌아온다. 가운데를 지나 780 px까지 갔다가 380 px로 한 번 더 문지르고 540 px에 선다. 「정리 전」(먹색)과 「정리 후」(민트) 칩이 선의 양쪽에 붙어 따라다니고, 자기 쪽 영역에서만 보인다.
4.1–4.62 선이 90° 돈다. 손잡이를 축으로 세로선이 가로선이 된다. 왼쪽/오른쪽이 위(전)/아래(후)가 되고, 손잡이의 화살표도 함께 돌아 위아래를 가리킨다. 두 칩은 각 창의 왼쪽 위 모서리로 날아간다.
4.62–5.12 분할 화면. 두 반쪽이 둥근 모서리 창 두 개로 줄어들고, 사이로 먹색 바탕이 드러난다. 두 창의 카메라는 같은 크롭(달라진 곳 전체)으로 물러난다. 손잡이는 가운데 틈에서 「달라진 곳 8」 알약으로 펴진다.
4.98–6.0 차이 표시(절정). 위쪽에 카운터 세 장이 내려온다: 바닥의 물건 23 → 2, 흩어진 컵 5 → 1, 널린 옷 7 → 0. 오른쪽 숫자가 23에서 2로 굴러 내려간다. 5.1초부터 0.084초 간격으로 1번부터 8번까지 하나씩 표시가 나온다. 물건의 실루엣을 감싼 손그림 고리가 펜으로 그리듯 한 바퀴 돌고(끝이 시작점을 살짝 지나침) 안쪽이 옅은 민트로 물들며, 번호 배지가 튄다. 같은 번호는 위 창과 아래 창에서 같은 순간에 나온다. 6.0초에 여덟 개가 모두 자리 잡는다.
6.0–7.2 정지에 가까운 읽기 시간이다. 먼지, 화분 잎, 커튼 밑단, 의자에 걸린 후드 소매, 시계 초침, 천장 조명이 두 창에서 똑같이 움직인다.
7.2–8.18 표시와 카운터가 빠르게 빠진다(0.2초). 아래 창이 전체 화면으로 열리며 위 창을 화면 위로 밀어낸다(위 창의 아랫변이 아래 창의 윗변을 따라간다). 알약은 다시 손잡이가 되어 곡선을 그리며 오른쪽 위로 날아간다.
8.02–10 정리 끝. 「토요일 오후 1시 · 같은 방」과 「정리 후」가 올라오고 민트 밑줄이 그어진다. 8.3초에 손잡이가 도장 「정리 끝」으로 커지며 찍힌다(1.45배에서 눌림, 충격 고리, 짧은 빛살 8개, 카메라 0.012 펀치). 햇빛이 짙어지고(빛 세기 1 → 1.6) 창가에 번짐과 빛줄기가 생기며, 카메라가 4% 천천히 다가간다.

포스터(절정) 시각은 렌더러 기본값인 6.0초다. 카운터 세 장, 두 창, 위아래 여덟 쌍의 번호 고리가 모두 다 그려진 화면이다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 장면 설명 하나, 상태 둘 (main.js:677 add, main.js:682 buildScene)
  • 물건 하나는 { id, kind, group, A, B, …고정 값 }이다. 상태는 { x, y, s, r, vis, z, surface, shape }이고, B를 생략하면 A와 같다(바뀌지 않은 가구).
  • kind마다 draw(g, st, t, E, it)와 box(st, it)가 있다. draw는 상태의 모양 값만 보고 그린다. 위치·크기·회전은 렌더러가 translate → rotate → scale로 걸어 준다(main.js:973–990).
  • 같은 물건이 상태에 따라 자리만이 아니라 모양도 바꾼다.
    • 책 일곱 권은 A에서 r = π/2로 누워 쌓인다(앞 책들의 두께를 누적한 높이, main.js:697–708). B에서는 선반에 0.85배로 선다.
    • 옷은 A에서 종류별 무더기 모양이다(CRUMPLE, main.js:487: 의자에 걸친 후드, 쌓인 스웨터, 의자 밑의 티셔츠·양말). B에서는 같은 물건이 개어진 사각형이 되어 바구니 위에 쌓인다.
  • 그리는 순서는 상태별 z로 정하고, 같으면 목록 순서로 정한다(안정 정렬, main.js:1556). 옷 무더기는 의자 좌판(z 1404)과 등받이(z 1416) 사이에, 후드는 등받이 뒤(z 1417)에 들어간다.
  • 2.5D: 소실점 하나로 윗면과 옆면 (main.js:124 prism)
  • 상자의 앞면은 그대로 그린다. 뒷면은 소실점 VP = (540, 560) 쪽으로 k = 1/(1 + d)만큼 줄인 사각형이다(b = VP + (p − VP)·k).
  • 앞면 윗변이 VP보다 아래에 있으면 윗면(앞 윗변과 뒷 윗변을 잇는 사다리꼴)이 보인다. 상자가 VP의 왼쪽에 있으면 오른쪽 옆면이, 오른쪽에 있으면 왼쪽 옆면이 보인다.
  • 움직이는 물건은 VP를 자기 좌표계로 옮겨 쓴다: VPL = ((VPx − x)/s, (VPy − y)/s)(main.js:986). 그래서 같은 상자가 어디로 옮겨져도 윗면이 맞는 방향으로 기운다.
  • 바닥 널은 더 높은 소실점(540, 300)으로 모이고, 이음매는 칸마다 원근 간격으로 엇갈린다(main.js:137–145).
  • 같은 렌더러, 같은 카메라 = 픽셀 단위 정합 (main.js:878 setCam, main.js:960 paintRoom)
  • 카메라는 screen = (wx, wy) + s·(p − (cx, cy)) 하나다. 와이프에서는 두 상태를 같은 전체 화면 카메라로 그린다.
  • 분할 화면의 두 창은 s와 (cx, cy)가 같고 창 중심 wy만 정확히 755 px(정수) 다르다(위 창 중심 517.5, 아래 창 중심 1272.5). 그래서 바뀌지 않은 액자, 시계, 책상 모서리가 두 창에서 같은 서브픽셀 위치에 놓인다.
  • 상태 사이에서 달라지는 것은 물건과 빛뿐이다. 정합은 위치의 정합이다. 바뀌지 않은 물건도 A에서는 어둡고 B에서는 밝다.
  • 와이프 = 미리 그린 두 상태 + 페더 클립 (main.js:1060 composite, main.js:1074)
  • 매 프레임 A를 오프스크린 A에, B를 오프스크린 B에 통째로 그린다. 둘 다 같은 t를 쓰므로 먼지 위치와 화분 흔들림까지 같다.
  • B에 destination-in으로 선형 그라디언트 마스크를 씌운다. 마스크는 선 위의 점 P에서 법선 n 방향으로 P − n·f에서 알파 0, P + n·f에서 1이다(f = 20 px, 범위 밖은 끝 색으로 채워진다).
  • 합성 순서는 A → A 쪽 가장자리 그림자(선에서 90 px, 0.30 → 0) → 마스크된 B다. B가 종이처럼 A 위에 얹혀 보인다.
  • 선은 넓은 민트 빛 두 겹(26 px α0.10, 12 px α0.22) 위에 흰 선 두 겹이다. 선과 법선을 일반 각도로 받으므로 같은 함수가 회전 단계도 처리한다.
  • 손이 끄는 손잡이: 최소 저크 획 + 감쇠 스프링 (main.js:1019–1051)
  • 손은 쉼점 사이를 최소 저크 곡선으로 움직인다: x = xa + (xb − xa)(10p³ − 15p⁴ + 6p⁵). 사람 팔의 뻗기 동작이 따르는 속도 모양이다(양 끝에서 속도·가속도 0). 쉼점은 [1.72 s 1012] → [2.4 s 166] → [3.06 s 780] → [3.6 s 380] → [4.0 s 540]이다(main.js:1020).
  • 손목이 돌아 생기는 호를 흉내 내려고, 획마다 세로로 ∓(16 또는 12)·sin(πp)를 더한다.
  • 손잡이는 손에 스프링으로 묶인다: x'' = ω²(x_손 − x) − 2ζω·x', ω = 19 rad/s, ζ = 0.52. setup에서 1/600초 고정 간격의 반암시적 오일러로 적분해 x, y, 속도를 표로 굽는다(main.js:1036).
  • frame은 표를 선형 보간만 한다. 손이 멈추는 반환점마다 손잡이가 조금 넘쳤다가 돌아오는데, 이 넘침은 식에서 저절로 나온다.
  • 4.0–4.12초에 표의 값을 540으로 부드럽게 끌어와 회전 축과 맞춘다(main.js:1048).
  • 손잡이는 속도에 비례해 진행 방향으로 늘어나고(1 + min(0.2, |v|/9000), main.js:1100) 수직 방향으로 줄어든다. 잡는 순간 0.92배로 눌리고, 놓으면 outBack으로 돌아온다.
  • 칩이 선을 탄다 (main.js:1601 paintChips)
  • 「정리 전」은 오른쪽 끝을 선 − 26에, 「정리 후」는 왼쪽 끝을 선 + 26에 맞춘다. 화면 밖으로 나가지 않게 24 px에서 멈춘다.
  • 각 칩은 자기 상태 쪽 영역으로 클립된다. 선이 칩을 밀어붙이면 칩이 선 밑으로 잘려 들어간다.
  • 회전이 시작되면 클립을 풀고, 칩 위치를 "선에 붙은 자리"에서 "각 창의 왼쪽 위 + 24 px"로 보간한다. 창이 움직이는 동안에도 목적지는 매 프레임 창의 사각형에서 다시 읽는다.
  • 좌우 → 위아래: 법선을 90° 돌린다 (main.js:1053 wipeLine)

  • 검사 결과: 렌더러 검사(정순, 새 페이지 역순, 되돌아가기)에서 바이트 단위로 같았다(maxPixelDiff 0). 표시 방식을 바꾸기 전에는 따로 13개 시각(0.4–9.0초, 모든 단계)을 정순과 역순으로 찍어 비교했고, 결과는 모두 같았다.

  • 고리는 볼록 껍질에서 나온다. 오목한 무리(책 더미 + 옆에 쓰러진 책 두 권)는 빈 바닥까지 함께 감싼다. 알파 셰이프나 오목 껍질로 바꾸면 더 바짝 붙지만, 고리가 울퉁불퉁해져 손그림 느낌이 줄어든다.
  • 겹침 판정의 hullGap은 실제 거리보다 작게 잴 수 있다(꼭짓점끼리 가장 가까운 경우). 그래서 겹치지 않는데도 반지름을 줄이는 일이 생길 수 있다. 안전한 쪽의 오차다.
  • 군집이 둘인 그룹은 한 창에 같은 번호가 두 번 나온다(B의 커튼). 숨은 차이 찾기 그림의 관례에는 맞지만, 번호 하나에 고리 둘을 짧은 선으로 잇는 방식도 있다.
  • 실루엣은 t = 6.0의 자세로 한 번 잰다. 크게 흔들리는 물건이면 매 프레임 다시 재거나, 흔들림 범위만큼 여유를 더해야 한다.
  • 차이는 상태 값의 비교다. 화면에 보이지 않는 변화(가려진 물건의 이동)도 차이로 잡힌다. 두 상태를 픽셀로 비교하면 빛 차이까지 잡힌다. 둘을 함께 쓰는 열지도 보기가 다음 단계다.
  • 크롭은 모든 차이를 한 화면에 담는다. 차이가 멀리 흩어지면 크롭이 넓어진다(여기서는 약 0.56배). 차이 두세 개씩 묶어 크롭 사이를 이동하는 "차례로 짚기" 모드가 다음 단계다.
  • 손잡이는 미리 정한 획을 따라간다. 사용자가 직접 끄는 대화형 버전은 이 데모의 범위 밖이다(t의 순수 함수여야 하므로). 같은 스프링 식에 포인터 위치를 넣으면 된다.
