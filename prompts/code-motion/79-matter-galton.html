만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

밝은 종이 바탕(점 격자) 위에 그린 인포그래픽형 갈톤 보드다.

  • 시작 (0–0.6초): 왼쪽 위에 헤드라인 "우연이 모이면"이 떠오른다. 깔때기에는 공 420개가 이미 차 있다.
  • 공은 남색과 하늘빛 회청색 두 색이 네 겹 띠로 쌓여 있다.
  • 못 14단이 위에서부터 한 줄씩 튀어나오고, 칸막이 14개가 바닥에서 자라 오른다.
  • 목에 걸린 산호색 문이 옆으로 빠지면서 공이 쏟아지기 시작한다.
  • 쏟아짐 (0.6–7초): 맨 먼저 빠져나가는 공들 가운데 하나만 산호색이다(가운데가 아닌 칸에 떨어지는 공으로 고른다).
  • 이 공이 지나간 길이 선으로 남고, 부딪힌 못은 산호색 고리로 표시된다.
  • 이 공이 멈추면 왼쪽 위 빈자리에 카드가 뜬다: "오른쪽 6번 / 왼쪽 8번 → k = 6 칸에 착지".
  • 칸마다 쌓인 수가 더미 위에 실시간으로 표시된다. 오른쪽 위 카운터는 "착지한 공 n / 420"을 센다.
  • 깔때기 안의 색 띠가 그대로 흘러내려 칸 속에 지층처럼 쌓인다.
  • 절정 (7.05–8.4초): 이론 곡선 N(np, np(1−p)), n = 14, p = ½가 왼쪽에서 오른쪽으로 그려진다.
  • 곡선은 쌓인 더미 위를 덮는다. 정수 k마다 이항값 점이 찍히고, 칸의 숫자는 곡선 위로 올라간다.
  • 헤드라인 둘째 줄 "질서가 된다"(산호색)가 나타난다.
  • 여운 (8.2초–): 오른쪽 카드에 공식이 정리되고, 지시선이 곡선을 가리킨다.
  • B(14, ½) ≈ N(7, 3.5)
  • μ = np = 7
  • σ² = np(1−p) = 3.5
  • 실측 μ · σ²
  • 아래 짙은 띠(y 1636–)에 하네스 자막이 올라간다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 물리 (matter-js 0.20, sim.js)
  • 정적 물체:
    • 깔때기 벽: 얇은 사각형. 안쪽 면이 그린 선과 정확히 겹치게 놓는다(sim.js:93).
    • 못: 원 182개.
    • 양옆 벽과 바닥.
    • 칸막이: 둥근 머리를 얹어서 칸막이 위에 공이 걸쳐 서지 않게 했다.
  • 동적 물체: 공 420개(r = 7.6).
  • Engine.update(engine, 1000/60/3). 고정 dt 5.56 ms로, 1/60초 기록 프레임마다 세 번씩 돈다(sim.js:33). Runner는 쓰지 않는다.
  • 2D 갈톤 보드의 문제와 보정: 아무 손도 대지 않으면 2D 강체 갈톤 보드는 너무 퍼진다.
  • 못에 한 번 맞을 때 옆으로 두세 칸씩 튀어 σ가 이항분포의 두 배 가까이 된다(전형적인 실패).
  • 실제 보드는 뒤로 기울어 있어서 공이 뒤판에 구르고 비빈다. 이 접촉을 못 영역 안의 가로 감쇠로 모델링했다(sim.js:37, sim.js:151–167).
  • 감쇠는 시간에 대해 지수 형태라 dt에 의존하지 않는다.
  • 26 px/s보다 느린 옆 속도는 놓아준다. 그래야 못에서 천천히 굴러떨어지는 공이 자유롭다.
  • 그 결과 못 한 번이 "왼쪽/오른쪽 반 칸"의 동전 던지기가 된다.
  • 못 반지름 6.5 + 공 반지름 7.6 = 14.1 > dx/4 = 13이라, 격자를 똑바로 관통하는 통로가 없다(sim.js:22–25).
  • 조율 결과 (node로 직접 굽기, 시드 79/80/81):
  • 착지율 420/420.
  • σ = 1.81 / 1.74 / 1.79 (이론 √14/2 = 1.87).
  • χ² = 10.5 / 13.7 / 14.8 (자유도 14) → 이항분포와 잘 맞는다.
  • 마지막 착지 6.9–7.0초, 7.7초 이후에는 정지.
  • 시드 79의 칸별 수: 0 0 0 8 29 59 77 83 70 57 31 6 0 0 0 (이론 0 0 2 9 26 51 77 88 77 51 26 9 2 0 0).
  • 잠자기: enableSleeping을 켰다.
  • 칸 아래에서만 잠들게 했다. 칸 위(깔때기, 못)에서 잠든 공은 매 스텝 깨운다(sim.js:158).
  • 깔때기에서 잠든 공은 받침이 빠진 뒤 허공에 떠 있게 되기 때문이다(matter 잠자기의 고질).
  • 사전 굽기 (pre-roll): 기록 전에 1.6초 동안 문을 닫은 채 깔때기를 가라앉힌다(sim.js:46, sim.js:169–172).
  • 그래서 0초에 이미 꽉 찬 깔때기가 보인다.
  • 공은 깔때기 아래부터 채워 넣는다. 생성 순서가 곧 높이이고, 색 띠는 생성 순서로 정한다(sim.js:201).
  • 그리기 (Canvas 2D, main.js):
  • 종이·격자·개수 축·깔때기·바닥·자막 띠는 setup에서 한 번 그린다(main.js:98–135).
  • 개수 축의 눈금(20개 간격)은 굽기 결과에서 최소제곱으로 맞춘 "공 하나당 높이" hPer로 정한다(main.js:61–67).
  • 같은 hPer를 곡선에도 쓴다. 그래서 곡선이 더미 높이와 같은 축척에 놓인다(main.js:157).
  • 공은 3배 해상도 스프라이트를 drawImage로 그린다(main.js:137–149).
  • 곡선은 N·φ((u−7)/σ)/σ를 칸 단위 u로 그린다. 정수 k의 점이 이항 확률의 근사값이다(main.js:259–294).

참고: - Francis Galton, Natural Inheritance (1889), quincunx. - de Moivre–Laplace 정리 (이항 → 정규). - matter-js Engine.update·Sleeping·Body 소스(0.20).

프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 물리는 setup에서 한 번만 돈다.
  • 고정 dt, 정해진 순서의 스텝.
  • Common._seed = 79, Common._nextId = 0(sim.js:79–80). 물체 id가 같아야 쌍(pair) 해소 순서가 같다.
  • 공의 초기 위치 지터와 못 위 균형 깨기 동전은 하네스 rand(79)로 만든다.
  • Math.random·Common.random은 쓰지 않는다.
  • 결과는 pos: Float32Array[(600+1)·420·2](1/60초마다 x, y)다. frame(t)는 이 표만 읽는다.
  • 두 기록 프레임 사이를 선형 보간한다(main.js:223–231). 직전에 무엇을 그렸든 같은 그림이 나온다.
  • 선택된 공(main.js:76), 정지 시각(main.js:79–85), 부딪힌 못의 시각, 칸별 수, μ·σ²는 모두 setup에서 표로 정한다.
  • 프레임에서는 t만 비교한다.
한계와 조절할 점

굽기 시간: - node 24에서 약 2.5–3.3초(공 420개 × 1,800+290 스텝). - 브라우저에서도 같은 JS라 비슷하다(목표 10초 이내).

손잡이: - 분포 폭 PHYS.side (sim.js:37): - 8 → σ 1.88, 9 → σ 1.81, 6.5 → 2.2, 4 → 2.6, 2 → 3.6(평평). - 값을 올리면 좁아지지만 늦게 도착하는 공이 생긴다. - 못/공 크기 BOARD.pegR, BOARD.r (sim.js:22, sim.js:25): - r + pegR ≥ dx/4를 지켜야 직통 통로가 생기지 않는다. - 바꾸면 side를 다시 맞춘다. - 속도 PHYS.gravity (sim.js:32): 깔때기 배출 속도와 낙하 시간을 함께 정한다. - 배출량 BOARD.neckHalf (sim.js:20): 목을 좁히면 막히거나 늦어진다. - 공 수 N (sim.js:43): 깔때기 용량은 약 430개. 더 넣으려면 hopTop·hopHalf를 키운다. - 문 여는 시각 GATE_T (sim.js:45). 사전 굽기 PREROLL (sim.js:46). - 연출 시각표 T (main.js:26–34): 곡선 7.05–8.4초, 헤드라인 둘째 줄 7.75초, 공식 카드 8.2초. - 선택된 공 고르기 (main.js:76): 먼저 나온 12개 가운데 5–9번 칸(7 제외)에 떨어지는 공.

한계: - 뒤판 마찰은 실제 접촉이 아니라 모델이다(2D 세계에는 뒤판이 없다). - 그래서 공 하나의 궤적은 진짜 기울어진 보드보다 지그재그 폭이 작다. - σ가 이론보다 3–7% 좁다. 꼬리 칸(0–2, 12–14)은 거의 비어 있다. - matter의 원 쌓기는 약간 무르다. 그래서 더미 높이는 hPer로 근사한 값이고, 칸별 실제 꼭대기와 몇 px 어긋날 수 있다. - 곡선은 이론값을 그리고, 카드에 실측 μ·σ²를 함께 적는다. - 같은 V8에서는 결정적이다. 다만 다른 JS 엔진에서 부동소수 경로가 달라지면 굽기 결과(어느 공이 어느 칸)도 달라질 수 있다. - 이 경우 화면 안의 수치는 모두 그 결과에서 다시 계산되므로 일관성은 유지된다.
