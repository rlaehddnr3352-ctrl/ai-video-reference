활용 가이드

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

영상에 옮길 때 주의

  • 손으로 쓴 WebGL2 셰이더 — 영상 스킬의 WebGL 층(three.js 등) 위에서 다시 쓴다
  • CPU 검증 프레임당 5.8s — 그대로 옮기면 MP4 내보내기가 매우 느리다. 해상도를 낮추거나 미리 굽는다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

10초. 깊은 남색 어둠에서 시작한다. 0–2.2 s에 빛나는 연기선이 아래에서부터 차오르며 보이지 않던 상승기류가 드러난다. 기류는 화면 전체에 걸친 큰 S자 비단 결로 출렁인다(난류, 2–4 s). 2.2 s부터 바람 속에 보이지 않는 구가 생긴다. 연기선이 그 둘레를 갈라 돌아가고, 흐름이 빨라지는 양 옆구리가 금빛으로 달아오르며, 중심은 어둡고 테두리는 층층이 겹친 구의 실루엣이 된다(절정 5.5–8 s). 난류가 가라앉으며 선은 층류로 곧게 정돈되고, 흔적이 길어져 장노출 사진 같은 여운으로 끝난다(8–10 s). 7장의 깊이 시트가 원근 시차로 엇갈리고, 먼 시트일수록 어둡고 가늘다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 상태 = 텍스처 두 장. 입자 122,880개(384×320)의 (x, y, dye, age)를 RGBA32F 핑퐁 텍스처에 두고(main.js:16), 흔적은 1080×1920 RGBA16F 누적 버퍼 하나에 둔다. 한 스텝(dt = 1/60 s, 영상 프레임당 2스텝, main.js:15)은 다음 순서다. 1. 이류(fragment shader, main.js:66): 흐름 함수 ψ = −U(x−cₓ) + 난류 fBm(2옥타브)을 쓴다. 노이즈는 해석적 기울기가 붙은 3D 그래디언트 노이즈이고(main.js:47), 모서리마다 정수 해시 1번으로 계산한다(sin·삼각함수 없음, main.js:42). 속도 = (∂ψ/∂y, −∂ψ/∂x)이므로 정확히 발산 0이다(main.js:92). 적분은 RK2다(main.js:99). 2. 보이지 않는 구: 각 깊이 시트 z는 3D 장의 단면이고, 구는 그 단면을 반지름 √(R²−z²)인 원으로 자른다. Bridson(2007)의 램프 ψ·ramp(d/d₀)가 그 원을 유선으로 만들어 바람이 반드시 돌아간다(main.js:73–90). 투영하면 중심은 모든 시트가 막혀 어둡고, 가장자리로 갈수록 막힌 시트가 줄어 구처럼 음영이 진다. 반지름은 track으로 0→0.27로 자란다(main.js:22). 구 안에 갇힌 입자와 수명이 다한 입자는 (id, step) 해시로 다시 태어난다(main.js:106–107). 3. 흔적: 버퍼에 blendFunc(ZERO, SRC_ALPHA)로 감쇠를 곱하고(main.js:326), 입자마다 prev→next 선분을 안티앨리어싱된 반열린 박스필터 선분으로 더한다(main.js:152–161). 같은 입자의 연속 선분이 이음매에서 겹치지 않아 구슬무늬가 없다. 밝기 이득은 (1−감쇠)에 비례해서 흔적 길이가 변해도 정상상태 밝기가 일정하다(main.js:341).
  • 연기 와이어(dye): 입자는 태어난 자리의 ψ를 dye로 지니고 다닌다(main.js:114). dye가 얇은 띠에 드는 입자만 밝히므로(main.js:146–148) 풍동의 연기선, 곧 물질선(streakline)이 그려진다. 순간 ψ로 띠를 고르면 흐름이 바뀌는 동안(구가 자랄 때) 띠가 입자 위로 미끄러져 모래알처럼 깜빡였는데, 지니고 다니는 값으로 바꾸자 선이 구를 감싸며 끊기지 않았다. 정상류에서는 같은 유선의 입자가 같은 dye를 가지므로 결국 유선과 같아진다. 노이즈 장을 바람과 함께 흘리지 않고 제자리에서 천천히 변형시켜 난류 구간에서도 선이 길게 이어진다(main.js:76 근처 q).
  • 색과 깊이: 속력이 배경 바람보다 빠르면 남색 → 청록 → 금색이 된다. 그래서 구 옆구리(포텐셜 흐름에서 약 2U)가 금빛이 된다. 깊이 시트는 id 해시로 7장 중 하나로 정해지고(main.js:38), 원근 1/(1−z/F)로 투영되며(main.js:125), 먼 시트는 0.12배로 어둡고 가늘다.
  • 그리기 비용: 입자당 정점 6개를 인스턴싱 없이 drawArrays(TRIANGLES, 0, 6N) 한 번으로 그리고 gl_VertexID로 모서리를 고른다(main.js:137, 343). SwiftShader는 drawArraysInstanced를 인스턴스마다 따로 처리해 스텝당 약 3.5 s가 걸렸고, 이 방식으로 약 0.13 s가 되었다(약 27배).
  • 합성(상태를 읽기만 함): 흔적 버퍼 → 13탭 다운샘플·텐트 업샘플 블룸 → ACES → 비네트·그레인(main.js:193).
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • replay({ dt: 1/60, every: 120, init, step, save, load })(main.js:297)를 쓴다. 모든 파라미터는 스텝 번호 n의 함수 track(n·dt)이고, 재탄생 난수는 GPU 정수 해시 pcg(id ^ step·φ)이며, 초기 구름은 rand(1010)이다.
  • save()는 입자 텍스처(RGBA32F)와 흔적 버퍼(RGBA16F)를 새 체크포인트 텍스처에 texelFetch 복사하고, load()는 거꾸로 복사한다(main.js:352–363). 셰이더 복사라 비트가 그대로 보존된다. 체크포인트는 2 s마다 하나에 약 18.6 MB(16.6 + 2.0), 10 s 동안 5개다.
  • 합성 패스는 상태를 읽기만 하고 쓰지 않으므로, 앞에서 어떤 프레임을 그렸든 n번째 스텝의 상태는 같다.
  • 결과: determinism: pass. 한 페이지에서 정순, 새 페이지에서 역순(첫 seek가 598스텝 재생, 이후 체크포인트 복원 + 최대 120스텝)으로 0, 3.7, 5, 7.1, 9.3, 9.967 s를 찍어 비교했고, 같은 페이지 점프백(9.967 → 5 s)도 통과했다.
  • 실시간 재생: 스테이지의 tick은 경과 시간만큼 앞으로 1–2스텝 진행한다. 끝 → 0 루프는 체크포인트 0 복원이다(위 역순 검사와 같은 경로).
한계와 조절할 점
  • 구가 자라는 동안 안에 갇힌 입자는 곧바로 다른 곳에서 태어난다. 밀어내는 효과(움직이는 장애물의 경계조건)는 없다. 움직이는 구나 글자(SDF)를 장애물로 쓰려면 Bridson의 이동 경계 항을 더해야 한다.
  • dye는 태어날 때 정해지므로, 난류 구간에서 태어난 입자가 정상류로 바뀐 뒤 수명(2.5–7.5 s) 동안 "엉뚱한" 띠를 밝힌다. 선이 조금 부드러워 보이는 이유다. 수명을 줄이거나 dye를 서서히 현재 ψ로 이완시키는 방법이 있다.
  • 체크포인트가 흔적 버퍼 전체(16.6 MB)를 복사한다. 흔적을 반해상도로 두거나, 체크포인트에서 흔적 대신 "직전 k스텝의 입자"만 저장하고 다시 그리는 방식이면 메모리를 크게 줄일 수 있다.
  • 하네스 관찰 1: 렌더러의 page.screenshot은 30 s 제한이다. 긴 seek(수백 스텝)는 GPU 명령을 쌓아만 두고 반환하므로, 스크린샷이 그 작업을 기다리다 시간 초과가 났다. seek 안에서 20스텝마다 1텍셀 readPixels로 동기화해 우회했다(main.js:346). 실시간 재생의 1–2스텝 tick에서는 동기화하지 않는다.
  • 하네스 관찰 2: SwiftShader에서는 인스턴싱이 매우 느리다(위 참조). 다른 데모도 인스턴스 수가 많으면 gl_VertexID 방식을 권한다.
