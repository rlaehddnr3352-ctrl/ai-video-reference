숫자·과정·경로·비교처럼 말로 설명하기 어려운 정보를 보여 줄 때 써요.

  • 실제 숫자와 출처를 표로 주세요. AI가 숫자를 지어내지 않게 '주어진 값만 쓰라'고 적어요.
  • 한 화면에 수치 하나, 결론 숫자는 크게.
  • 그래프는 마지막 값에서 1초 멈춰야 기억에 남아요.

영상에 옮길 때 주의

  • d3: 영상 스킬에 없는 라이브러리라면 원리만 가져와 Canvas 2D·SVG·WebGL로 직접 쓴다
  • 실제 지도 데이터(world-atlas) — 영상에서는 직접 그린 양식화된 지도로 바꾼다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

  • 0–2.6 s 등장 — 어두운 지구가 빠르게 돌며 들어온다. 그동안 태양이 서쪽에서 들어와(새벽) 유럽·아프리카·인도가 밝아지고, 동아시아는 밤으로 남아 도시 불빛이 켜져 있다.
  • 1.0–6 s 절정 — 서울에서 도쿄·런던·두바이·싱가포르·시드니·샌프란시스코·모스크바·뉴욕·호놀룰루·베이징으로 10개 대권 항로가 차례로 뜬다. 항로는 지표면에서 떠오른 호로 그려지고, 빛나는 머리와 끝이 가늘어지는 꼬리를 단다. 지평선 너머로 넘어간 구간은 지구에 가려진다. 도착하면 도시 이름과 물결 고리가 뜬다. 왼쪽 위 카운터(DOM)가 누적 비행거리를 센다.
  • 5.7–9.4 s 줌인 — 카메라가 서울로 다가가며 지수적으로 확대된다. 그사이 10편의 귀국편이 서울로 모여들어 도착할 때마다 빛이 고인다. 밤의 한반도·일본·중국 동부가 도시 불빛과 달빛 해안선으로 드러난다.
  • 8.7–9.6 s 여운 — 모두 돌아오면 항로망 전체가 한 번 따뜻하게 밝아지고, 마지막 0.4 s에 거의 검게 어두워진다. 플레이어는 끝에서 0으로 되감아 반복 재생하므로 어두운 끝과 어두운 시작이 이음매가 된다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리

d3-geo 파이프라인 하나. 모든 지리 형상은 geoOrthographic().precision(0).clipExtent(…) 투영 하나를 지나간다(main.js:311). 50m 해안선은 꼭짓점 간격이 이미 0.1° 이하이므로 적응형 재표본화(precision)는 끈다. 클리핑은 d3가 두 번 한다. 하나는 정사영의 clipAngle 90°로 보이는 반구만 남기는 것, 다른 하나는 clipExtent로 화면 밖을 잘라내는 것이다. 회전은 rotate([-λ, -φ])이고(main.js:347), 같은 회전을 3D 기저 e/n/c로도 계산해 둔다(main.js:350). 이 기저로 항로·도시 점을 d3 없이 직접 투영한다.

육지 (main.js:386–399). - topojson feature()로 얻은 50m MultiPolygon(1,419개)을 원본 그대로 둔다. 개관용으로 0.1° 간격으로 솎은 LOD를 하나 더 만든다(thinLand, main.js:93). 이때 솎은 뒤 geoArea가 25% 넘게 달라지는 폴리곤은 원본을 쓴다. 날짜변경선이나 극을 지나는 고리가 뒤집히는 것을 막기 위해서다. - 폴리곤마다 경계 캡(중심 단위벡터와 각반경)을 미리 계산해 둔다(main.js:115). 매 프레임 화면이 덮는 캡에 닿지 않는 폴리곤은 d3에 넘기기 전에 뺀다(main.js:387). - d3 geoPath가 SVG 문자열을 만들지 않고 Path2D에 바로 그린다(main.js:392). 같은 경로를 채우기와 해안선 획에 다시 쓴다.

낮과 밤의 경계 (main.js:401–419). - 반자오점(태양 반대편)을 중심으로 geoCircle().radius(90)을 만든다(main.js:276, 406). 이것을 같은 투영과 클리핑에 통과시켜 1/4 해상도 마스크에 채운다. 반구 다각형을 지평선과 화면 경계에서 자르는 일은 d3가 맡는다. 줌인해서 밤이 화면 전체를 덮으면 clipExtent가 화면 사각형을 내보낸다. - 경계는 구면 위 각도로 정한 σ = 4.5°(main.js:27)만큼 부드럽게 만든다. 3회 반복 상자 흐림(blur3, main.js:223)으로 처리하며, 반경과 상관없이 픽셀당 O(1)이다. - 원판 바깥 마스크 값은 가장 가까운 지평선 점의 태양 부호로 이어 붙인다(main.js:415). 이렇게 하지 않으면 흐림이 밤쪽 가장자리를 밝게 끌어당긴다.

빛 (main.js:421–461). - 1/4 해상도에서 픽셀마다 구면 법선을 구하고 Lambert 항 lam = n·L을 계산한다(main.js:432). L은 시야 공간의 태양 방향이다. - 곱셈 맵은 낮의 조도와 밤의 남색을 마스크로 섞는다. 덧셈 맵에는 대기 산란(림)과 경계선의 따뜻한 띠를 넣는다(main.js:439–440). - 바다의 태양 반사는 반벡터 (L+V)/|L+V| 위치에 둔다. - 달빛 해안선 획은 줌인했을 때만 그린다(main.js:456). CPU 래스터에서 해안선 전체에 획을 긋는 것이 가장 비싼 연산이기 때문이다.

도시 불빛 (main.js:131–205, 463–510). - 실제 도시 좌표 주변에 rand(seed)로 점을 뿌린다(main.js:165). 조밀한 중심, 긴 꼬리, 위성도시, 고속도로 회랑, 인구 근처의 희박한 농촌 점으로 구성한다. - 점은 geoContains로 육지에 있는 것만 남긴다(main.js:156). 그런데 Eurasia 고리 하나에 1만 꼭짓점이 있어 판정 1회에 약 1 ms가 든다. 그래서 같은 육지를 등장방형으로 래스터화해 먼저 거른다. 동아시아는 0.025°, 전 지구는 0.1°이다(main.js:147). 해안선이 지나가지 않는 픽셀(alpha 0 또는 255)은 바로 결정하고, 반투명 해안 픽셀만 geoContains가 판정한다. 약 3.3만 점 가운데 정밀 판정은 약 2,200회다. - 매 프레임 점은 태양과의 각도로 밤 쪽에서만 켜진다. 그리기는 1만 번의 drawImage 대신 JS에서 반해상도 버퍼 하나에 스플랫한다. 커널은 (1−d²/r²)³이다(main.js:465). 그 뒤 톤 커브 1−e^(−1.5v)를 조회표(16,384칸)로 적용해 drawImage 한 번으로 올린다. 변환과 그리기는 지구 원판의 경계 상자 안만 한다.

항로 (main.js:207–221, 538–630). - geoInterpolate로 대권을 140점 표본화한다. 각 점을 1 + h·sin(πf)배 띄운 3D 점으로 저장한다. 먼 항로일수록 h가 크다(main.js:211). - 띄운 점은 구 뒤에 있으면서 원판 안에 투영될 때만 가린다(main.js:586). 그래서 호가 지평선을 넘어가는 장면이 자연스럽다. - 머리 위치는 smooth((t − 출발)/비행시간)으로 정한다. 꼬리는 머리 뒤 30% 구간을 굵기와 알파를 점점 줄인 선분들로 그린다.

합성 (main.js:512–536). 지구를 다 그린 뒤 원판 하나를 destination-in으로 채워 지구를 깔끔하게 오려낸다. 별(카메라를 따라 시차 이동)과 대기 후광은 destination-over로 지구 뒤에 그려 넣는다. 덕분에 clip()이 필요 없다.

렌더 경로. ?render=1(헤드리스 SwiftShader)일 때만 라이브 캔버스를 willReadFrequently: true로 만들어 CPU 래스터를 쓴다(main.js:286). SwiftShader에서는 GPU 가속 2D 캔버스가 수천 개의 그리기 명령을 캡처 시점까지 미루기 때문에 훨씬 느리다. 일반 브라우저에서는 기본 GPU 캔버스를 쓴다.

프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 모든 시간 변수(카메라 회전·확대, 노출, 태양 경도, 항로 진행, 페이드)는 track/smooth로 만든 t의 순수 함수다(main.js:83–87, 579).
  • 도시 불빛과 별은 setup에서 rand(1507)과 rand(77)로 한 번만 생성한다. 프레임 사이에 이어지는 상태가 없다.
  • 오프스크린 버퍼(곱셈·덧셈 맵, 밤 마스크, 불빛 버퍼)는 매 프레임 전체를 다시 쓴다. 이전 프레임 값이 남지 않는다.
  • 렌더러의 앞→뒤 / 뒤→앞(새 페이지) / 같은 페이지 되돌아가기 검사를 통과했다(determinism: pass).
한계와 조절할 점
  • 최적화 (CPU 프로파일 기반, 출력은 PSNR 64–68 dB로 동일).
  • 원래 프로파일에서 Path2D.closePath가 자기 시간 17%로 가장 비쌌다. d3가 해안선 고리마다 부르기 때문이다. openRingSink는 closePath를 첫 점으로의 lineTo로 바꾼다. fill은 열린 서브패스를 스스로 닫는다.
  • 보이는 반구 안에 통째로 들어간 다각형(캡 중심각 + 반지름 < 90°)은 d3의 회전·구면 클리핑·polygonContains를 건너뛴다. setup에서 고리를 단위벡터 배열로 바꿔 두고, 매 프레임 시점 기저 (e, n)와의 내적 두 번으로 바로 투영한다. 지평선에 걸친 다각형만 d3가 자른다.
  • 픽셀 반복문의 Math.exp·Math.pow는 조회표로 바꿨고, 반복 범위는 원판 경계 상자로 줄였다.
  • 결과: 프레임당 JS 22–32 ms → 16–23 ms.
  • 남은 비용은 지평선에 걸친 큰 고리(유라시아 1만 꼭짓점)의 d3 클리핑, 도시 불빛 스플랫, 밤 마스크 블러다. 다음 후보는 Web Worker + OffscreenCanvas로 투영을 옮기는 것, 또는 빛·밤 계산을 WebGL 셰이더로 옮기는 것(기하는 d3, 빛은 GPU)이다.
  • 도시 불빛은 그럴듯하게 만든 합성 데이터다. 실제 야간광(VIIRS) 래스터를 쓰면 훨씬 사실적이다.
  • 경계 흐림은 화면 공간 상자 흐림이다. 그래서 정사영 가장자리에서 각도 폭이 약간 짧아진다. 구면 각도로 정확하게 하려면 마스크 대신 픽셀마다 lam으로 부드러운 계단을 만들면 되는데, 그러면 geoCircle을 쓰는 의미가 없어진다.
  • R이 1100 px를 넘어 LOD가 50m 원본으로 바뀔 때 몇 px짜리 섬이 갑자기 나타날 수 있다. 확대가 빠른 구간이라 거의 보이지 않는다.
  • 하네스 관련: 초기 render.mjs는 setup 예외가 나면 300 s 동안 멈췄다(현재는 lead가 고쳤다). 이 데모에서는 timeout으로 감싸 우회했다.
