활용 가이드

장면 전환로 쓸 때

장면 A에서 B로 넘어가는 0.3–1초 구간에 써요. 컷 사이 이탈을 줄여요.

  • 전환 하나를 영상 전체에 반복해 쓰면 통일감이 생겨요. 매번 다른 전환은 산만해요.
  • 앞 장면의 마지막 프레임과 다음 장면의 첫 프레임을 같이 알려 주세요.
  • 실사 영상 사이에 넣을 땐 투명 배경(알파) 영상이나 두 영상을 직접 합치는 방식으로 요청해요.

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

영상에 옮길 때 주의

  • 손으로 쓴 WebGL2 셰이더 — 영상 스킬의 WebGL 층(three.js 등) 위에서 다시 쓴다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

9.6초. 똑바로 선(가시가 위, 심장형이 아래) 맨델브로트 집합 전체로 시작해 0.3초 머문 뒤 가속하여, 시호스 밸리로 초당 약 2.1자릿수(×130)의 일정한 속도로 파고든다. 화면이 천천히 돌며 해마 꼬리 나선, 나선 속의 나선, 실 같은 가지들이 연이어 지나간다. 7.6초쯤 배율 10¹⁴(화면 반높이 ≈ 10⁻¹⁴)을 넘고, 마지막 1.5초 동안 감속하며 화면 한가운데에 원래 집합과 똑같은 작은 사본(주기 998의 미니브로트, 크기 ≈ 6·10⁻¹⁶)이 똑바로 선 채 나타나 멈춘다(절정·여운). 최종 화면 반높이 1.4·10⁻¹⁵ — 시작보다 1.6·10¹⁵배 확대, 픽셀 간격 2·10⁻¹⁸(배정도 double의 한계 10⁻¹⁶보다 훨씬 아래).

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  1. 고정밀 기준점 — BigInt 고정소수점 (main.js:31–main.js:58). 소수 256비트(≈77자리) 정수 연산. 유명한 시호스 밸리 좌표(위키백과 줌 시퀀스의 중심, main.js:26)에서 출발해 주기 p = 998(그 점의 궤도가 0에 가장 가까이 돌아오는 반복 횟수)에 대한 뉴턴법 z_p(c) = 0으로 미니브로트의 핵 c₀를 찾는다(nucleus, main.js:45, setup에서 실행). 기준 궤도 Z₀…Z_p(핵이므로 Z_p = 0, 정확히 주기적)를 같은 정밀도로 계산해 float 텍스처로 올린다(main.js:198, main.js:284).
  2. 미니브로트의 크기와 방향 (main.js:203–main.js:214). λ = Π 2Z_j, β = Σ 1/Π…로 s = 1/(βλ²)(복소수)를 구하면 |s|가 크기, arg s가 회전이다. 끝 화면은 이 사본이 똑바로 서도록 돌리고(main.js:213), 핵이 아니라 몸통(c′ = −0.75)이 가운데 오도록 중심을 s·(−0.75)만큼 옮긴다(main.js:214).
  3. 섭동 반복 (GPU, float32) (main.js:111). 픽셀마다 기준 궤도에서의 작은 차이만 δ ← 2Zδ + δ² + δc로 반복한다. δc ~ 10⁻¹⁵는 float32로 충분히 표현된다 — 정밀도가 필요한 것은 기준 궤도뿐. 미분 dz/dc도 함께(픽셀 크기로 축척해 넘침 없이) 추적한다.
  4. 글리치 방지 — Zhuoran 재기준(rebasing) (main.js:128). |Z + δ| < |δ|(픽셀 궤도가 기준보다 0에 더 가까움 → δ의 상대 정밀도 손실 신호)이거나 기준 궤도 끝(m = p)에 이르면 δ = z, m = 0으로 기준 궤도의 처음부터 다시 따라간다. 기준 궤도 하나로 화면 전체가 글리치 없이 그려진다.
  5. BLA(쌍선형 근사)로 반복 건너뛰기 (main.js:216–main.js:246, 셰이더 main.js:94). δ²가 무시될 만큼 작을 때 δ → Aδ + Bδc가 2^l 반복을 한 번에 건너뛴다. 단일 단계 A = 2Z_m, B = 1, 유효 반경 R = ε|Z_m|(ε = 2⁻²³), 두 단계 병합은 A = A_y A_x, B = A_y B_x + B_y, R = min(R_x, (R_y − |B_x|·|δc|max)/|A_x|). 반경은 화면 크기(|δc|max)에 따라 매 프레임 다시 계산해 R 텍스처만 갱신한다(main.js:302). 끝 화면의 픽셀당 반복 ~5000–6000회가 루프 ~1400걸음이 된다 (JS로 같은 알고리즘을 돌려 확인: 무BLA float 섭동과 같은 수준의 오차).
  6. 내부 판정: 넓은 화면에서는 주 심장형·주기 2 원판의 해석식(main.js:84), 깊은 화면에서는 m = p마다(Z_p = 0이므로 z = δ가 미니브로트 자신의 궤도 점) Brent 순환 검사(main.js:122). 나머지는 걸음 상한 2500.
  7. 색 (main.js:133–main.js:143). 매끈한 반복 수 ν = n + 1 − log₂(ln|z|/ln2)를 √ν와 ln ν로 섞어 순환 팔레트 (먹 → 코발트 → 청록 → 크림 → 금 → 주홍 → 장미 → 자두)를 읽고, 법선 맵 u = z/z′의 조명(입체감)과 거리 추정 DE = |z| ln|z| / |z′|(픽셀 단위)로 경계를 어둡게 — 가는 필라멘트가 잉크 선처럼 남고 계단도 줄어든다.
  8. 줌 (main.js:179). ln r(t)는 0.3초 정지 → 1초 3차 가속 → 6초 일정 속도 → 2.3초 3차 감속(이음매에서 속도 연속). 즉 r = exp(ln-스케일 함수) — t의 순수 함수. 회전도 t의 함수(main.js:186).
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 기준 궤도·BLA 계수는 setup에서 한 번(정수 연산이라 매번 같다). 프레임마다 바뀌는 것은 r(t), 회전, BLA 반경뿐.
  • 셰이더는 상태가 없다. 그레인은 좌표와 round(t·30) 해시.
