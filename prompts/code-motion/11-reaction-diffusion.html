데모는 영상 파일이 아니라 코드가 지금 그리는 화면이에요. 그래픽 카드를 많이 쓰는 기법이라 미리보기가 버벅일 수 있어요. 해상도를 낮춰 확인하고, MP4 렌더링은 시간이 더 걸려요. 재생 중 스페이스 · 클릭은 멈춤, ← →는 0.5초 이동이에요.

광고 · 쇼츠에서는무늬가 스스로 자라는 배경, 패션 · 뷰티 무드

활용 가이드

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

질감·필터로 쓸 때

화면 전체의 질감·색감을 바꿔 브랜드 무드를 만들 때 써요(필름, 판화, 수채화 등).

  • 질감은 영상 전체에 일관되게. 한 컷만 바꾸면 실수처럼 보여요.
  • 실사 영상 위에 필터로 얹고 싶다면 '이 영상 파일 위에 효과를 입혀'라고 요청해요.
  • 강도를 숫자로 조절할 수 있게 해 달라고 하면 수정이 쉬워요.

영상에 옮길 때 주의

  • 손으로 쓴 WebGL2 셰이더 — 영상 스킬의 WebGL 층(three.js 등) 위에서 다시 쓴다
  • CPU 검증 프레임당 10.2s — 그대로 옮기면 MP4 내보내기가 매우 느리다. 해상도를 낮추거나 미리 굽는다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

어두운 청록 바닥 위, 0초에 씨앗 하나가 희미하게 빛난다. 카메라는 2.3배로 다가가 있고, 씨앗이 호박색 구슬로 부풀었다가 스스로 둘로 갈라지며(유사분열) 고리 모양 군락을 이룬다. 1–3초 사이 다른 씨앗 다섯 개가 화면 밖에서 차례로 싹트고, 카메라가 물러나면 구슬 군락 여러 개가 서로를 향해 자라 화면을 채운다(~4초). 4–6.5초가 절정이다. 첫 씨앗을 중심으로 매개변수 파동이 퍼지면서 구슬이 길쭉해지고 서로 이어져 줄무늬가 되고, 산호 미로로 바뀐다. 색도 호박색에서 산호색으로 넘어가고, 새로 생긴 무늬의 앞쪽 가장자리가 금빛으로 잠깐 빛난다. 그사이 따뜻한 키 라이트가 쓸고 지나가며 젖은 표면에 반사광이 미끄러진다. 6.5–9초는 여운이다. 미로가 자리 잡고 가장자리는 다시 구슬(동물 가죽 무늬)로 돌아가며, 카메라가 천천히 다시 다가가 윤기 있는 관 모양 입체를 보여준다. 위·아래는 피사계 심도로 흐려지고 앞쪽에는 초점이 나간 부유 입자가 떠다닌다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 상태 = RGBA32F 텍스처 하나(360×640): r=u, g=v, a=처음 v>0.18이 된 시각(birth). 핑퐁 두 장(main.js:326).
  • Gray–Scott 한 스텝(main.js:80): 9점 라플라시안(인접 0.2, 대각 0.05, 중심 −1, main.js:90), Du=1, Dv=0.5, dt=1의 명시적 오일러. 경계는 좌표 clamp(노이만). texelFetch만 쓰고 필터링 샘플은 쓰지 않는다. SwiftShader에서 texture()+LINEAR는 2–3배 느렸다. 비디오 1프레임에 110회 반복(main.js:28, 9초 동안 29,700회).
  • 공간·시간에 따라 변하는 feed/kill(main.js:65): 첫 씨앗에서 퍼지는 파동 wave(n)(main.js:249)와 fBm 노이즈로 p∈[0,1]을 만든다. p=0은 유사분열 구슬(f=0.0367, k=0.0649), p=1은 산호(f=0.0545, k=0.062)이고, 그 사이에 벌레/줄무늬 영역이 있다. outer(n)(main.js:250)은 끝무렵 가장자리를 다시 구슬로 되돌린다. 매 스텝 파라미터 텍스처로 한 번 굽는다.
  • 씨앗(main.js:18, main.js:51, main.js:339): rand(11)로 위치를 흔든 6개의 원반. 정해진 스텝 번호에 v를 주입하며, 가장자리는 각도 노이즈로 들쭉날쭉하게 만든다. 첫 씨앗은 init()에서 심는다.
  • 표면 렌더(매 프레임, 시뮬레이션 해상도에서): 1. 마스크 패스(main.js:100): v를 smoothstep으로 날카로운 무늬 마스크로 바꾸고, birth로부터 "갓 자란" 글로우를 만든다. 2. 마스크를 가우시안 블러(분리형 2패스)한 것을 높이로 쓴다. 고원(plateau)이 둥근 돔이 되어 관·구슬처럼 보인다. 그 기울기로 노멀을 만든다(main.js:110). 3. 4× 다운샘플 + 블러(main.js:121, main.js:135): AO, 블룸, "도달한 영역" 마스크, 재질 p.
  • 최종 셰이더(main.js:148): 4탭 3차 B-스플라인 업샘플(main.js:154)로 3–7배 확대에도 텍셀 각이 보이지 않게 하고, fwidth 기반 재임계(main.js:185)로 줌과 무관하게 경계를 선명하게(안티에일리어싱 포함)유지한다. 쓸고 지나가는 키 라이트(wrap diffuse) + 차가운 필 + Blinn 스페큘러 두 겹 + AO(main.js:200–211), 빛 웅덩이(main.js:203), 피사계 심도(초점 띠 밖은 블러된 높이로 섞기, main.js:181), 성장 글로우와 블룸(main.js:216), 낮은 주파수의 색조 변화(main.js:192), 초점 나간 부유 입자(main.js:165), 톤매핑·비네트·그레인.
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • replay({ dt: 1/30, every: 30 })(main.js:345): 비디오 프레임 하나 = 스텝 하나(110회 반복). 스텝 내용은 n만의 함수다 (씨앗 스케줄, wave(n), outer(n), birth 시각 = n/30/9).
  • save()는 새 RGBA32F 텍스처를 만들어 blitFramebuffer(NEAREST)로 GPU 안에서 복사하고, load()는 거꾸로 복사한다 (main.js:365–366). 체크포인트 0은 씨앗을 심은 직후 상태라서, 루프가 끝나 0으로 돌아가면 이것이 복원된다.
  • 렌더 전용 텍스처(마스크, 블러, 파라미터)는 매 프레임 n으로부터 다시 만든다. 파라미터 맵도 렌더에서 다시 계산하므로(main.js:371) 체크포인트 로드 뒤에 낡은 값이 남지 않는다.
  • 하네스 우회: 헤드리스에서만(?render) 스텝마다 1픽셀 readPixels로 GPU를 기다린다(main.js:360). 이게 없으면 긴 seek의 GPU 작업이 전부 스크린샷 쪽으로 밀려 Playwright의 30초 스크린샷 타임아웃에 걸렸다. 라이브 재생에서는 실행하지 않는다.
  • 결과: 앞→뒤 / 뒤→앞(새 페이지) / 점프백 모두 픽셀 일치(deterministic: true).
한계와 조절할 점
  • 명시적 오일러라 Du·dt가 안정 한계에 가깝다. 무늬 크기는 격자 셀 수(약 10셀)로 정해지므로 화면에서의 크기는 해상도로만 조절된다.
  • 360×640을 3배 업샘플한다. 경계 재임계로 선명하지만 아주 가는 구조는 표현할 수 없다. 실제 GPU라면 720×1280으로 올릴 만하다.
  • 높이를 블러한 마스크로 근사하므로, 엄밀한 의미의 3D 표면(자기 그림자, 시차)은 없다. 다음 단계로 높이 기반 스크린 공간 그림자나 비스듬한 카메라(perspective tilt)와 레이마칭 릴리프를 해 볼 만하다.
  • 매개변수 파동은 손으로 짠 스크립트다. 이미지(글자, 로고)를 feed/kill 맵으로 써서 "무늬가 글자를 그리는" 연출로 확장할 수 있다.
