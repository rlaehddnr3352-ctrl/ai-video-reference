활용 가이드

배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

영상에 옮길 때 주의

  • Tone.js: 영상 스킬에 없는 라이브러리라면 원리만 가져와 Canvas 2D·SVG·WebGL로 직접 쓴다
  • 소리 — 소리를 쓸지는 영상 스킬의 규칙을 따른다. 소리에 그림을 맞추는 방식을 참고한다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

9.6초, 1080×1920. 크림색 종이 위에 칸딘스키·바우하우스풍 구성이 음악과 함께 한 겹씩 쌓인다. 빨강·파랑·노랑과 검은 선을 쓴다. 아래 320px은 검은 띠이고, 그 안에 이 곡의 악보가 가는 줄무늬로 깔려 있다. 붉은 재생선이 지나가면 연주된 음표가 밝아진다. 처음에는 위쪽에 "▶ 소리를 들으려면 화면을 누르세요" 알약이 뜬다(데모 29와 같은 방식).

  • 1마디(0–2초): 첫 킥(점) 하나에 검은 원이 튀어나오며 고리를 하나 내보낸다. 패드 화음(Fmaj9)과 함께 큰 노란 원 면이 종이에 스며든다. 멜로디 네 음이 대각선 아래쪽에 파란 ¾ 호와 빨간 반원 호로 하나씩 돋아났다가 흐려진다. 마디 끝 하이햇 두 번에 짧은 획 두 개가 돌며 자리 잡는다.
  • 2마디(2–4초): 킥이 반박으로 들어오고 원이 한 단계 커진다. 기울어진 파란 사각 면(Dm9)이 깔린다. 베이스가 들어와 아래쪽에 두꺼운 검은 막대가 오른쪽에서 미끄러져 박힌다(높이 = 음높이, 가로 위치 = 시각). 엇박 하이햇이 획 격자를 채운다.
  • 3마디(4–6초), 고조: 원 둘레에 빨간 후광이 차오르고, 킥이 네 박이 된다. 빨간 반원 면(B♭maj9)이 깔린다. 박수마다 긴 검은 선이 화면을 가로질러 그어지고, 시작점에 빨간 사각형이 돌며 찍힌다. 멜로디가 올라가며 대각선 위쪽에 노란 삼각형이 나타난다.
  • 4마디(6–8초), 절정: 16분 하이햇이 획 격자를 빠르게 채운다. 킥은 필인까지 몰아친다. 멜로디가 D6에서 정점을 찍는다(검은 테 노란 삼각형). 오른쪽 위에 연한 파란 삼각 면(C9sus4)이 깔린다.
  • 8초, 해결: 마지막 화음(F-A-C, Fmaj9, 낮은 F)이 울린다.
  • 원이 탄성 있게 마지막으로 커지며 큰 고리를 내보내고, 모든 색면이 한 번 피어오른다.
  • 낮은 F는 파란 바닥선이 되어 화면 폭을 가로질러 그어진다. 마지막 세 음은 흐려지지 않고 남는다.
  • 8.6초부터는 고리가 사라지고, 그때까지 쌓인 모든 것이 한 장의 정지된 구성으로 남는다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리

1. 악보 하나, 감각 둘 (score.js) - 120 BPM, 4/4, F장조. 킥·하이햇·박수·베이스·멜로디(F장조 5음 음계)·패드를 { t, d, m, v } 목록으로 적었다. - 소리와 그림은 모두 이 목록에서 나온다. 그림은 오디오를 분석하지 않는다. 데모 29가 FFT 분석표를 읽은 것과 반대 방향이다.

2. 소리: Tone.Offline (synth.js:17) - setup에서 Tone.Offline(…, 9.6 s, 2ch, 44.1 kHz) 안에 악기를 만들고 악보대로 예약해 AudioBuffer 한 개로 굽는다.

파트 악기
킥 MembraneSynth(F1, 피치 하강 사인, synth.js:42)
하이햇 MetalSynth(FM 금속 배음 + 고역 통과, synth.js:46)
박수 NoiseSynth 세 번 연타 → 대역 통과(synth.js:52, synth.js:87)
베이스 MonoSynth(톱니파 + 24 dB 저역 필터 엔벨로프, synth.js:57)
멜로디 PolySynth(FMSynth) 벨 소리 + 점8분 FeedbackDelay(synth.js:62)
패드 PolySynth(Synth) fatsawtooth + 저역 필터(synth.js:75)
  • 잔향: Convolver에 시드 난수로 만든 2.2초 스테레오 임펄스 응답을 넣는다(synth.js:38). 지수 감쇠이고 꼬리로 갈수록 어두워진다. Tone.Reverb처럼 내부 난수로 IR을 만들지 않는다.
  • 마무리: 마지막 0.45초는 페이드아웃해서(synth.js:24) 반복 재생 이음매가 깨끗하다. 결과는 문맥에 묶이지 않는 AudioBuffer로 복사해 둔다.
  • 재생: 데모 29의 onTransport 방식(main.js:86). 재생이면 그 시각부터 AudioBufferSourceNode를 새로 시작하고, 정지면 멈춘다. AudioContext는 첫 클릭 뒤에 resume된다. 헤드리스 검증(?render)에서는 재생기를 만들지 않는다.

3. 그림: 일시정지된 GSAP 타임라인 하나 (main.js:139) - setup에서 음표 목록을 돌며 gsap.timeline({ paused: true })에 트윈을 넣는다. frame(t)는 tl.time(t, true) 후 SVG 속성을 쓴다(main.js:363). - 트윈 대상은 DOM이 아니라 작은 상태 객체 { s, r, o, x, … }다. 렌더 함수가 그 값을 SVG transform/opacity에 옮긴다(값이 바뀔 때만 setAttribute). - 같은 속성에 여러 펄스가 겹치는 경우(킥이 원을 튕기는 것)를 펄스마다 객체 하나로 두고 합산할 수 있다(main.js:194). - 매핑: 칸딘스키의 바우하우스 설문(노랑–삼각형, 빨강–사각형, 파랑–원)과 『점·선·면』을 따른다.

소리 모양
킥 검은 원(main.js:187). 킥마다 0.15·세기 만큼 튕기고(power3.out 감쇠) 고리 하나를 expo.out으로 내보낸다(main.js:208). 원 크기는 마디마다 계단식으로 자라고(main.js:189), 마지막 화음에서 elastic.out으로 커진다.
하이햇 6열 격자(−18° 회전, main.js:225)의 짧은 획. 칠 때마다 하나가 생기며 rest+110° → rest로 back.out(2.2) 회전해 자리 잡는다(헤링본). 정박의 획은 빨강.
박수 미리 정한 긴 선 넷(main.js:245)이 stroke-dashoffset으로 0.26초 만에 그어지고, 시작점의 빨간 사각형이 back.out(3)으로 돌며 찍힌다.
베이스 두꺼운 막대. y = 음높이, x = 시각(main.js:277), 너비 = 길이. 오른쪽 150px에서 power4.out으로 미끄러져 들어오고 두께가 1.7 → 1로 가라앉는다. 마지막 낮은 F는 화면 폭의 파란 바닥선이다.
멜로디 낮은 음(왼쪽 아래) → 높은 음(오른쪽 위) 대각선 위에 놓인다(main.js:23). 같은 음이 반복되면 축에 수직으로 ±110, ±205씩 비켜 놓는다(main.js:297). 음역별 모양: G5 이상 노란 삼각형(main.js:301), C5–F♯5 빨간 반원 호(main.js:305), 그 아래 파란 ¾ 호. 음이 울리면 0 → 1.18 → 1로 자라며 회전해 들어오고, 끝나면 0.3까지 흐려져 흔적으로 남는다(main.js:317).
패드 화음마다 큰 색면 하나(main.js:151): 노란 원, 기운 파란 사각, 빨간 반원, 연한 파란 삼각. 면마다 자기 <svg> 레이어이고 CSS mix-blend-mode: multiply(main.js:159)로 종이 결 위에 인쇄된 것처럼 겹친다. 투명도·배율은 CSS로 바꾼다(합성기에서 처리, SVG 재래스터 없음). 마지막 화음의 피어오름(fin, main.js:148)이 모든 면에 더해진다.
  • 악보 띠: 아래 검은 띠에 다섯 줄(패드·멜로디·베이스·하이햇·킥, main.js:325)로 음표를 그린다. 재생선은 타임라인의 선형 트윈(main.js:337)으로 움직이고, 지나간 음표는 불투명해진다.
  • 종이: 2D 캔버스에 시드 난수로 한 번 그린다(main.js:46) — 얼룩, 섬유, 낟알, 가장자리의 옅은 갈변.

참고: - Kandinsky, W. Punkt und Linie zu Fläche (1926); 바우하우스 색-형태 설문(1923) - Tone.js 문서: Offline, MembraneSynth, MetalSynth, MonoSynth, PolySynth, Convolver - GSAP 문서: Timeline time(), fromTo, immediateRender

프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 그림은 악보에서만 나온다. 오디오 버퍼는 그림에 쓰이지 않는다. 박수의 NoiseSynth는 실행마다 소리가 조금 다르지만 그림에는 영향이 없다. 잔향 IR은 rand(8282)로 만들어 매번 같다.
  • GSAP: 모든 트윈을 fromTo + immediateRender: false, lazy: false, overwrite: false로 만든다(main.js:140).
  • 한 속성의 트윈들은 하나의 연속 사슬이다: 각 트윈의 from = 그 속성이 트윈 직전에 갖는 값(처음이면 객체의 초기값).
  • 그래서 GSAP가 되감기 때 "시작값"을 쓰든 "트윈 이전 값"으로 되돌리든 같은 값이 된다. 앞→뒤, 뒤→앞, 새 페이지 어느 순서로 tl.time(t)를 불러도 상태가 같다.
  • 펄스(킥 튕김, 마지막 화음 피어오름)도 0 → 진폭(0.012초) → 0의 두 트윈 사슬이라 불연속이 없다.
  • 렌더 함수는 상태 객체만 읽는다(이전 프레임의 DOM 값을 읽지 않음). 속성 쓰기 캐시는 같은 값을 다시 쓰지 않을 뿐 결과를 바꾸지 않는다.
  • 난수는 rand(seed)만 쓴다: 종이(1925), 획 각도 흔들림(4711), 멜로디 위치 흔들림(906), IR(8282). GSAP random()과 Tone 내부 난수에 그림을 맡기지 않는다. performance.now는 소리 동기화(main.js:86)에만 쓴다.
한계와 조절할 점

한계 - 멜로디 위치는 음높이와 반복 횟수만으로 정한다. 같은 음이 다섯 번 넘게 나오면 겹친다(지금 악보는 최대 4번). - 패드 면은 CSS 합성이라 GPU가 없는 환경에서는 블렌드 비용이 크다. 헤드리스 CPU 래스터에서는 느릴 수 있다. - 소리는 첫 클릭 전에는 나지 않는다(브라우저 정책). 출력 지연(outputLatency)만큼 앞당겨 시작하지만, 블루투스 출력에서는 어긋날 수 있다. - 박수 소리(NoiseSynth)는 실행마다 미세하게 다르다(그림과 무관).

조정 손잡이 - 악보 전체 score.js — 음 하나를 바꾸면 소리와 그림이 함께 바뀐다. 길이 score.js:9. - 음색: 킥 synth.js:42, 하이햇 synth.js:46, 베이스 synth.js:57, 멜로디 synth.js:62, 패드 synth.js:75, 잔향 양 synth.js:39. - 색 main.js:21. 킥 원의 위치·크기 main.js:22, 성장 계단 main.js:189, 튕김 세기 main.js:194. - 멜로디 축 main.js:23, 음역 범위 main.js:24, 반복 음 간격 main.js:297, 흔적 투명도 0.3 main.js:317. - 하이햇 격자 위치·간격·회전 main.js:225. 박수 선 main.js:245. 베이스 막대 배치 main.js:277. - 색면 모양·최고/휴지 투명도 main.js:151.
