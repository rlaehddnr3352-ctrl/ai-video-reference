데모는 영상 파일이 아니라 코드가 지금 그리는 화면이에요. 그래픽 카드를 많이 쓰는 기법이라 미리보기가 버벅일 수 있어요. 해상도를 낮춰 확인하고, MP4 렌더링은 시간이 더 걸려요. 재생 중 스페이스 · 클릭은 멈춤, ← →는 0.5초 이동이에요.

#026 · 아날로그 표현

동판에 새긴 달

WebGL2 셰이더 · 명암을 선의 굵기로 (판화 해칭)

질감·필터무거움 · 그래픽 카드 사용
광고 · 쇼츠에서는지폐 · 고급 인쇄물 같은 해칭 질감 (위스키 · 명품)

활용 가이드

질감·필터로 쓸 때

화면 전체의 질감·색감을 바꿔 브랜드 무드를 만들 때 써요(필름, 판화, 수채화 등).

  • 질감은 영상 전체에 일관되게. 한 컷만 바꾸면 실수처럼 보여요.
  • 실사 영상 위에 필터로 얹고 싶다면 '이 영상 파일 위에 효과를 입혀'라고 요청해요.
  • 강도를 숫자로 조절할 수 있게 해 달라고 하면 수정이 쉬워요.

영상에 옮길 때 주의

  • 손으로 쓴 WebGL2 셰이더 — 영상 스킬의 WebGL 층(three.js 등) 위에서 다시 쓴다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

10초. 등불 아래 호두나무 작업대에 광택 나는 동판이 놓여 있다(0–0.6초 밝아짐). 판 위로 창빛 반사가 천천히 흐른다.

  1. 조각 (0.15–3.5초). 테두리 괘선이 먼저 한 바퀴 그어지고, 괘선기로 하늘의 가로줄이 위에서 아래로 깔린다(달 주변은 선이 가늘어져 달무리가 된다, 별 자리는 비워 둔다). 이어서 뷰린이 달의 선을 한 줄씩, 끝에서 끝으로 판다. 파인 홈은 어두운 구리색이고 등불 쪽 벽에 밝은 테가 서며, 지금 파고 있는 선의 끝에는 깎여 말린 구리(버)가 반짝인다. 2초부터 교차 해칭, 2.5초부터 가장 어두운 곳의 세 번째 해칭, 마지막에 글자(SELENOGRAPHIA). 동판이므로 그림은 좌우가 뒤집혀 있다.
  2. 잉크와 닦기 (3.55–4.8초). 탐폰으로 두드린 잉크가 얼룩지며 판 전체를 덮고, 탈라탄 천이 대각선으로 닦아 낸다. 판 면은 다시 구리색이 되지만 닦인 결 방향의 얇은 막(plate tone)과 판 가장자리에 고인 잉크가 남고, 홈 속 잉크는 까맣게 남는다.
  3. 종이 (4.85–6.3초). 물에 적신 종이(가장자리가 너덜한 수제지)가 위에서 내려와 판을 덮고, 오른쪽 아래 모서리부터 젖혀 지며 찍힌 면이 드러난다. 이제 그림은 바로 선다.
  4. 판화 (6.3–10초). 크림색 레이드지(가는 발 자국과 체인 선), 판이 눌린 자리의 판 자국(plate mark) 엠보싱, 닦기 결이 남은 옅은 판 톤, 판 아래 연필 메모(7 / 30 · Luna · imp.). 6.6초부터 빛이 달을 돌아 차오른 달(오른쪽에서 빛) → 보름 → 그믐 초승달(왼쪽에서 빛)로 바뀌고, 모든 선의 굵기가 연속으로 따라 변한다 — 보름에는 고원의 선이 점과 짧은 획으로 사라지고 바다(마리아)와 광조만 남으며, 초승달에서는 원반 대부분이 세 겹 해칭으로 덮인다. 9.2초부터 선명한 판화로 멈춘다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리

셰이더는 shader.js(프래그먼트 하나, 전체 화면 삼각형 하나), 데이터와 시간표는 main.js.

  1. 달은 그림이 아니라 "어둡기 D"를 계산하는 함수(shader.js:75 moonDark). 화면 원반 → 구면 점 s(shader.js:252). - 크레이터 150개(main.js:75, 실제 이름 있는 23개 main.js:49 + 멱법칙 크기의 무작위 127개, 바다 위에는 덜 생기게 main.js:83)를 RGBA32F 텍스처 한 장(main.js:175)에 넣고 texelFetch로 돈다. 단면은 포물선 사발 + 가우시안 테 + 중앙봉, 범람한 바닥은 평평하게 자른다. 높이와 기울기를 해석적으로 함께 누적해(shader.js:107) 법선을 한 번에 얻는다 (유한차분 3회 대신 1회). - 테의 그림자(shader.js:95): 바닥 점에서 태양 방향으로 사발 원과 만나는 거리 tr을 닫힌식으로 구하고, tr·tan(태양 고도) 와 테 높이를 비교한다. 명암 경계(터미네이터) 근처 크레이터 바닥이 까맣게 잠긴다. - 바다 18개를 실제 위·경도의 가우시안 덩어리 + fBm 가장자리로(shader.js:58, main.js:39), 티코·코페르니쿠스의 광조를 방위각 사인 합의 줄무늬로(shader.js:65). - 반사: 람베르트와 로멜–젤리거를 섞어(shader.js:115) 보름달이 가장자리까지 밝게, 밤 면에는 지구조(shader.js:119).
  2. 판화가의 말로 옮기기: 선 가족 세 개(shader.js:129 famCoord). 각 가족은 기울어진 축에 대한 위도선이라 구를 감싸며 타원으로 휘고, 위도에 크레이터 높이를 더해(shader.js:262) 선이 사발 안으로 꺾여 들어간다(등고선처럼 표면을 따름). 축과 경도 기준 e1은 경도 이음매(±π)가 달 뒤편에 가도록 고른다(main.js:26).
  3. 선 하나의 모양(shader.js:137 famInk). 원하는 잉크 비율 c(= 선 폭/간격)가 D에 비례한다(shader.js:267). - 밝은 톤에서는 선이 렌즈 모양 짧은 획(flick)으로 끊기고, 톤이 짙어질수록 획이 길어져 이어진 선이 된다(shader.js:149). 획의 폭 1−u², 뷰린 압력의 완만한 부풂(press) — 그래서 선 끝이 부풀었다 가늘어진다. - 안티에일리어싱 = 정확한 박스 필터(shader.js:159): fwidth(v)로 한 픽셀이 몇 간격인지 알고, 선 구간 [−hw, hw]와 픽셀 구간의 겹친 길이를 그대로 쓴다. hw→0이면 잉크도 정확히 0이라 가는 선이 회색 안개로 번지지 않는다. 선이 3px보다 촘촘해지는 가장자리에서는 평균 톤으로 넘어간다(shader.js:162). - 교차 해칭: B 가족은 D>0.40부터, C 가족은 D>0.68부터(shader.js:267–269). 중간 톤 전이에는 A 선 사이에 점각 (shader.js:165, D 0.1–0.5에서만 반지름이 0이 아님). - 조각 과정: 선마다 시작 시각(위에서 아래로, 손의 흔들림 약간)과 진행률이 있고, 경도가 뷰린 끝(tip)을 넘지 않은 부분만 나타나며 끝 5간격은 가늘어진다. 진행 중인 선 끝에 버(burr)의 반짝임(shader.js:142).
  4. 하늘·테두리·글자. 하늘은 5.6px 간격의 기계 괘선(정확한 박스 필터, 위에서 아래로 한 줄씩 왼→오른쪽으로 그어짐), 달 둘레 160px에서 선이 가늘어져 달무리(밝은 위상일수록 강하게), 별은 3×3 칸을 합산한 해시 격자 위의 십자형 빈칸(shader.js:182). 글자는 setup에서 Canvas 2D로 텍스처에 한 번 써 두고(main.js:99, 빨강=새긴 글자, 초록=연필), 같은 설계 좌표 q로 읽으므로 판 위에서는 함께 뒤집힌다(shader.js:250).
  5. 재료. 동판: 창빛 반사 띠 + 연마 긁힘 노이즈 + 경사진 베벨(shader.js:209). 홈: 잉크 덮임률의 화면 기울기(dFdx/dFdy)를 등불 방향과 내적해 홈 벽의 밝은 테를 만든다(shader.js:313). 잉크: 얼룩진 fBm 문턱으로 번지고(shader.js:307), 대각선 닦기 전선 뒤로는 회전·늘인 fBm 결의 잔막만 남는다(shader.js:310). 종이: 섬유 fBm + 발 자국(4.4px 사인) + 체인 선 + 티끌, 높이의 유한차분으로 사광 음영(shader.js:230). 판 자국은 둥근 사각 SDF를 높이로 써서 같은 사광으로 엠보싱하고, 안쪽은 눌려 결이 35%로 약해진다(shader.js:335). 찍힌 잉크는 같은 기울기 트릭을 반대로 써 돋은 선의 윗벽이 살짝 빛난다(shader.js:346).
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 상태 없음. 모든 단계(조각 진행 3종, 괘선, 글자, 잉크, 닦기, 종이, 젖힘, 빛의 방위각)는 track()으로 만든 t의 순수 함수이고 (main.js:124–135), 매 프레임 uniform으로 넘긴다(main.js:192).
  • 크레이터 배치는 rand(2611)로 setup에서 한 번. 셰이더 노이즈는 좌표 해시뿐(시간 성분 없음).
  • 판 단계와 판화 단계의 좌표계 전환(거울상)은 젖힘이 시작되는 순간 한 번에 일어나는데, 그때는 종이가 판을 완전히 덮고 있다 (main.js:198). 모든 미분(fwidth/dFdx)은 균일 제어 흐름에서 계산한다.
한계와 조절할 점
  • 달은 정사영 구 하나이고 크레이터 밖으로 드리우는 긴 그림자(터미네이터의 산맥 그림자)는 없다 — 바닥 그림자만 있다.
  • 선 가족은 고정된 세 축의 위도선이다. 진짜 판화가는 형태마다 방향을 바꾸므로(크레이터 둘레를 도는 선 등), 크레이터별 국소 좌표계로 선 방향을 섞으면 더 손맛이 날 것이다.
  • 종이 젖힘은 실제 종이 말림을 기하로 풀지 않은 근사(띠 모양 원통 음영 + 그림자)다.
  • 글꼴은 사용자 시스템의 세리프에 따른다(Garamond 계열이 없으면 Times/Georgia).
  • 빛이 도는 동안 잉크가 "다시 찍히는" 것은 물리적으로 불가능한 연출이다 — 같은 판을 다른 위상으로 새긴 연작을 이어 보는 셈.
