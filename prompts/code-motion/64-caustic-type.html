빛으로 쓴 글자

역설계 커스틱(최적 수송·포아송 반복) · 광자 메시 래스터화 · 분산

제목·로고무거움 · 그래픽 카드 사용
광고 · 쇼츠에서는빛으로 맺히는 글자 (주얼리 · 조명 · 향수)

활용 가이드

제목·로고로 쓸 때

영상 첫 1–2초, 브랜드명이나 핵심 제목이 처음 나오는 순간에 써요.

  • 제목은 한 줄, 6–10자 안쪽이 가장 잘 보여요.
  • 기법이 끝난 뒤 0.5–1초는 글자를 멈춰 읽을 시간을 주세요.
  • 로고라면 브랜드 색 2–3개만 지정하면 나머지 톤은 AI가 맞춰요.

영상에 옮길 때 주의

  • 손으로 쓴 WebGL2 셰이더 — 영상 스킬의 WebGL 층(three.js 등) 위에서 다시 쓴다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

어두운 방의 엷은 트래버틴 바닥(줄눈이 있는 큰 석판, 결 무늬, 작은 기공)에 높은 창으로 든 햇빛이 1 : 1.5 직사각형으로 떨어진다. 처음에는 창에 얹힌 물결 면을 지난 빛이 어지러운 커스틱 그물로 춤춘다. 물이 잦아들면서 그 빛이 흘러 모여 세 줄의 시가 된다.

빛이 / 머문 / 자리

글자마다 획 가장자리를 따라 날카로운 빛의 선이 서고, 획 안에는 빛 웅덩이가 고인다. 둘레는 빛을 빌려 준 만큼 어둡다. 절정(≈ 6.1–6.4초)에는 분산 때문에 획 가장자리에 무지개 테가 생기고 블룸이 가장 크다. 여운에서는 물이 아주 조금 숨 쉬듯 일렁여 글자가 살아 있는 빛처럼 떨린다. 햇빛은 서서히 금빛으로 기울고 끝에서 어두워진다. 먼지 낀 공기 속 빛기둥이 화면 위쪽에서 비스듬히 내려온다. 바닥 가까이에서는 글자 모양을 머금고, 위로 갈수록 고르게 퍼진다. 빛기둥 안에서는 먼지 알갱이가 반짝인다. 초점 면에서 먼 알갱이는 큰 보케가 되어 깊이를 만든다. 카메라는 천천히 다가간다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리

1. 역설계 — 원하는 밝기 → 렌즈 (design.js, setup에서 CPU로 한 번) - 목표 밝기 main.js:40 - 글자를 Noto Serif KR 800으로 2배 래스터(main.js:291)하고 서브픽셀 거리장 signedDistance를 구한다(main.js:304). - 거리 d(설계 칸 단위)의 함수로 밝기를 정한다: - 획 안의 웅덩이: 2.4 · sigmoid - 가장자리 바로 안쪽의 빛 선: 4.2 · gauss - 바닥: 0.17, 글자 둘레는 50 %까지 어두운 해자 - 2×2 표본을 평균해 256 × 384 설계 칸으로 내린다. 평균을 1로 맞추면 대비는 약 0.15 … 8배다. - 관례 (Ferraro) - 목표면에는 정규 격자 칸, 렌즈면에는 같은 위상의 변형 메시를 둔다. 렌즈 칸 (i, j)가 받은 빛은 목표 칸 (i, j)로 간다. - 그러므로 렌즈 칸 넓이 = 목표 밝기이면 그림이 맞는다. - 렌즈 꼭짓점은 p = q + ∇v(셀 중심 퍼텐셜 v의 기울기 사상)다. 그래서 실제 굴절면(높이 ∝ v)으로 만들 수 있다. - 반복 design.js:204 1. 칸 넓이를 구한다. 사변형의 넓이는 평균 야코비안 J = I + H의 행렬식과 정확히 같다. H는 꼭짓점 기울기가 함의하는 3×3 스텐실 헤시안이다(design.js:147). 2. 손실을 구한다(design.js:217): √(trJ² − 4detJ + 4I) − trJ ≈ −2(넓이 − I)/trJ. Ferraro의 (넓이 − 목표)에 칸의 늘어남을 반영한 축척을 곱한 것이다. 3. 포아송 방정식 ∇²δ = 손실을 푼다(design.js:223). 노이만 경계라 테두리 꼭짓점은 테두리를 따라 미끄러진다. 4. v += δ: 모든 꼭짓점이 ∇δ만큼 움직인다(design.js:224). - 고정점에서는 모든 칸이 정확히 det J = I다. Benamou–Froese–Oberman의 det D²u = f 고정점 반복을 메시 자신의 이산 헤시안 위에서 돌린 것이다. - 포아송 풀이기 design.js:87 - x 방향은 DCT-II로 풀고(길이 256, Makhoul 방식의 FFT 한 번), 각 x 모드는 y 방향 삼중대각을 Thomas 알고리즘으로 정확히 푼다. - 모드 0(순수 노이만, 특이)은 플럭스 적분으로 처리한다. 256 × 384 한 번에 ≈ 3.5 ms다. - node 단위 점검 (스크래치 스크립트, 데모 폴더 밖) - DCT는 직접 공식과 1e-14, 왕복 7e-16로 일치한다. 포아송 잔차는 8e-12다. - 실제 한글 글리프 목표(Pretendard Bold/Black 윤곽을 래스터)에서는 160회 반복 후 칸 넓이 오차가 rms 0.2 %, 최악 칸 5–7 %다(≈ 0.55 s). 접힘과 뒤집힌 칸은 0개다. - 처음에 쓴 순수 Ferraro 손실(넓이 − 목표, 접힘 직전 절반 보폭)은 고대비 글자에서 보폭이 매 반복 반으로 줄어 rms ≈ 30 %에서 멈췄다. - 역사상 design.js:238 - 렌더러에 필요한 것은 반대 방향이다. 즉 정규 렌즈 격자 576 × 864의 각 점의 빛이 바닥 어디에 떨어지는지다. - 변형된 렌즈 사변형을 두 삼각형이 모두 양수가 되는 대각선으로 나눈다(design.js:269). - 각 삼각형을 덮는 격자점 위에 한 번씩 래스터하고 목표 삼각형을 무게중심 보간한다. 이 구간별 아핀 사상에서는 정확하다. - 점검(node): 이 메시가 그리는 밀도를 목표 칸 중심에서 점 표본하면 밝은 획에서 2.7 %, 어두운 바닥에서 8 % 오차다. 모든 칸 중심이 정확히 삼각형 하나에 덮인다.

2. 광자 메시 래스터화 (main.js:84–117) - 정규 렌즈 격자 메시(삼각형 약 99만 개)의 각 꼭짓점을 바닥 위의 착지점에 놓는다(main.js:104). - 착지점 = L + k_c · (amp · 혼돈 오프셋 + s · (설계 착지점 − L)) - 혼돈 오프셋은 방향 파동 7개(main.js:49)의 높이 기울기 K∇h = Σ(f/k)·cos(위상)·방향이다. 각 파동의 집속 세기 f ≈ 0.26–0.52로 합 ≈ 2.9라서 접힘(커스틱 선)이 생긴다. - 위상 시계 waveClock(main.js:76)은 속도를 1/240초 격자로 적분한 값이다. 물이 느려져도 위상이 튀지 않는다. - 두 사상의 혼합은 물리적이다. - 근축 근사에서 착지 오프셋은 높이 기울기에 선형이다. 그래서 위치를 섞는 것은 두 굴절면을 섞는 것과 같다. - 항등 사상과 기울기 사상 사이의 보간은 McCann의 변위 보간이다. 빛이 찢어지지 않고 글자로 흘러 들어가 점점 초점이 맞는다. - 프래그먼트는 이 텍셀에 내려앉은 렌즈 넓이를 텍셀 넓이로 나눈 역야코비안을 dFdx/dFdy(L)로 구한다(main.js:114). 접힘의 무한대는 30에서 자른다. - 가산 합성이 겹친 층을 더한다. 창 테두리에서는 반그림자(main.js:116)를 준다. - 분산 main.js:420 - R·G·B를 각각 colorMask로 한 번씩 그린다. 굴절 세기는 R 1 − δ, G 1, B 1 + 1.4δ다(δ: main.js:67, 절정에 0.034). - 설계 오프셋이 최대 0.22 패치 폭이므로 가장자리 무지개 테는 ≈ 6 px다.

3. 장면 (main.js:146) - 화면 광선이 바닥 평면과 만나는 점을 구한다. 바닥은 트래버틴이다(main.js:156): 러닝 본드 석판과 안티앨리어싱된 줄눈, 결 띠, 결 방향으로 길쭉한 기공, 화면 미분으로 구한 미세 요철 법선(main.js:193). - 조명: - 커스틱 텍스처(태양 원반만큼의 바이어스 0.35, main.js:198) - 패치가 방으로 되비추는 반사광(밉 6.5에 거리 감쇠, main.js:201) - 차가운 실내 환경광 - 빛기둥 main.js:131, main.js:208 - 시선 광선을 높이로 20단계 진행한다. 각 점을 태양 방향으로 바닥에 투영해 커스틱 텍스처를 높이에 비례한 밉으로 읽는다. - 높이가 수면에 가까워질수록 고른 빛으로 섞는다. 그래서 바닥 근처에서는 글자 모양 빛줄기가 서고 위로 갈수록 퍼진다. - 먼지 main.js:217 - 점 420개를 빛기둥 안에 해시로 흩고 t의 사인으로 떠돌게 한다. - 각자 위치의 빛기둥 밀도로 밝힌다. 초점 거리와의 차로 착란원 크기를 정하고(main.js:239), 에너지는 크기^1.6으로 나눈다.

4. 마무리 (main.js:254) - 밉 체인을 B-스플라인 4탭으로 읽어 블록 없는 둥근 블룸을 만든다(main.js:278). - 지수 톤, 그늘은 차갑게 빛은 따뜻하게 분할 토닝, 비네트, 그레인.

프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 상태가 없다. 매 프레임 세 패스를 처음부터 다시 그리고, 모든 값은 t의 순수 함수다.
  • track 키프레임(main.js:62–75)
  • 위상 시계: 고정 1/240초 격자 적분(main.js:76)
  • 먼지: 정점 ID 해시와 t
  • 빛기둥 지터: 픽셀 해시와 프레임 번호
  • 역설계는 setup에서 한 번 한다. 순수 JS이고 난수가 없어서, 같은 글꼴 래스터면 같은 렌즈가 나온다.
  • 가산 블렌딩은 프리미티브 순서대로 합산되므로 같은 GPU에서 결정적이다.
한계와 조절할 점

자원 - setup: - 역설계 ≈ 0.3–0.6 s - 역사상 ≈ 25 ms - 글꼴 래스터와 거리장 ≈ 0.1 s - GPU 메모리: - 커스틱 RGBA16F + 밉 ≈ 16 MB - 장면 RGBA16F + 밉 ≈ 22 MB - 메시 ≈ 16 MB(인덱스 12 + 착지점 4) - 프레임당 메시 그리기는 삼각형 ≈ 99만 × 3이다. 헤드리스(SwiftShader)에서는 빛기둥을 10단계로 줄인다(main.js:393).

한계 - 렌즈는 근축(얇은 렌즈, 작은 각) 모형이다. 실제로 깎으려면 design.js의 v를 높이로 적분하고 굴절률·거리로 축척해야 한다. - 태양 원반의 크기에 의한 흐림은 텍스처 바이어스로만 흉내 낸다. - 설계 해상도(256 칸 폭)가 글자 가장자리의 날카로움을 정한다. 어두운 바닥은 렌더 격자 대비 설계 칸이 작아서 약 8 % 얼룩이 남는다.
