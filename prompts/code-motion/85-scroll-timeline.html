  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

10초, 1080×1920. 밝은 잡지풍 롱리드 「한 잔의 커피가 오기까지」를 보이지 않는 독자가 읽어 내려간다. 무대 위쪽 1080×1600은 기사가 담긴 스크롤 컨테이너다. 아래 320 px은 짙은 커피색 독서 도크로, 챕터 진행 막대 다섯 개가 있고 그 아래에 하네스 자막이 앉는다. 색은 크림·커피 갈색·잎 초록에 강조색 하나(토마토 주홍)이고, 글꼴은 제목과 숫자가 Noto Serif KR, 본문과 UI가 Pretendard다. 그림은 모두 CSS 도형과 인라인 SVG다.

  • 0–0.8초, 표지: 큰 세리프 제목, 김이 오르는 커피잔(옆모습), 흩어진 원두. 독자가 천천히 내리기 시작하면 원두가 세 겹 깊이로 다르게 떠오르고(시차), 잔은 느리게 물러나며, 김이 피어오르고, "스크롤해서 읽기"가 사라진다.
  • 01 씨앗(0.8–2.15초): 흙 단면에서 뿌리가 그려지고, 줄기가 자라며 씨앗 껍질을 머리에 이고 올라온다. 떡잎이 열리고 본잎이 펼쳐진다. 단계 칩(발아 → 떡잎 → 본잎)이 차례로 켜지고, 숫자가 0 → 3(~4년)으로 센다.
  • 02 농장: 산 세 겹과 계단식 커피나무 줄이 서로 다른 속도로 움직이고(시차), 구름이 지난다. 오른쪽 고도 자에서 주홍 띠(1,000~2,000m)가 차오르고 표식이 올라가며, 숫자가 1,000 → 2,000 m를 센다(천 단위 쉼표 포함).
  • 03 수확: 가지의 체리 열세 알이 하나씩 초록 → 노랑 → 빨강 → 검붉게 익는다. 오른쪽 체리 단면이 반으로 갈라지며 마주 보는 생두 두 알이 드러나고, 껍질·과육·파치먼트·생두 이름표가 붙는다. 숫자는 100 → 20%로 줄고 막대도 함께 줄어든다.
  • 04 로스팅: 온도 곡선(실제 로스팅 프로필의 형태, 0–12분, 25 → 225℃)이 그려진다. 그 끝을 원두 한 알이 따라가며 초록에서 짙은 갈색으로 볶인다. 건조·갈변·발현 구간이 뒤에서 채워지고, 9분(196℃) 지점에서 "1차 크랙" 표지가 튀어나온다. 숫자는 25 → 230℃, 아래 색 띠의 바늘도 함께 간다.
  • 05 한 잔: 위에서 본 잔에 라테 하트가 피어나고 크레마가 돈다. 오른쪽 격자에 원두 70알이 하나씩 튀어 들어오고, 숫자가 그 속도로 0 → 70알을 센다.
  • 8.2–10초, 정리 카드: 짙은 갈색 카드가 붙박인 채, 다섯 줄 요약(3~4년 · 해발 1,000~2,000m · 5kg → 1kg · 200~230℃ · 70알)이 한 줄씩 들어오고, 마지막으로 "오늘 아침의 한 잔에는 몇 해의 시간이 담겨 있다."가 떠오른다.
  • 내내: 위쪽 고정 막대의 주홍 진행 막대가 늘고, 막대 가운데의 챕터 이름이 바뀐다. 각 섹션의 고정 머리말은 막대 바로 아래에 붙어 있다가 다음 섹션에 밀려난다. 머리말 밑줄은 그 섹션을 읽은 만큼 그어진다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리

1. 스크롤 컨테이너와 시계 (main.js) - .reader는 1080×1600, overflow: hidden이다(style.css:30). 휠이나 스크롤바로는 움직이지 않고 scrollTop으로만 움직인다. overflow: hidden도 스크롤 컨테이너이므로 scroll()/view() 타임라인이 그대로 동작한다. - 하네스는 1080×1920 무대를 CSS transform으로 축소하지만, scrollTop과 타임라인 오프셋은 컨테이너의 자기 좌표(무대 px)다. 화면 배율과 상관없이 같은 값이 같은 그림이다. - 독자의 경로 y(t)(main.js:73–main.js:76): 섹션마다 "도착 → 읽기 → 떠남"이다. - 도착: 플릭(cubic-bezier(.55,0,.12,1), main.js:32)으로 0.6초, 빨리 출발해 길게 미끄러져 선다. - 읽기: 0.75초 동안 100 px을 천천히 내린다(smoothstep). 이음마다 속도가 0이라 이어짐이 자연스럽다. - 쉬는 위치는 setup에서 잰다. 글꼴을 기다린 뒤 각 섹션의 offsetTop − 110(고정 막대 높이, main.js:20)이다.

2. scroll() — 진행 막대와 표지 시차 - 진행 막대는 animation-timeline: scroll(nearest block)이다(style.css:40). - 표지의 제목·소개·태양·원두·잔·김(style.css:60, style.css:83, style.css:101)도 scroll(nearest block)이다. animation-range: 0px 1600px처럼 스크롤 px 범위를 쓰고, 원두 세 겹은 이동 거리가 260/520/860 px로 다르다. - 김은 SVG 경로의 stroke-dashoffset(pathLength=1)을 스크롤로 민다.

3. view() — 문단 - 문단은 이름 없는 view()(요소 자신이 대상)에 animation-range: entry 10% cover 52%로 아래에서 떠오른다(style.css:137).

4. 이름 있는 view timeline — 섹션 그림과 숫자 - 섹션마다 view-timeline: --s1 block … --s5를 둔다(style.css:120). 그림·숫자·머리말 밑줄은 그 섹션의 타임라인에서 돈다. - 범위는 "cover N px"이다. cover 범위의 시작(섹션 윗변이 컨테이너 아랫변에 닿을 때)부터 스크롤한 거리다. 섹션 높이를 1520 px으로 고정하고 쉬는 위치를 막대 아래로 정했으므로, 쉬는 순간은 어느 섹션이든 cover 1490px (1600 − 110)이다. 그래서 모든 범위를 그 기준으로 쓸 수 있다. - 1150–1450 px: 플릭이 감속하며 도착하는 동안. - 1450–1550 px: 읽으며 내리는 동안. 숫자는 대개 1380 → 1548 px에서 센다. - 숫자(style.css:147): @property --num { syntax: '<integer>' }(style.css:17)을 @keyframes count { from { --num: var(--from) } to { --num: var(--to) } }로 보간하고, counter-reset: n var(--num) + ::after { content: counter(n) }으로 보인다. 고도(style.css:155)는 등록된 정수 두 개로 나눈다. --kilo = calc((num − 500)/1000)(정수 반올림 = 내림), --rest = num − 1000·kilo, 보이는 형식은 counter(k) "," counter(r, pad3)이다. @counter-style pad3(style.css:21)로 세 자리를 채운다. - 씨앗(style.css:170 이하): SVG 뿌리·줄기의 stroke-dashoffset, 씨앗의 translate, 떡잎·본잎의 scale(transform-box)을 쓴다. - 농장(style.css:207, style.css:223): 산 세 겹이 cover 0%–100%에 30/70/130 px씩 움직인다(시차). 고도 띠는 scaleY다. - 체리(style.css:236): SVG fill을 CSS 키프레임으로 바꾼다. animation-range: cover calc(1250px + var(--i) * 14px) …로 한 알씩 엇갈린다. - 로스팅: 곡선은 stroke-dashoffset이다. 원두는 같은 경로를 offset-path로 따라가고, 등록된 <color> --roast로 볶인다 (style.css:289, 타임라인·범위가 두 개인 목록). 1차 크랙(style.css:300)은 곡선 길이의 78.3% 지점(9분)에서 튀어나온다. - 원두 70알(style.css:338): cover calc(1360px + var(--i) * 2.4px)로 한 알씩, 숫자와 같은 범위에서 들어온다.

5. 고정(sticky) 요소 - 위 막대는 position: sticky; top: 0이다. 섹션 머리말은 top: 110px이고(style.css:126), 다음 섹션의 머리말에 밀려난다. - 정리 카드(style.css:348)는 2500 px 섹션 안에서 top: 150px에 붙는다. 섹션의 이름 있는 타임라인 --sum(style.css:347)이 카드의 줄들을 150 px 간격으로 들여보낸다(style.css:355). 카드 자신은 고정되어 있어 자기 view()로는 진행하지 않는다. 그래서 바깥 섹션의 타임라인을 쓴다.

6. timeline-scope — 컨테이너 밖에서 읽기 - .coffee에 timeline-scope: --s1, …, --sum(style.css:26)을 두어 이름을 끌어올렸다. - 그래서 스크롤 컨테이너 밖에 있는 독서 도크(style.css:367)의 막대(style.css:373)와 글자색(style.css:375), 그리고 고정 막대 가운데의 챕터 이름(style.css:50)이 각 섹션의 view timeline을 따라간다. - 모든 규칙에서 animation 단축형을 먼저 쓰고 animation-timeline을 뒤에 쓴다(단축형이 타임라인을 auto로 되돌린다).

프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 그림은 scrollTop의 순수 함수이고, scrollTop = round(y(t))는 t의 순수 함수다. 시간 기반 CSS 애니메이션, rAF 루프, 난수는 없다.
  • 렌더링 장벽(main.js:88): 헤드리스 Chrome 156에서 숫자로 확인했다.
  • scrollTop을 쓴 직후 getComputedStyle을 읽으면 스크롤 타임라인 값은 이전 위치 그대로다.
  • 한 번 requestAnimationFrame을 기다리면 새 위치 값이 된다.
  • 이유: 브라우저는 프레임의 "update animations" 단계에서 스크롤 타임라인을 표본으로 뜨고, 이 단계는 rAF 콜백보다 먼저 돈다.
  • 그래서 헤드리스 렌더(?render, api.headless)에서는 frame(t)가 scrollTop을 쓰고 rAF 한 번만 기다린다. 이 대기는 상태를 바꾸지 않고 그림이 따라오기를 기다릴 뿐이다.
  • 실시간 재생에서는 기다리지 않는다. 플레이어는 rAF 틱에서 frame()을 부르고, 앞 프레임이 끝나지 않았으면 그 틱을 건너뛴다. frame() 안에서 다음 rAF를 기다리면 그 rAF는 다음 화면 프레임으로 밀리고, 그 프레임의 틱은 "그리는 중"이라 건너뛰어진다. 그래서 한 프레임 걸러 한 번만 그려졌다(60 Hz 화면에서 30 fps). 기다리지 않으면 그리는 화면 프레임이 새 scrollTop을 그대로 반영한다.
  • 헤드리스 수치 점검(스크린샷 없음): t를 0, 0.8, 1.4, 2.15, 2.75, 3.5, 4.85, 6.2, 7.6, 8.2, 9, 9.6, 9.99, 그리고 다시 3.5로 옮겼다.
  • scrollTop, 진행 막대, 다섯 숫자(3, 1000/1/0 → 2000/2/0, 100 → 20, 25 → 230, 0 → 70), 체리 색, 원두의 offset-distance와 색, 챕터 이름, 도크 막대, 요약 줄이 모두 경로대로였다. 3.5초로 돌아가면 처음 값과 같았다.
  • 섹션 위치는 1600 + 1520·i px이었고, 쉬는 순간 머리말은 정확히 y = 110에 붙었다.
  • 단축형이 범위를 덮어쓰지 않는 것도 확인했다(getComputedStyle(...).animationRange).

  • 숫자의 시작·끝 값과 범위: style.css:154–style.css:160.
