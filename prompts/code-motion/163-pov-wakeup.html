활용 가이드

장면 전환로 쓸 때

장면 A에서 B로 넘어가는 0.3–1초 구간에 써요. 컷 사이 이탈을 줄여요.

  • 전환 하나를 영상 전체에 반복해 쓰면 통일감이 생겨요. 매번 다른 전환은 산만해요.
  • 앞 장면의 마지막 프레임과 다음 장면의 첫 프레임을 같이 알려 주세요.
  • 실사 영상 사이에 넣을 땐 투명 배경(알파) 영상이나 두 영상을 직접 합치는 방식으로 요청해요.

캐릭터·연기로 쓸 때

마스코트·캐릭터가 움직이거나 표정 연기를 하는 장면에 써요.

  • 캐릭터 디자인(정면·옆면 그림)을 먼저 정하고 기법은 움직임에만 쓰세요.
  • 동작은 '준비 → 동작 → 여운' 3박자로 적으면 자연스러워요.
  • 말하는 캐릭터는 대사 음성 파일을 주고 입 모양을 맞춰 달라고 해요.

영상에 옮길 때 주의

  • three.js — 영상 스킬이 three.js를 넣는 방법을 따른다

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

어둡고 붉은 감은 눈에서 시작해 눈꺼풀이 무겁게 열리고, 흐린 천장이 두 번의 깜빡임 끝에 또렷해진 뒤, 울리는 토마토색 자명종(7:00)을 내 손으로 끄고 일어나 창가로 걸어가 커튼을 열면 하얗게 넘친 빛이 가라앉으며 햇빛 드는 마을이 나타난다.

팔레트는 아침 방의 크림·모래·나무색, 세이지와 흐린 파랑(이불, 잠옷 소매, 지붕), 그리고 강조색 하나(토마토 #ff5a3c)다. 토마토는 자명종, 장치 칩의 작은 시계, 마지막 "오전 7:00"에만 쓴다. 이야기 내내 돌아오는 장치는 7:00이다. 진짜 자명종의 문자판, 왼쪽 위 칩의 작은 시계(진짜 시계가 울릴 때 같이 떨린다), 마지막 제목의 시각이 모두 7:00이다. 칩에는 지금 쓰는 장치의 이름만 적는다.

시간 t 장치 무엇이 보이나
0–0.3 눈꺼풀 감은 눈. 화면은 거의 검고, 피부를 지난 빛이 어두운 붉은색으로 비친다.
0.3–1.7 눈꺼풀 눈꺼풀이 천천히 0.24까지 열렸다가 0.10으로 다시 처지고(무거운 눈) 다시 열린다. 틈 너머로 흐린 천장과 펜던트 등, 창에서 튕겨 올라온 아침 빛과 나뭇잎 그림자가 번져 보인다.
1.80–2.13 초점 첫 깜빡임: 0.1초에 감기고 0.2초에 열린다. 열릴 때마다 흐림이 반으로 준다.
2.30–2.64 초점 둘째 깜빡임 뒤 눈꺼풀이 화면 밖으로 다 열리고, 2.95초까지 초점이 맞는다. 천장의 잎 그림자가 또렷해진다.
2.72–3.4 고개 돌림 누운 채 고개를 오른쪽으로 돌린다. 천장 → 벽 모서리 → 협탁으로 훑고, 조금 지나쳤다 돌아온다(베개가 가까운 층으로 스친다). 누워 있으니 세상이 옆으로 누워 보인다. 자명종이 떨며 울린다.
3.28–4.3 내 손 화면 아래에서 내 팔이 올라와 자명종 윗단추를 손바닥으로 누른다(3.92–3.98). 울림이 0.06초 시간 상수로 멎고, 칩의 작은 시계도 멈춘다.
4.36–5.0 일어나기 상체를 일으킨다. 시선이 자명종에 붙어 있어 화면이 자명종을 중심으로 90° 돌며 바로 선다. 바로 선 문자판이 7:00을 가리킨다.
5.02–5.9 일어나기 고개를 창 쪽으로 돌리고, 몸을 앞으로 숙였다가 침대 옆에 선다. 커튼 틈으로 들어온 햇빛 띠가 벽과 바닥에 떨어져 있다.
5.88–7.3 걸음 흔들림 세 걸음에 창으로 간다. 발이 닿을 때마다 머리가 가장 낮아지고, 좌우로 한 번씩 기울며, 커튼 틈의 빛이 커진다.
7.2–7.54 노출 순응 몸을 숙이며 두 손이 아래에서 올라와 커튼 틈에 손가락을 넣는다.
7.44–7.72 노출 순응 커튼을 천천히 벌린다. 빛이 쏟아지고 눈이 반사적으로 찡그린다(가장자리에 눈꺼풀).
7.68 노출 순응 절정. 벌어지는 커튼과 두 손, 하얗게 넘친 창, 아래쪽의 꽃상자와 지붕들.
7.72–7.98 노출 순응 커튼을 양옆으로 활짝 젖힌다. 화면이 하얗게 넘치고 아랫단은 진자처럼 흔들린다.
7.8–8.7 노출 순응 노출이 내려오며 마을과 하늘이 드러나고, 찡그림이 풀린다. 포스터는 8.1초(찡그린 눈꺼풀 가장자리 너머로 마을이 막 드러나는 순간)다.
8.75–10 — 여운. 숨 쉬듯 미세하게 흔들리며 시선이 마을 위를 천천히 옮겨 가고, 하늘에 "오전 7:00 / 좋은 아침"이 떠오른다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 눈꺼풀 마스크: 개구도 a(t) 하나가 움직이는 베지어 눈꺼풀 두 장(body.js:42, body.js:68, post.js:104–post.js:137)
  • 눈 좌표를 u ∈ −1, 1, v ∈ −1.78, 1.78로 둔다. 눈꼬리는 화면 밖 X₀ = −1.35, X₁ = 1.35라서 틈이 화면 끝까지 이어진다.
  • 각 눈꺼풀은 조절점 x를 같은 간격으로 둔 3차 베지어다. 그러면 x(s)가 s에 선형이고 y는 닫힌 식이 된다: s = (u − X₀)/(X₁ − X₀), B(s) = 3(1−s)²s·k₁ + 3(1−s)s²·k₂. 위 꺼풀은 k = (1.12, 0.88)(코 쪽이 높다), 아래 꺼풀은 (0.9, 1.1)이다.
  • 위 y_u = c − ε + h_u·B_u(s), 아래 y_l = c + ε − h_l·B_l(s). h_u = 7a^1.25, h_l = 7a^1.7(위 꺼풀이 대부분 움직이고 아래는 늦게 따라온다), c = −0.06 + 0.1a(틈이 조금 위로 열린다). ε는 가장자리 폭과 같아서 a = 0이면 두 꺼풀이 2ε 겹치고 빛줄이 새지 않는다. a = 1이면 두 곡선이 화면 밖에 있다.
  • 가장자리는 각막에서 몇 mm 거리라 늘 초점이 나간다. 그래서 부호 거리 d = (y_u − v)/√(1 + y_u′²)에 smoothstep(−w, w, d)를 건다. w = 0.05 + 0.05(1 − a)라서 거의 감았을 때 더 부드럽다. 보임 = 위 × 아래.
  • 속눈썹은 너무 가까워 한 올씩 보이지 않는다. 가장자리 안쪽의 부드러운 어둠으로만 넣는다: 1 − 0.6e^(−d_u/0.045) − 0.24e^(−d_l/0.03).
  • 감은 눈꺼풀은 검지 않다. 피부는 빨강을 통과시키고 파랑을 흡수한다. 꺼풀 색 = 장면의 아주 흐린 평균(1/4 해상도 평균의 mip 6.5–8) × 투과율 (0.17, 0.045, 0.02) × (0.5 + 0.9e^(d/0.07)). 틈 가까이(d → 0)가 더 밝다. 틈으로 들어온 빛이 꺼풀 안으로 번지기 때문이다. 이 계산은 노출 전 선형 빛에서 하므로 눈의 순응이 꺼풀 빛에도 그대로 걸린다.
  • a(t): 0.3–1.0초 0 → 0.24, 1.28초까지 0.10으로 처짐, 1.7초까지 0.46. 깜빡임은 감기 0.1초(p², 가속하며 닫힘) + 감은 채 0.03초 + 뜨기 0.2초(1 − (1−p)³, 감속하며 열림)다. 둘째 깜빡임이 끝까지 열린다. 빛이 쏟아질 때는 반사적 찡그림 a = 1 − 0.4·sq(0.14초에 좁혀지고 0.9초에 풀림)가 같은 눈꺼풀을 다시 화면에 들인다.
  • 초점 맞춤: 지수로 줄어드는 흐림 반경, 반 해상도 보겔 원반 수집(body.js:89, post.js:57)
  • R(t) = 64·e^(−(t − 0.3)/0.9)·β₁·β₂ px. 깜빡일 때마다(눈물막이 고르게 펴진다) 남은 흐림에 β = 0.5를 곱하고(열리는 0.2초 동안 부드럽게), 마지막 반 픽셀은 2.5–2.95초의 smoothstep으로 0까지 당긴다.
  • 수집은 540×960에서 한다. 보겔 원반 32점: rᵢ = R√((i + 0.5)/N), θᵢ = i·2.39996(황금각). 각 표본은 원반 넓이의 1/N을 대표하므로 그 크기의 mip(lod = log₂(R√π/√N) + 0.5)을 읽는다. 그래서 점 무늬 대신 고른 원반이 된다.
  • 시야 가장자리는 조금 더 흐리다: R·(1 + 0.35|p|²). 선명한 상(FXAA)과는 smoothstep(0.35, 1.4, R)로 섞는다. R < 0.35이거나 눈을 감고 있으면 이 패스들을 건너뛴다(post.js:196).
  • 고개 돌림: 고정점을 겨누는 각도 목표 + 감쇠 스프링, 목 피벗에서 생기는 시차(main.js:153–main.js:200, body.js:100)
  • 카메라 회전 q = q_몸(β)·q_요(−ψ)·q_피치(−θ + 끄덕임)·q_롤(롤). 눈 = 목 + q·(0, 0.10, −0.09)다. 눈이 회전 중심보다 9cm 앞에 있으니, 고개를 돌리면 가까운 것(베개, 협탁 모서리)이 먼 벽보다 많이 미끄러진다. 시차가 저절로 생긴다.
  • 목표 각도는 고정점 P를 몸통 좌표로 옮겨 얻는다: v = q_몸⁻¹(P − 목), ψ = atan2(v_x, −v_z), θ = atan2(−v_y, √(v_x² + v_z²)). 고정점은 천장 → 자명종 → 창 → 마을로 0.2–0.28초 램프로 바뀐다(main.js:162).
  • 스프링 x″ = ω²(g − x) + 2ζω(ff·g′ − x′)를 600Hz 반암시 오일러로 setup에서 굽고 선형 보간으로 읽는다. 요는 ω = 13, ζ = 0.68이라 넘침이 e^(−ζπ/√(1−ζ²)) ≈ 5%다. 피치는 ω = 14, ζ = 0.62에 속도 앞먹임 ff = 0.8을 더한다. 몸이 일어나며 눈높이가 40cm 바뀌는 동안에도 시선이 자명종에서 밀리지 않는다. 그래서 세상이 자명종을 중심으로 돈다. 몸통 β는 ω = 9, ζ = 0.74다.
  • 누운 1인칭: 누우면 머리의 위쪽이 머리맡(+z)을 향한다. 오른쪽으로 고개를 돌리면 중력이 화면 옆을 향하는 게 실제 시점이다. 일어나기(β 90° → −6°)가 화면을 90° 돌려 바로 세운다.
  • 누운 머리는 베개에 닿은 뒤통수 중심(베개 위 약 9cm)을 축으로 돈다. 축을 너무 낮게 두면 옆을 볼 때 눈이 베개를 파고든다(body.js:115).
  • 걸음 흔들림: 걸은 거리에 위상이 묶인 머리 궤적(body.js:123–body.js:152, main.js:190)
  • 속도는 사다리꼴(앞뒤 30%가 가감속)이고 거리는 닫힌 식이다: p < r이면 p²/(2r(1−r)), 순항 구간은 (p − r/2)/(1−r), 끝은 대칭. 속도 비 k = v/v_max.
  • 걸음 위상 φ = s/L_걸음(1.37m를 세 걸음). 발이 닿는 순간은 정수 φ다. 위상을 시간이 아니라 거리에 묶었으므로 가감속 중에도 걸음이 어긋나지 않고, 흔들림 크기는 k에 비례해 멈출 때 사라진다.
  • 상하 y = 0.034·k·(|sin πφ| − 2/π): 한 걸음에 한 번, 보폭(두 걸음)에 두 번이다. 발이 닿을 때 가장 낮고(뾰족한 골), 평균은 0이다.
  • 좌우 x = 0.02·k·sin πφ: 보폭에 한 번이고, 걷는 방향의 오른쪽 벡터를 따른다. 롤 1.3°·k·sin(πφ − 0.35)는 흔들림보다 조금 늦게 기운다. 발이 닿을 때마다 끄덕임 −0.5°·k·cos 2πφ, 걷는 동안 몸통 앞기울기 −4°·k.
  • 내 손: 화면 아래 어깨에서 월드 목표로 뻗는 두 마디 IK(body.js:161, main.js:400–main.js:456, room.js:190)
  • 어깨는 몸통 좌표로 목에서 (±0.18, −0.2, 0.06)이라 화면 밖 아래에 있다. 뻗을 때 목표 쪽으로 5–6cm 따라 나간다.
  • IK: d = |T − S|를 [|a − b|, a + b] 안으로 자르고, cos α = (a² + d² − b²)/(2ad), 팔꿈치 E = S + a(cos α·û + sin α·v̂), v̂는 극 벡터를 û에 수직으로 만든 것. 위팔 a = 0.31, 아래팔 b = 0.28.
  • 극 벡터가 팔꿈치 자리를 고른다. 자명종에는 발 쪽으로 둬서 아래팔이 화면 가장자리에서 올라오고 문자판을 가리지 않는다(main.js:423). 커튼에는 바깥 아래로 둔다.
  • 손목 경로는 쉬는 자리(화면 밖) → 들어 올림 → 닿는 점의 3차 베지어이고, 1 − (1−p)^2.2로 빠르게 출발해 내려앉는다. 손 방향은 아래팔 방향에서 목표 자세로 70% 꺾는다(손목 굽힘).
  • 자명종: 손바닥이 단추 위에 오도록 손목 = 단추 − 0.05·손가락 방향 − 0.026·손바닥 법선(main.js:404). 1.4cm 누르고 2cm 뗀다. 커튼: 두 손이 손가락을 틈에 넣고 손바닥을 바깥으로 향한 채 앞단을 끌고, 커튼 앞단이 그 손을 따라간다.
  • 손은 둥근 손바닥, 두 마디 캡슐 손가락, 안쪽의 엄지다. 쥠 값 하나가 마디마다 −1.05c, −1.25c로 접는다(room.js:255).
  • 노출 순응: 망막의 로그 평균 휘도를 비대칭 시간 상수로 쫓는 노출(main.js:32, main.js:208–main.js:252, post.js:140)
  • 목표: ln L = Σ fᵢ ln Lᵢ. 영역은 열린 창(마을 1.75), 커튼(0.2), 방(0.065, 빛이 들면 0.25)이다. fᵢ는 각 직사각형을 카메라로 투영해 근평면과 화면으로 자른(Sutherland–Hodgman) 화면 점유율이다. 눈꺼풀도 넣는다: + ln(보임 + (1 − 보임)·0.04). Lᵢ는 실제 렌더의 로그 평균을 재서 정했다.
  • 순응: ln L_a ← ln L_a + (ln L − ln L_a)(1 − e^(−Δt/τ)). 밝아질 때 τ = 0.45초(빠름), 어두워질 때 1.6초(느림). 하한 0.036(감은 눈에 적응한 상태). setup에서 120Hz로 굽는다.
  • 노출 E = K·L_a^(−p), K = 0.333, p = 0.86. 순응이 완전하지 않아서 어두운 방은 조금 어둡게, 햇빛 든 풍경은 조금 밝게 남는다.
  • 커튼이 열리면 L이 약 3.3스톱 뛴다. L_a가 늦게 따라가므로 노출은 아직 방의 것이고, 화면이 하얗게 넘쳤다가 약 1초에 걸쳐 내려온다. 깜빡임(0.1초 어둠)은 τ↓가 느려서 순응을 거의 흔들지 않는다. 막 깼을 때도 같은 식이 살짝 눈부심을 만든다.
  • 블룸은 창빛에만 생긴다. 장면의 절대 휘도에 문턱 1.4/E를 건다(main.js:352). 커튼이 닫혀 있을 때는 틈과 햇빛 자국만, 넘친 순간에는 창 전체가 번지고, 순응이 끝나면 아무것도 번지지 않는다.
  • 창이라는 포털: 마을은 열린 창의 화면 사각형 안에서만 그린다(main.js:360, main.js:378)
  • 같은 자세의 카메라 두 대를 쓴다. 마을은 near 1.5 / far 1600, 방은 near 0.03 / far 30이라 손끝과 먼 산 모두 깊이 정밀도가 충분하다.
  • 마을을 먼저 그리되, 열린 창 부분의 네 모서리를 투영한 화면 사각형으로 가위(scissor)를 건다. 창이 시야 밖이면 아예 그리지 않는다. 깊이를 지우고 방을 그 위에 그린다. 방은 닫혀 있으니 결과는 같고, 대부분의 프레임에서 마을 비용이 사라진다.
  • 커튼: 천 길이를 지키는 주름, 늦게 따라오는 아랫단(room.js:68, room.js:80, main.js:36)
  • 주름 7개 z = A·sin(2πns). 폭 W로 모인 천의 정확한 길이 ∫₀¹ √(W² + (2πnA cos 2πns)²) ds = L을 이분법으로 풀어 A(W)를 표로 만든다. 모을수록 주름이 깊어진다.
  • 앞단은 0.28초 동안 천천히 벌어지고(빛이 새어 든다) 0.26초 동안 활짝 젖혀진다. 아랫단은 앞단을 약하게 감쇠한 스프링(ω = 10, ζ = 0.32)으로 따라가 진자처럼 흔들린다.
  • 역광 투과는 주름 위상에 묶은 방출 지도 1 − 0.2cos²(2πns)다. 천이 옆으로 누운 곳은 빛이 지나는 길이 길어 조금 어둡다.
  • 아침 빛과 그림자: 해는 창 축에서 60° 왼쪽, 고도 27°다. 방의 해(PCF 그림자 1024²)는 커튼 틈으로 벽과 바닥에 빛 띠를 떨군다. 천장에는 창턱에서 튕겨 오른 빛을 스포트라이트 쿠키(창 네 칸 + 틈의 띠 + 바깥 나뭇잎)로 비춘다(main.js:98). 같은 해가 마을을 옆에서 비춰 지붕과 왼쪽 벽은 밝고, 정면은 하늘빛 그늘이다.
  • 자명종과 칩: 돌아오는 7:00(room.js:109, main.js:311, main.js:458)
  • 울림: 몸체가 바닥을 축으로 0.07rad, 12.5Hz로 흔들리고 들썩이며, 망치는 16Hz로 친다. 소리 선 세 쌍이 퍼지며 사라진다. 누른 뒤 울림 = e^(−(t − 3.98)/0.06).
  • 칩은 미리 구운 알약 모양에 장치 이름을 쓰고, 그 앞의 작은 토마토 시계(7:00)를 매 프레임 같은 울림 값으로 떨게 그린다. 이름은 겹쳐 바뀐다(들어오기 0.32초, 나가기 0.12초).
프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • frame(t)는 닫힌 식이다. 눈꺼풀, 흐림, 걸음, 엉덩이 경로, IK, 커튼 앞단, 울림 모두 t만 읽는다. 상태가 쌓이는 것(머리·몸통 스프링, 커튼 아랫단 스프링, 눈의 순응)은 setup에서 고정 간격으로 적분해 배열에 굽고, frame은 보간해 읽기만 한다.
  • 천장 빛의 그림자 지도는 t < 3.25초에만 다시 그린다. 그 뒤에는 빛 세기가 0이라 낡은 지도가 픽셀에 닿지 않는다. 그림자를 드리우는 빛의 수는 늘 같아서 셰이더가 도중에 바뀌지 않는다.
  • 난수는 rand(seed)로 만든다(마을 1630, 쿠키 잎 512, 꽃상자 909). Math.random이 섞인 애드온은 쓰지 않는다.
  • 칩의 그림자 있는 알약은 setup에서 굽고, 칩 캔버스는 매 프레임 상태를 되돌린 뒤 통째로 다시 그린다. 헤드리스에서만 2D 캔버스를 willReadFrequently로 만든다.
  • setup 끝에서 두 시각(흐림·눈꺼풀이 있는 1.2초, 손·넘친 빛의 7.6초)을 그리고 renderer.compile로 시야 밖 재질까지 미리 만든다.
  • 렌더러 검사 결과는 byte-identical이다.
한계와 조절할 점
  • 초점 흐림은 깊이와 무관한 균일 흐림이다(시야 가장자리만 조금 더 흐리다). 깬 뒤에는 가까운 베개와 손도 선명하다. 동공 지름 × |1/z − 1/z_초점|으로 깊이별 흐림을 주고, 밝아지면 동공이 줄어 피사계 심도가 깊어지게 하면 노출과 초점이 한 몸이 된다.
  • 순응 목표는 영역별 휘도를 렌더에서 재어 넣은 모형이다. 매 프레임 화면을 읽어 평균을 내지 않으므로, 조명을 바꾸면 그 값들을 다시 재야 한다.
  • 누운 시점은 실제처럼 세상이 옆으로 눕는다. 움직임 속에서는 자연스럽지만, 정지 화면 한 장으로는 방향이 헷갈릴 수 있다.
  • 손은 캡슐로 만든 단순한 리그이고 스키닝이 없다. 커튼 천이 손가락을 감싸지 않는다.
  • 고개를 빨리 돌릴 때의 움직임 흐림, 두 눈의 시차와 엇갈린 깜빡임, 눈물막의 일렁임은 넣지 않았다. 실제 GPU 브라우저의 비용은 재지 않았다(헤드리스 CPU 수치만 있다).
