배경·분위기로 쓸 때

글자나 제품 뒤에 깔리는 배경, 분위기를 잡는 오프닝·엔딩에 써요.

  • 배경은 주인공보다 어둡거나 덜 선명하게. 대비가 강하면 글자가 안 읽혀요.
  • 루프로 만들어 두면 여러 영상에 재사용할 수 있어요.
  • 무거운 셰이더 배경은 미리 렌더링해 영상 파일로 깔면 편해요.

정보·데이터로 쓸 때

숫자·과정·경로·비교처럼 말로 설명하기 어려운 정보를 보여 줄 때 써요.

  • 실제 숫자와 출처를 표로 주세요. AI가 숫자를 지어내지 않게 '주어진 값만 쓰라'고 적어요.
  • 한 화면에 수치 하나, 결론 숫자는 크게.
  • 그래프는 마지막 값에서 1초 멈춰야 기억에 남아요.

만드는 법

  1. 준비하기

    Claude Code를 열고 빈 폴더에서 시작해요. aimotion 스킬을 처음 한 번 설치해요.

    claude plugin marketplace add kstost/cokacmotion claude plugin install aimotion@aimotion

  2. 프롬프트 만들기

    칸을 채우면 아래 프롬프트가 바로 바뀌어요. 데모의 장면이 아니라 내 장면을 적는 게 핵심이에요.

  3. 미리보기 보고 고치기

    Claude Code가 만든 HTML을 브라우저로 열어 확인하고, 고칠 점을 말로 알려 줘요. 자주 쓰는 수정 문장을 눌러 복사하세요.

  4. MP4로 뽑기

    실시간 화면 녹화보다 프레임 단위 렌더링이 끊김 없고 선명해요.

    이제 render(t)로 1/30초마다 프레임을 캡처해서 30fps MP4로 렌더링해 줘. 결과 파일 이름은 out.mp4로.

  5. 내 영상에 합치기

    제목 · 자막 · 전환처럼 실사 위에 얹을 효과라면 배경을 투명하게 뽑아 편집 프로그램(캡컷 · 프리미어)의 위 트랙에 올려요. 이미 찍은 영상이 있으면 파일을 주고 "이 영상 위에 효과를 입혀 줘"라고 해도 돼요.

    배경을 투명하게 해서 알파 채널이 있는 영상(ProRes 4444 .mov 또는 WebM)으로도 뽑아 줘.

초 단위로 보기

데모가 몇 초에 무엇을 보여 주는지예요. 장면을 따라 하려는 게 아니라, 기법이 어떤 순서와 리듬으로 쓰였는지 보는 용도예요.

10초, 96 BPM(한 박 625 ms, 16박 = 4마디). 바우하우스 악보 포스터가 살아 움직인다. 크림색 종이에 검정·빨강·코발트·노랑만 쓴다. 21 × 25 = 525개의 점이 합창단이다. 위에는 머리줄(NO. 73 / FOR 525 VOICES), 굵은 괘선 두 줄, 큰 제목 CHORUS, 지휘 도형이 있고, 그 아래에 박자 정보 줄(96 BPM · 4/4 · BAR n · BEAT n)이 있다. 아래 검은 띠에는 16칸 박자표가 있고 자막도 이 띠 위에 얹힌다.

  • 입장 (b0–b1, 0–1.25 s)
  • 괘선이 그려지고, 점들이 왼쪽 위 모서리에서 퍼지는 스태거로 튀어나와 자리를 잡는다.
  • 제목 글자는 아래에서 한 자씩 올라온다.
  • b1에는 지휘자의 예비 호흡처럼 가운데에서 부드럽게 한 번 부푼다.
  • 카운트인 1·2·3·4 (b2–b5): 박마다 점들이 큰 숫자를 이룬다.
  • 숫자는 지휘봉이 가는 쪽에서 밀려온다. 4/4 지휘 도형의 방향(아래·왼쪽·오른쪽·위)을 따라 1은 위에서, 2는 오른쪽에서, 3은 왼쪽에서, 4는 아래에서 온다.
  • 다음 숫자의 물결이 지나가며 앞 숫자를 지운다. 바뀌는 점은 빨간 앞머리로 잠깐 빛난다.
  • 마지막 4는 빨강이다.
  • 오른쪽 위 지휘 도형에서는 빨간 선이 한 박에 한 구간씩 그려지고, 검은 지휘봉 점이 그 끝을 따라간다. 지금 박의 번호는 빨갛게 표시된다.
  • 합창 (b6–b11, 절정)
  • b6: 가운데에서 빨간 폭발이 퍼지며 점들이 네모가 된다. 노란 삼각형이 스프링으로 튀어나온다. 삼각형은 곱하기 합성이라 점은 검게 남고 종이만 노래진다.
  • b7: 왼쪽 위 모서리에서 네모들이 커지며 스프링으로 90° 돈다. 코발트 띠가 물결 앞머리를 탄다.
  • b8: 오른쪽 아래 모서리에서 노란 깡충 뛰기가 지나간다. 삼각형은 빨간 정사각형으로 모프된다.
  • b8¾–b11¼: 도형 둘레를 도는 점(움직이는 원점)이 8분음표마다 자기 자리에서 물결을 하나씩 보낸다. 물결 넷은 빨강·코발트로 번갈아 간다.
  • b10: 정사각형이 코발트 원으로 모프된다.
  • b11: 포르티시모. 모서리에서 모서리로 한 번에 쓸고 지나가며 한 번 더 90° 돈다. 빨강·코발트·노랑 대각 줄무늬가 번쩍인다.
  • 이 여섯 박 동안 CHORUS의 여섯 글자가 한 박에 하나씩 빨갛게 켜진다.
  • 여운 (b12–b15)
  • b12: 끊기. 가장자리에서 가운데로 모두 작은 동그라미로 돌아온다.
  • b13: 합창이 한 목소리가 된다. 가운데에서 퍼지는 물결로 바깥 점들은 사라진다. 안쪽 점들은 왼쪽 위에서 빛을 받은 망점 구가 되고, 오른쪽 아래에 그림자가 진다. 점들이 모여 하나의 '점'이 된다.
  • b14: 지휘봉이 위에서 멈추고 지휘 선이 처음부터 지워진다. 코발트 원은 판이 어긋난 인쇄처럼 오른쪽 위로 비켜 앉는다. 박자 줄은 FINE이 된다.

원리

개발자용 구현 설명이에요(원작자 노트, MIT). 몰라도 만들 수 있지만, Claude에게 "이 원리 중 ○○만 써 줘"처럼 지시할 때 도움이 돼요.

기법과 원리
  • 타임라인 하나(main.js:261): createTimeline({ autoplay: false }) 위에 모든 동작을 박 단위 위치(B(n) = n × 625 ms)로 올린다. anime의 시간 단위는 ms라서 frame(t)는 tl.seek(t * 1000)(main.js:435)을 부른다.
  • seek는 동기다. tick()이 그 자리에서 모든 자식 애니메이션을 렌더한다(node_modules/animejs/dist/modules/core/render.js, tick).
  • 엔진(rAF)에는 아무것도 등록되지 않는다.
  • 그리드 스태거: stagger(each, { grid: [21, 25], from })(main.js:262).
  • 각 점의 지연은 원점에서 그 칸까지의 격자 거리 × each다(utils/stagger.js). 원점은 'first', 'last', 'center', [fx, fy](0..1 비율)를 쓴다. reversed: true는 가장자리부터 시작한다.
  • 움직이는 원점(main.js:344–349)은 궤도 경로에서 각 8분음표 시각의 점을 getPointAtLength로 구해 [fx, fy]로 넘긴다. 물결 넷이 지나간 자리에서 나간다.
  • 층으로 쌓는 점: anime은 점 DOM을 직접 쓰지 않는다. 점마다 일반 객체를 두고, 몸짓 하나마다 속성 하나(intro, on0–3/off0–3, burst, sq, grow, rot1, cob, hop, yel, m0–3, ff, rot2, calm, gath)를 둔다. 속성마다 정확히 한 번 [0, 1]로 트윈한다.
  • compose(main.js:381)가 이 층들을 합쳐 점 하나의 transform·색·모서리 둥글기로 만든다.
  • 숫자 존재감은 on × (1 − off)다. 합창 층은 (1 − calm)을 곱해 끊기에서 사라진다. 마지막은 s + (sphere − s) × gath로 망점 구에 끌려간다.
  • 이렇게 하면 물결이 숫자 위에, 색 띠가 회전 위에 겹칠 수 있다. 바뀐 문자열만 다시 쓴다(main.js:413–415).
  • 이징
  • 맞춤 이징은 ease: () => fn으로 감싼다(main.js:46). anime은 함수형 매개변수를 대상마다 한 번 호출하므로(animation/animation.js:326), 감싸지 않은 함수는 대상 객체를 진행도로 받는 호출을 한 번 더 겪는다.
  • bump(main.js:49)는 빠른 상승 뒤 부드럽게 내려와 0으로 돌아오는 맥박이다. hopEase는 포물선 깡충이다.
  • 숫자와 회전에는 createSpring({ stiffness, damping })(main.js:276, :321)을 쓴다. 스프링 이징을 받으면 anime은 지속시간을 스프링의 정착 시간으로 바꾼다.
  • 숫자 래스터(main.js:98–119)
  • 1–4를 Anybody(OFL) wght 900·expanded로 칸당 16 px 캔버스에 쓴다.
  • 칸마다 덮인 비율을 평균해 smoothstep으로 대비를 준다. 경계 칸은 반쯤 큰 점이 되어 도트 매트릭스 숫자의 가장자리가 매끈하다.
  • 망점 구(main.js:121–143): 위왼쪽에서 오는 빛 L과 구의 법선으로 확산광을 구한다. 잉크 = 1 − 확산이다.
  • 망점은 면적이 잉크에 비례하므로 크기는 √잉크다(AM 망점 인쇄의 원리).
  • 가장자리 칸은 거리로 반 칸 안티에일리어싱한다. 그 아래 타원 띠는 그림자다.
  • SVG 드로잉: createDrawable(svg/drawable.js)은 pathLength=1000을 두고 draw: 'a b'를 stroke-dasharray/offset로 바꾼다.
  • 괘선 셋은 140 ms 간격 스태거로 그린다.
  • 지휘 선은 지휘봉과 같은 맞춤 이징으로 그린다(batonS, main.js:300). 한 박에 한 구간씩 나아가고, 박 사이는 outIn(타점에서 빠르고 정점에서 느림)이다.

프레임마다 같은 그림이 나오게 하는 법 (결정성)
  • 모든 움직임은 하나의 일시정지 타임라인에 있다. frame(t)는 tl.seek(t·1000) 다음 compose(t)만 한다.
  • 박자표, 박자 카운터, CHORUS 글자색, 지휘 번호 색은 t에서 바로 계산한다.
  • Math.random, rAF, 타이머, CSS 전환은 쓰지 않는다. anime의 무작위 기능(from: 'random', jitter)도 쓰지 않는다.
  • 원소·속성 하나에 트윈 하나
  • 같은 속성에 트윈 둘을 이어 걸면(그리기 → 지우기, 모프 → 모프) anime 4.5의 형제 트윈 규칙에서 빈틈이 생긴다. 앞 트윈은 '다음 트윈의 인계 시점'부터 손을 놓고, 명시적 from이 있는 뒤 트윈은 자기 시작까지 기다린다. 그 사이 구간으로 뒤섞인 순서로 seek하면 값이 남는다. 숫자 탐침으로 확인했다.
  • 그래서 다음처럼 바꾸었다.
    • 도형은 경로 둘이다. 삼각형 → 정사각형 경로 아래에 정사각형 → 원 경로를 두고, b10에 불투명도로 넘긴다.
    • 지휘 선을 지우는 일은 종이색 지우개 획을 같은 경로에 그리는 것으로 한다. 점선 안내선과 번호, 지휘봉은 지우개 위에 있다.
    • 점의 모든 층은 속성 하나에 트윈 하나다.
  • 프라이밍(main.js:371): setup 끝에서 tl.seek(duration) → tl.seek(0)을 한 번 한다.
  • 그러면 아직 렌더된 적 없는 트윈의 from 값이 한 번씩 쓰인다. 새 페이지에서 처음 그린 상태와 뒤로 seek해 되돌린 상태가 같은 문자열이 된다.
